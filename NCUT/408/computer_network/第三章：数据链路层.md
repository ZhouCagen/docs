# 第 3 章 数据链路层

## 3.1 数据链路层的功能

### 3.1.1 基本概念与服务范围

数据链路层把网络层交下来的分组封装成**帧**，在相邻节点之间的一段链路上传送。跨越多段网络时，各段可以使用不同的链路层协议。

| 概念       | 含义                                     | 辨析                               |
| ---------- | ---------------------------------------- | ---------------------------------- |
| 链路       | 相邻节点之间的一段物理线路               | 是通信路径的一部分                 |
| 数据链路   | 物理链路加上实现通信协议所需的硬件和软件 | 除线路外，还包括控制传输的协议功能 |
| 帧         | 数据链路层的协议数据单元（PDU）          | 通常由首部、数据部分和尾部组成     |
| 点对点信道 | 一条链路连接两个节点                     | 如 PPP 链路                        |
| 广播信道   | 多个节点共享通信介质                     | 需要解决多个节点如何使用介质的问题 |

数据链路层面向**相邻节点间**的传输；传输层面向**端到端**的通信。路由器每经过一跳，都要处理入链路的帧，并为出链路重新封装。

### 3.1.2 主要功能

| 功能             | 解决的问题                       | 常用方法                     |
| ---------------- | -------------------------------- | ---------------------------- |
| 链路管理         | 何时建立、维持和释放链路         | 协商参数、建立与释放连接     |
| 封装成帧、帧定界 | 接收端怎样区分一帧的开始和结束   | 长度字段、定界符、编码违例   |
| 透明传输         | 数据恰好与控制标记相同时怎样传输 | 字节填充、零比特填充         |
| 差错检测         | 帧在传输过程中是否发生比特差错   | CRC 等检错码                 |
| 流量控制         | 发送速度是否超过接收能力         | 停止—等待、滑动窗口          |
| 可靠传输         | 怎样处理丢失、重复等问题         | 编号、确认、超时重传         |
| 介质访问控制     | 多个节点如何共享广播信道         | 信道划分、随机访问、轮询访问 |

**组帧、透明传输、差错检测是本章的基础问题，但并非所有链路层协议都提供可靠传输。** 例如，以太网检错后丢弃错误帧，不在其 MAC 层通过确认与重传保证交付；无线局域网则使用链路层确认与重传改善交付可靠性。

### 3.1.3 三组易混概念

- **透明传输**：上层无需关心数据中是否含有与链路控制标记相同的内容，接收方仍能恢复原始数据；不表示“无需封装”或“没有开销”。
- **流量控制与可靠传输**：前者防止接收方来不及接收，后者处理数据出错、丢失、重复等问题；滑动窗口可以同时参与实现两者。
- **检错与可靠交付**：CRC 检查通过，只表示没有检测出比特差错；不能由此推断没有丢帧、重复帧，也不能绝对排除漏检。

### 3.1.4 典型协议的连接与可靠性对比

| 协议                     | 是否面向连接     | 是否可靠                       |
| ------------------------ | ---------------- | ------------------------------ |
| 以太网 MAC（802.3）      | 无连接           | 不可靠                         |
| 无线局域网 MAC（802.11） | 无连接的数据传输 | 有确认、重传，但不保证可靠交付 |
| PPP                      | 建立链路后传输   | 不可靠                         |

**链路建立与可靠交付是两个不同的问题。** PPP 有链路建立和参数协商过程，但不因此提供可靠交付；802.11 对普通单播数据使用确认和有限重传，仍可能因达到重传限制而丢帧。

## 3.2 组帧

### 3.2.1 四种组帧方法

| 方法         | 基本原理                                       | 优点或局限                                                         |
| ------------ | ---------------------------------------------- | ------------------------------------------------------------------ |
| 字节计数法   | 首部记录帧包含的字节数，按长度确定边界         | 计数字段出错可能使后续多帧失去同步；是否包含计数字段自身按题目约定 |
| 字节填充法   | 用特殊字节定界；数据中出现特殊字节时加转义字节 | 面向字节，接收端要去转义                                           |
| 零比特填充法 | 用特殊比特串定界；对帧内容进行比特填充         | 面向比特，可承载任意比特串                                         |
| 违规编码法   | 用线路编码中不用于普通数据的信号组合表示边界   | 不必增加转义数据，但依赖具体线路编码                               |

组帧时也要限制帧的数据部分长度，最大值常称为**最大传送单元（MTU）**。MTU 通常描述可承载的上层数据大小，不等于包含首尾部的完整帧长。

### 3.2.2 字节填充法

假设用 `SOH`、`EOT` 表示帧首和帧尾，用 `ESC` 表示转义。原始数据中出现 `SOH`、`EOT` 或 `ESC` 时，在其前面插入 `ESC`。

```text
原始数据：A  EOT  ESC  B
发送帧：  SOH  A  ESC EOT  ESC ESC  B  EOT
```

接收端遇到数据区的 `ESC`，删除该转义字节，并把其后的字节作为普通数据解释。**转义字符本身也必须转义**，否则会产生歧义。

### 3.2.3 零比特填充法

帧定界标志为 `01111110`。发送端扫描两个标志之间的内容，**每连续出现 5 个 `1`，立即插入 1 个 `0`**；接收端执行逆操作。

```text
原始数据：01111110
填充后：  011111010
          0 + 11111 + 插入的0 + 10
```

- 定界标志自身不参与填充。
- 填充是针对比特流，不按字节重新计数。
- 连续 5 个 `1` 后，即使原本下一位就是 `0`，也要先插入一个 `0`。
- 去填充时只删除规则要求删除的那个 `0`，不能把所有 `0` 都删掉。

### 3.2.4 违规编码法

若某种线路编码只用“高—低”和“低—高”表示数据，就可以利用未用于数据的“高—高”“低—低”等组合表示边界。这里的“违规”是**协议有意保留并使用特殊信号组合**，不是随机传输出错。

## 3.3 差错控制

### 3.3.1 码距与检错、纠错能力

#### 码距与最小码距

两个等长码字对应位不同的个数，称为**码距（海明距离）**。可以先按位异或，再统计结果中 `1` 的个数。编码集合中任意两个不同合法码字之间的最小距离，称为**最小码距** $d_{\min}$，也常简记为 $d$。

例如，`A = 00000`，`B = 11111`，对应的 5 个位置全部不同，因此两者的码距为 5。若编码系统只有这两个合法码字，则最小码距也是 5；若还有其他合法码字，必须比较所有不同合法码字对才能确定最小码距。

#### 检错能力

若要保证检测任意最多 $e$ 位错误，则要求：

$$
\boxed{\text{保证检测 }e\text{ 位错误：}\quad d_{\min}\ge e+1}
$$

**原因：检错只需要判断收到的码字是否为合法码字。** 任意两个合法码字至少相差 $d_{\min}$ 位，因此错误位数不超过 $d_{\min}-1$ 时，不可能从原码字变成另一个合法码字，可以保证检出。

#### 纠错能力

若要保证纠正任意最多 $t$ 位错误，则要求：

$$
\boxed{\text{保证纠正 }t\text{ 位错误：}\quad d_{\min}\ge 2t+1}
$$

**原因：纠错不仅要发现错误，还要唯一确定原来发送的是哪个合法码字。** 将与某合法码字距离不超过 $t$ 的所有比特串看作其半径为 $t$ 的纠错范围，任意两个合法码字的纠错范围必须互不重叠。因此：

$$
d_{\min}>2t\quad\Longrightarrow\quad d_{\min}\ge2t+1.
$$

以保证纠正 2 位错误为例，分别考虑只有下列两个合法码字的编码系统：

| 最小码距 | 合法码字         | 能否保证纠正 2 位错误                                                |
| -------- | ---------------- | -------------------------------------------------------------------- |
| 4        | `0000`、`1111`   | 不能。收到 `0011` 时，与两个合法码字的距离均为 2，无法唯一确定原码字 |
| 5        | `00000`、`11111` | 可以。两个码字半径为 2 的纠错范围不重叠，可唯一确定原码字            |

#### 同时检错与纠错

若要求**纠正任意最多 $t$ 位错误，同时检测任意最多 $e$ 位错误**，其中 $e\ge t$，则需要：

$$
\boxed{d_{\min}\ge t+e+1,\qquad e\ge t}.
$$

这里“同时检测”的含义是：不超过 $t$ 位的错误能够纠正；**超过 $t$ 位、但不超过 $e$ 位的错误必须报告为不可纠正的错误，不能误纠正成其他合法码字。**

原因是，原码字发生最多 $e$ 位错误后，接收结果不能落入另一个合法码字半径为 $t$ 的纠错范围。因此两者之间的最小距离必须满足：

$$
d_{\min}>e+t\quad\Longrightarrow\quad d_{\min}\ge e+t+1.
$$

例如，$d_{\min}=3$ 的码可保证检测 2 位错误，或保证纠正 1 位错误。**不能直接理解为普通译码器能同时区分所有双错并纠正所有单错。** 接收码字发生两位错误时，纠单错译码器可能将它误判为另一码字的一位错误。

若要求同时纠正 1 位错误、检测 2 位错误，则需 $d_{\min}\ge1+2+1=4$。上述保证均针对规定的错误位数范围，超出范围后不保证仍能正确检错或纠错。

### 3.3.2 奇偶校验

在信息位后添加 1 位校验位，使整个码字中 `1` 的个数满足约定：偶校验为偶数，奇校验为奇数。

| 能力               | 结论                   |
| ------------------ | ---------------------- |
| 奇数个位翻转       | 一定能检测出来         |
| 偶数个位翻转       | 不能检测出来           |
| 确定错误位置并纠正 | 单个奇偶校验位不能做到 |

注意统计的是**信息位与校验位合起来**的 `1` 的个数。

### 3.3.3 循环冗余校验 CRC

#### 生成多项式与位串

把比特串看成二进制多项式的系数。例如：

$$
G(x)=x^3+x^2+1\quad\longleftrightarrow\quad 1101.
$$

若 $G(x)$ 的阶数为 $r$，则生成多项式的位串有 $r+1$ 位，帧检验序列 **FCS 有 $r$ 位**。

**通信双方必须事先约定使用同一个生成多项式 $G(x)$ 及相同的编码、校验规则**，通常由协议规定，而不必在每次通信前重新协商。常规 CRC 生成多项式的最高次项和常数项系数均为 1，即对应位串的首位、末位均为 `1`。

#### 发送端与接收端的计算

1. 设原始数据为 $M$，在末尾补 $r$ 个 `0`，即得到 $M(x)x^r$。
2. 用生成多项式对应的位串进行**模 2 除法**：减法使用异或，不借位、不进位。
3. 取 $r$ 位余数作为 FCS；不足 $r$ 位时在左边补 `0`。
4. 用 FCS 替换先前补入的 $r$ 个 `0`，发送 `原始数据 + FCS`。
5. 接收端将完整收到的码字用同一生成多项式相除；余数非零则检出错误，余数为零则通过检验。

$$
\boxed{FCS=\operatorname{rem}\bigl(M(x)x^r/G(x)\bigr)}
$$

$$
T(x)=M(x)x^r+FCS(x),\qquad T(x)\bmod G(x)=0.
$$

这里的加法也在模 2 意义下进行。

#### 计算例题

数据 `101001`，生成多项式位串 `1101`：

```text
r = 3
补零数据：101001000
模2除法：101001000 ÷ 1101，余数为 001
发送码字：101001001
接收检验：101001001 ÷ 1101，余数为 000
```

**易错点：补零数看最高次数，不看多项式项数；FCS 长度看阶数，不看余数去掉前导零后的长度。**

#### 突发错误的检测能力

**使用 $r$ 次生成多项式、附加 $r$ 个检验位的 CRC，可以检测所有长度小于等于 $r$ 的突发错误**，前提是生成多项式的常数项为 1。

突发错误的长度，是从**第一个出错位到最后一个出错位之间的位数，包含首尾**；中间不要求每一位都出错。例如，错误模式 `1001` 表示首尾两位翻转，中间两位未翻转，其突发长度为 4，而实际出错位数为 2。

设突发长度为 $\ell$，错误多项式可写成 $E(x)=x^iB(x)$，其中 $B(x)$ 的次数为 $\ell-1$。当 $\ell\le r$ 时，$B(x)$ 的次数小于 $G(x)$ 的次数；又因 $G(x)$ 的常数项为 1，它与 $x^i$ 互素，因此不可能整除非零的 $E(x)$，接收端的校验余数必不为零。

例如，生成多项式 `1101` 的阶数为 3，附加 3 位 FCS，可保证检测所有长度不超过 3 的突发错误。**长度超过 $r$ 不表示一定漏检，而是不再仅凭这一条件保证全部检出。** “检测所有长度不超过 $r$ 的突发错误”也不等于“检测任意位置的 $r$ 位错误”。

CRC 是检错方法。错误模式恰好能被生成多项式整除时仍可能漏检；它本身不提供确认、重传或去重。

### 3.3.4 海明码

#### 校验位数量与位置

设信息位有 $m$ 位，校验位有 $k$ 位。要区分“无错”和全部 $m+k$ 个单比特错误位置，需满足：

$$
\boxed{2^k\ge m+k+1}.
$$

校验位放在编号为 $1,2,4,8,\ldots$ 的位置，信息位依次放在其余位置。**先约定从左还是从右编号，再全过程保持一致。**

本例与照片一致，从右向左编号，4 位数据 $D_4D_3D_2D_1=1010$，取 $k=3$：

| 位置 | 7     | 6     | 5     | 4     | 3     | 2     | 1     |
| ---- | ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| 内容 | $D_4$ | $D_3$ | $D_2$ | $P_3$ | $D_1$ | $P_2$ | $P_1$ |
| 数值 | 1     | 0     | 1     | 待定  | 0     | 待定  | 待定  |

#### 分组与校验位取值

将位置编号写成二进制。某一二进制位为 `1`，就参加对应校验组：

| 校验位        | 覆盖位置（含自身） | 偶校验时的计算                  |
| ------------- | ------------------ | ------------------------------- |
| $P_1$，位置 1 | 1、3、5、7         | $P_1=D_1\oplus D_2\oplus D_4=0$ |
| $P_2$，位置 2 | 2、3、6、7         | $P_2=D_1\oplus D_3\oplus D_4=1$ |
| $P_3$，位置 4 | 4、5、6、7         | $P_3=D_2\oplus D_3\oplus D_4=0$ |

因此，按位置 7 到位置 1 排列的海明码为 **`1010010`**。

#### 检错与纠错

接收端对各组（含校验位）异或，得到 $S_1,S_2,S_3$，组成校验结果 $S_3S_2S_1$：

- `000`：在无错或至多单错的假设下表示无错。
- 非零：在至多单错的假设下，该二进制数就是错误位置，将对应位取反即可。
- 例如 `101` 表示第 5 位出错。

普通海明码能纠正单比特错误；若要同时做到纠正单错、检测双错，可增加一个总奇偶校验位形成扩展海明码。不要把普通海明码的单错定位规则直接用于任意多比特错误。

## 3.4 流量控制与可靠传输机制

### 3.4.1 滑动窗口

发送窗口 $W_T$ 描述发送方允许发送的序号范围，其中既可能有已发送但未确认的帧，也可能有尚未发送的帧。接收窗口 $W_R$ 描述接收方当前可以接收的序号范围。

- 发送方发送一帧，只会占用一个窗口位置，**并不因此滑动窗口**。
- 收到能够推进窗口左边界的确认后，发送窗口才能前移，允许发送新帧。
- 接收端是否接收乱序帧、怎样推进窗口，取决于协议。
- SR 收到窗口内乱序帧时可以缓存、确认，但缺失的前部帧未补齐前，窗口左边界不能越过缺口。

设序号字段有 $n$ 位，则序号空间大小为 $2^n$，按模 $2^n$ 循环编号。

### 3.4.2 ARQ 的基本机制

自动重传请求（ARQ）通过**检错、编号、确认和超时重传**处理传输差错。

| 机制        | 作用                           |
| ----------- | ------------------------------ |
| 检错        | 识别损坏的数据帧或确认帧       |
| 序号        | 区分新帧与重复帧               |
| ACK         | 告知发送方某些数据已被正确接收 |
| 超时重传    | 未能及时收到有效确认时再次发送 |
| NAK（可选） | 显式请求重传，帮助更早恢复     |

**没有 NAK 也可以通过超时重传恢复。** ACK 丢失不等于数据帧丢失；接收端需要避免把重传造成的重复帧再次交付上层。

本节约定 **ACK $i$ 表示确认第 $i$ 帧**。部分题目用 ACK $i$ 表示“下一帧期望 $i$”，此时确认范围到 $i-1$；做题前必须看清定义。

### 3.4.3 停止—等待协议

每发送一帧就等待确认，收到有效 ACK 后再发送下一帧：

$$
\boxed{W_T=W_R=1}.
$$

使用 1 位序号 `0`、`1` 交替即可区分相邻的新帧与重传帧。

| 情况             | 发送方处理                       | 接收方处理                               |
| ---------------- | -------------------------------- | ---------------------------------------- |
| 数据帧损坏或丢失 | 超时后重传                       | 错帧丢弃；收到重传正确帧后接收并确认     |
| ACK 损坏或丢失   | 超时后重传原数据帧               | 识别重复帧，丢弃重复数据，但重新发送 ACK |
| ACK 迟到         | 可能已经发生重传；按编号处理确认 | 仍需依靠序号避免重复交付                 |

**确认帧通常不再要求对方确认，ACK 丢失依靠数据帧重传触发再次确认。**

### 3.4.4 后退 N 帧协议 GBN

GBN 允许连续发送多帧，但接收端只按序接收：

$$
\boxed{1\le W_T\le 2^n-1,\qquad W_R=1}.
$$

- **累积确认**：ACK $i$ 表示第 $i$ 帧及其之前的帧均已按序收到。
- **不缓存乱序帧**：只接收当前期望帧，其后的乱序帧即使正确也丢弃。
- **回退重传**：超时后，从最早未确认帧开始，重传所有已发送但尚未确认的帧。
- 典型实现为最早未确认帧维护计时器。

例：发送 `0、1、2、3、4`，其中 2 丢失。接收端接收 0、1，丢弃随后到来的 3、4，并可重复确认 1。若超时时尚未发送其他帧，则发送端重传 `2、3、4`。

**“后退 N 帧”不表示每次固定重传恰好 N 帧**，具体数量取决于当前已发送但未确认的帧。

窗口不能达到 $2^n$：若序号空间全部占满，而一轮 ACK 全丢失，重传旧帧可能与接收方期待的新一轮同序号帧混淆。

### 3.4.5 选择重传协议 SR

SR 对正确帧逐一确认，并缓存接收窗口内的乱序帧，只重传出错或超时的帧。

在本章标准窗口模型下，为避免新旧帧混淆：

$$
\boxed{W_T+W_R\le 2^n}.
$$

通常取等大的发送、接收窗口：

$$
\boxed{W_T=W_R\le 2^{n-1}}.
$$

例：发送 `0、1、2、3、4`，其中 2 丢失。若 3、4 在接收窗口内，接收端将其缓存并分别确认；发送端只需重传 2。补齐后，接收端再将连续的数据按序交付。

SR 通常为每个已发送但未确认的帧维护独立的超时状态。**收到某个后续帧的 ACK，只能标记该帧已确认；最早未确认帧没有确认时，发送窗口不能直接越过它。**

收到已经接收过的旧帧时，接收端可能需要再次确认，以免其 ACK 丢失使发送端不断超时。窗口外帧不能一律理解成“丢弃且绝不回应”。

### 3.4.6 三种协议对比

| 项目       | 停止—等待              | GBN                                  | SR                         |
| ---------- | ---------------------- | ------------------------------------ | -------------------------- |
| 发送窗口   | 1                      | 至多 $2^n-1$                         | 等大窗口时至多 $2^{n-1}$   |
| 接收窗口   | 1                      | 1                                    | 等大窗口时至多 $2^{n-1}$   |
| 确认方式   | 逐帧确认               | 累积确认                             | 逐帧确认                   |
| 缓存乱序帧 | 不缓存                 | 不缓存                               | 缓存窗口内的正确乱序帧     |
| 超时后重传 | 当前帧                 | 最早未确认帧及后续已发未确认帧       | 对应的未确认帧             |
| 主要特点   | 简单，长时延链路效率低 | 接收端简单，但可能重复发送大量正确帧 | 重传量少，缓存和控制更复杂 |

例：序号字段为 3 位时，GBN 最大发送窗口为 7；等大窗口的 SR 最大发送、接收窗口各为 4。

### 3.4.7 信道利用率与吞吐量

#### 统一符号与条件

设数据帧长为 $L$ bit，链路速率为 $R$ bit/s，单程传播时延为 $T_p$，ACK 发送时延为 $T_A$：

$$
T_D=\frac LR,\qquad RTT=2T_p.
$$

本节的 RTT **只包含往返传播时延**。假设接收完整帧后立即确认，无差错、无排队，忽略处理时延。若题目对 RTT 另有定义，应避免重复计入 ACK 或帧发送时间。

#### 停止—等待

从发送一帧开始到收齐 ACK，周期为 $T_D+RTT+T_A$：

$$
\boxed{U=\frac{T_D}{T_D+RTT+T_A}}.
$$

若忽略 ACK 发送时间，并令 $a=T_p/T_D$：

$$
U=\frac1{1+2a}.
$$

例如，$L=1200$ B，$R=1$ Mbit/s，$T_p=20$ ms，忽略 ACK 发送时间：

$$
T_D=9.6\ \mathrm{ms},\qquad U=\frac{9.6}{9.6+40}\approx19.35\%.
$$

链路速率提高而帧长、传播时延不变时，$T_D$ 变小，停止—等待的利用率反而降低。

#### 滑动窗口的理想利用率

在 ACK 不形成额外瓶颈、无差错且发送方持续有数据的模型下，发送窗口为 $W$：

$$
\boxed{U=\min\left(1,\frac{WT_D}{T_D+RTT+T_A}\right)}.
$$

要使发送端在第一帧的 ACK 回来前不因窗口耗尽而空闲，需满足：

$$
WT_D\ge T_D+RTT+T_A.
$$

$$
\boxed{W_{\min}=\left\lceil\frac{T_D+RTT+T_A}{T_D}\right\rceil}.
$$

接上例，$W_{\min}=\lceil49.6/9.6\rceil=6$。若用 GBN，至少需要 3 位序号；若用等大窗口 SR，至少需要 4 位序号。

#### 吞吐量与有效数据速率

$$
\text{帧比特吞吐量}=UR.
$$

若每帧中只有 $L_{\mathrm{payload}}$ bit 是有效数据，则在上述无差错模型中：

$$
\boxed{\text{有效数据速率}=UR\frac{L_{\mathrm{payload}}}{L}}.
$$

计入重传时，重复发送的比特不能再次计作成功交付的有效数据。计算前先区分题目问的是线路利用率、帧吞吐量，还是有效载荷速率。

## 3.5 介质访问控制

介质访问控制（MAC）解决**多个站点如何协调使用同一广播信道**的问题。

| 类别     | 典型方法                      | 核心思路                           |
| -------- | ----------------------------- | ---------------------------------- |
| 信道划分 | FDM、TDM、WDM、CDM            | 按频率、时间、波长或码序列划分资源 |
| 随机访问 | ALOHA、CSMA、CSMA/CD、CSMA/CA | 站点竞争使用介质，处理或降低冲突   |
| 轮询访问 | 轮询、令牌传递                | 按控制规则轮流取得发送权           |

### 3.5.1 信道划分

| 方法              | 划分依据     | 关键特征                                                                                               |
| ----------------- | ------------ | ------------------------------------------------------------------------------------------------------ |
| 频分复用 FDM      | 频带         | 多用户可同时发送，使用不同频段；相邻频带间可留保护频带                                                 |
| 时分复用 TDM      | 时隙         | 多路信号按时间交错复用到同一信道，各路在自己的时隙内独占信道；固定时隙周期出现，无数据时仍可能空占时隙 |
| 统计时分复用 STDM | 按需分配时隙 | 集中传送有数据用户的内容，提高突发业务的资源利用率                                                     |
| 波分复用 WDM      | 光的波长     | 光纤中的频分复用                                                                                       |
| 码分复用 CDM      | 码片序列     | 不同用户可在同一时间使用同一频段，靠编码区分                                                           |

TDM 的“帧”是一轮时隙，不等同于链路层的数据帧。FDM 不要求不同用户必须使用完全相同宽度的子频带。

**TDM 对传输介质的要求：**

- **位速率**：介质的位速率大于单个信号的位速率，并应足以承载各路信号的总位速率及必要开销。
- **频率带宽**：介质带宽应足以容纳调制后结合信号（复合信号）的频率带宽，实际通常还需留有余量。

#### CDMA 计算

在教材的同步、正交、理想接收模型中，将码片中的 `0` 映射为 $-1$，`1` 映射为 $+1$。每站分配一个长度为 $m$ 的码片向量 $S$：

- 发送比特 1：发送 $S$。
- 发送比特 0：发送 $-S$。
- 不发送：贡献零向量。
- 多站同时发送：接收向量为各站发送向量的逐项叠加。

不同站点的码片向量正交：

$$
\frac1m S\cdot T=0,\qquad \frac1m S\cdot S=1,\qquad \frac1m S\cdot(-S)=-1.
$$

接收到混合向量 $X$ 后，计算目标站点的归一化内积：

$$
\boxed{b_S=\frac1m X\cdot S}.
$$

结果为 $+1$ 表示发送 1，$-1$ 表示发送 0，$0$ 表示该站未发送。

例：$S=(1,1,-1,-1)$，$T=(1,-1,1,-1)$。S 站发送 1，T 站发送 0：

$$
X=S-T=(0,2,-2,0),\qquad \frac{X\cdot S}{4}=1,\quad \frac{X\cdot T}{4}=-1.
$$

**求和后要除以码片数。** 码片速率与信息比特率也不同：每个信息比特用 $m$ 个码片表示时，码片速率为信息比特率的 $m$ 倍。

### 3.5.2 ALOHA 协议

| 项目           | 纯 ALOHA                 | 时隙 ALOHA           |
| -------------- | ------------------------ | -------------------- |
| 发送时刻       | 有数据就发送             | 只能在时隙开始时发送 |
| 是否先侦听     | 否                       | 否                   |
| 时间同步       | 不要求站点按统一时隙发送 | 需要时隙同步         |
| 冲突后的处理   | 等待随机时间后重传       | 等待随机时隙后重传   |
| 冲突易发区长度 | $2T$                     | $T$                  |

这里假设各帧发送时间相同，均为 $T$，时隙 ALOHA 的时隙长度也为 $T$。**时隙化可以减少冲突，但不能消除冲突**：两个站点选择同一时隙仍会碰撞。

### 3.5.3 CSMA 协议

载波侦听多路访问（CSMA）在发送前先监听信道。由于传播时延存在，**本地侦听为空闲，不代表其他站点没有刚开始发送**，因此仍可能冲突。

| 类型          | 侦听到空闲                                       | 侦听到忙                         | 特点                                     |
| ------------- | ------------------------------------------------ | -------------------------------- | ---------------------------------------- |
| 1-坚持 CSMA   | 立即发送                                         | 持续侦听，空闲后立即发送         | 空闲利用及时，但多个等待站点容易同时发送 |
| 非坚持 CSMA   | 立即发送                                         | 等待随机时间后重新侦听           | 减少同时争抢，但可能浪费空闲时间         |
| $p$-坚持 CSMA | 在时隙边界以概率 $p$ 发送，以 $1-p$ 推迟一个时隙 | 持续侦听，等待空闲后参与时隙竞争 | 在冲突概率和等待时间间折中               |

$p$-坚持主要用于时隙化信道；推迟后仍要检查信道状态，不能在已经忙的信道上继续按概率盲发。

### 3.5.4 CSMA/CD

CSMA/CD 在 CSMA 基础上增加**碰撞检测**，用于传统共享式、半双工以太网。

基本过程：**先听后发，边听边发；冲突停发，随机退避。** 检测到冲突后发送强化冲突的干扰信号，停止当前帧传输，等待退避后重新竞争。

#### 争用期与最小帧长

采用 CSMA/CD 的以太网要求：

$$
\boxed{\text{最短帧发送时延}\ge\text{争用期}=2\times\text{最大单程传播时延}}.
$$

设网络中最远两个站点的单程传播时延为 $\tau$。发送方最迟可能在约 $2\tau$ 后才检测到冲突，因此发送完整帧的时间必须至少覆盖该往返时间：

$$
\boxed{T_{\mathrm{frame}}\ge 2\tau,\qquad L_{\min}\ge 2\tau R}.
$$

$L_{\min}$ 的单位为 bit；换算为字节要除以 8，并按题目要求向上取整。

如果帧太短，发送方可能已经发完并停止检测，远端碰撞信号才到达，从而误以为发送成功。

传统 10 Mbit/s 以太网以 512 比特时间作为争用期：

$$
2\tau=51.2\ \mu s,\qquad L_{\min}=512\ \mathrm{bit}=64\ \mathrm{B}.
$$

**64 B 指从目的地址到 FCS 的 MAC 帧长度，不包含前导码和帧开始定界符。** 小于最小帧长的碰撞残片不作为有效帧接收。

#### 截断二进制指数退避

发生第 $i$ 次碰撞后，令 $k=\min(i,10)$，从整数集合 $\{0,1,\ldots,2^k-1\}$ 中随机选择 $r$：

$$
\boxed{T_{\mathrm{backoff}}=r\times2\tau}.
$$

- 第 1 次碰撞：$r\in\{0,1\}$。
- 第 2 次碰撞：$r\in\{0,1,2,3\}$。
- 达到第 10 次后，随机数范围不再继续扩大。
- 达到 16 次尝试仍失败时，放弃该帧并报告错误。

**退避结束后仍需遵守载波侦听等发送条件，不保证此刻必然能发送。** 退避时间可以为 0，也不表示能够无视忙信道。

#### 典型计算

若单程传播时延为 $20\ \mu s$，速率为 10 Mbit/s，在只计传播时延的模型下：

$$
L_{\min}\ge 2\times20\times10^{-6}\times10^7=400\ \mathrm{bit}=50\ \mathrm{B}.
$$

这是由题设推得的理论下限；若题目指定采用标准以太网，还要满足 64 B 的标准最小帧长。

### 3.5.5 CSMA/CA

无线链路不能简单照搬 CSMA/CD：自身发送信号可能掩盖远端信号，而且两个发送站点可能彼此听不到，却都能到达同一接收端，形成**隐藏站**问题。

CSMA/CA 使用**碰撞避免**机制降低碰撞概率，并通过确认与重传处理失败。**“避免”不表示保证没有碰撞。**

#### 帧间间隔与随机退避

本章传统 802.11 模型中：

$$
\boxed{SIFS<PIFS<DIFS}.
$$

| 间隔 | 用途                              | 优先级                     |
| ---- | --------------------------------- | -------------------------- |
| SIFS | ACK、CTS、分片间响应等            | 最高，便于连续完成一次交换 |
| PIFS | 点协调功能 PCF 中的协调访问       | 介于两者之间               |
| DIFS | 分布式协调功能 DCF 的普通数据竞争 | 相对较低                   |

DCF 的基本流程：

1. 侦听信道；普通竞争发送要满足 DIFS 等待条件。
2. 若需要退避，从竞争窗口中随机选择退避时隙数。
3. 信道保持空闲时逐时隙递减；信道变忙则**冻结剩余计数**。
4. 再次空闲并经过 DIFS 后，从剩余值继续倒计时。
5. 计数减到 0 时发送；接收端正确收到需确认的单播帧后，等待 SIFS 再发 ACK。
6. 未收到 ACK 则按规则扩大竞争窗口并重试。

初次发送且信道已经满足持续空闲条件时，教材模型允许不经过随机退避直接发送；忙后等待、重传以及连续发送后续帧等情况需要按规则退避。不要把所有发送都简化成“空闲就立即发送”。

#### RTS/CTS 与虚拟载波侦听

可在较长数据帧前使用短控制帧预约信道：

```text
发送站 → 接收站：RTS
等待 SIFS
接收站 → 发送站：CTS
等待 SIFS
发送站 → 接收站：DATA
等待 SIFS
接收站 → 发送站：ACK
```

其他站点根据控制帧或数据帧中的持续时间字段设置**网络分配向量 NAV**，在预约时间内推迟访问。这称为虚拟载波侦听，与实际监听物理信道共同使用。

RTS/CTS 可以缓解隐藏站导致的长数据帧碰撞，但自身也可能冲突，并且增加控制开销，不是每次数据传输都必须使用。

| 对比项     | CSMA/CD                      | CSMA/CA                                     |
| ---------- | ---------------------------- | ------------------------------------------- |
| 典型环境   | 共享式半双工以太网           | 无线局域网                                  |
| 碰撞处理   | 发送中检测碰撞并停止         | 尽量避免碰撞，通过缺少 ACK 判断传输可能失败 |
| 链路层 ACK | 以太网 MAC 不使用逐帧 ACK    | 普通需确认的单播交换使用 ACK                |
| 关键手段   | 碰撞检测、干扰信号、指数退避 | 帧间间隔、退避、ACK、NAV、可选 RTS/CTS      |

### 3.5.6 轮询与令牌传递

轮询由控制站依次询问各站是否需要发送；令牌传递由站点按约定顺序传递一个特殊控制帧，取得令牌的站点才可发送。

- 正常运行时可以避免多个站点同时争用导致的碰撞。
- 令牌本身用于控制发送权，不承载普通用户数据。
- 需要管理令牌丢失、重复以及站点加入退出等情况。
- 逻辑环不一定对应物理环；令牌总线在物理总线上构造逻辑传递顺序。

#### CSMA/CD 与令牌环

CSMA/CD 属于**随机访问协议**，站点竞争共享信道，可能发生冲突，负载越大，冲突通常越严重。令牌环属于**轮询访问协议**，各站依次获得令牌后才能发送，重负载下表现通常更稳定。

#### 令牌持有时间与数据帧回收

- **有限发送权**：令牌持有时间有限，站点不能无限占用信道；无数据发送时，应及时传递令牌。
- **目的站复制，源站回收**：目的站复制数据帧并继续转发，源站负责回收自己发送的数据帧，防止其在环中无限循环。
- **释放令牌**：基本令牌环模型中，源站回收数据帧后释放新令牌，传递发送权；部分实现支持提前释放令牌。

## 3.6 局域网

### 3.6.1 基本概念与体系结构

局域网通常覆盖较小范围，便于组织内部共享资源。其技术特征主要由**拓扑结构、传输介质和介质访问控制方法**决定。

| 典型网络         | 逻辑拓扑 | 典型物理拓扑               |
| ---------------- | -------- | -------------------------- |
| 传统共享式以太网 | 总线形   | 总线形，或集线器形成的星形 |
| 令牌环           | 环形     | 可为星形连接               |
| FDDI             | 双环     | 双环                       |

IEEE 802 参考模型把数据链路层划分为：

- **逻辑链路控制 LLC 子层**：向上提供统一接口，屏蔽不同 MAC 方法的差异。
- **介质访问控制 MAC 子层**：处理介质访问、MAC 帧、MAC 地址和差错检测等与具体网络相关的问题。

### 3.6.2 以太网与 IEEE 802.3

#### 基本特点、网卡与 MAC 地址

以太网 MAC 提供无连接、尽力而为的交付服务。发送前不建立 MAC 层连接，不对普通数据帧逐帧确认，检出错误后丢弃。

网络适配器（网卡、NIC）实现主机与局域网的连接，承担物理层和数据链路层的相关功能。常见以太网 MAC 地址为 **48 位，即 6 B**，通常写成 12 个十六进制数字。

| 地址类型 | 含义                                        |
| -------- | ------------------------------------------- |
| 单播地址 | 标识单个接口，供一对一传输                  |
| 组播地址 | 标识一组接收者                              |
| 广播地址 | `FF:FF:FF:FF:FF:FF`，向所在广播域内各站发送 |

MAC 地址标识网络接口；有多个网络接口的路由器会有多个接口地址。MAC 地址通常也称“物理地址”，但它参与的是链路层寻址，不能据此认定它属于物理层。

#### 常见传统以太网名称

| 名称     | 速率      | 典型介质   | 教材中的典型距离                          |
| -------- | --------- | ---------- | ----------------------------------------- |
| 10BASE5  | 10 Mbit/s | 粗同轴电缆 | 单段 500 m                                |
| 10BASE2  | 10 Mbit/s | 细同轴电缆 | 单段 185 m                                |
| 10BASE-T | 10 Mbit/s | 双绞线     | 站点到集线器 100 m                        |
| 10BASE-F | 10 Mbit/s | 光纤       | 具体距离取决于所指子类型，教材表列 2000 m |

`BASE` 表示基带传输，`T` 表示双绞线，`F` 表示光纤。传统 10 Mbit/s 以太网使用曼彻斯特编码。

**光纤以太网主要用于支持点对点通信，目的是扩大以太网的覆盖范围。**

#### Ethernet II 的 MAC 帧格式

```text
目的地址    源地址      类型       数据与填充        FCS
  6 B        6 B       2 B        46～1500 B        4 B
```

$$
\boxed{L_{\mathrm{MAC}}=6+6+2+L_{\mathrm{data}}+4=18+L_{\mathrm{data}}}.
$$

| 长度或字段            | 数值        | 注意事项                            |
| --------------------- | ----------- | ----------------------------------- |
| 最小 MAC 帧           | 64 B        | 数据不足 46 B 时填充                |
| 最大普通未标记 MAC 帧 | 1518 B      | 不考虑 VLAN 标签及其他扩展          |
| 以太网 MTU            | 1500 B      | 不包括 MAC 首尾部                   |
| 前导码                | 7 B         | 物理层同步用途，不计入上述 MAC 帧长 |
| 帧开始定界符 SFD      | 1 B         | 紧随前导码，不计入上述 MAC 帧长     |
| 帧间间隔              | 96 比特时间 | 不是 MAC 帧中的一个字段             |

类型字段表示上层协议，如 `0x0800` 表示 IPv4。IEEE 802.3 基本帧格式相应位置使用长度含义；做题要区分题目采用的帧格式。

FCS 使用 CRC，保护 MAC 帧中从目的地址到数据及填充的内容，不把前导码作为 MAC 帧内容参加该校验。

**最小数据字段为 46 B，不代表上层交下来的数据必须至少 46 B。** 例如上层交付 40 B，只需添加 6 B 填充，MAC 帧仍为 64 B。

#### 发送时间与有效速率

若题目只计算 MAC 帧发送时间：

$$
T=\frac{8L_{\mathrm{MAC}}}{R}.
$$

若题目要求连续帧发送时计入 8 B 前导码与定界符以及 96 比特时间的帧间间隔，按每帧分摊一次间隔：

$$
T_{\mathrm{周期}}=\frac{8(L_{\mathrm{MAC}}+8)+96}{R}.
$$

例：100 Mbit/s 链路发送 1518 B 的 MAC 帧，每帧承载 1500 B 上层数据，忽略其他开销：

$$
T_{\mathrm{周期}}=\frac{8(1518+8)+96}{10^8}=123.04\ \mu s,
$$

$$
R_{\mathrm{有效}}=\frac{1500\times8}{123.04\times10^{-6}}\approx97.53\ \mathrm{Mbit/s}.
$$

若问更高层的应用数据速率，还要扣除网络层、传输层等首部。

#### 高速以太网

| 类型            | 标称速率   | 双工与 CSMA/CD                               |
| --------------- | ---------- | -------------------------------------------- |
| 快速以太网      | 100 Mbit/s | 半双工使用 CSMA/CD，全双工不使用             |
| 吉比特以太网    | 1 Gbit/s   | 教材包含半双工与全双工；全双工不使用 CSMA/CD |
| 10 吉比特以太网 | 10 Gbit/s  | 只支持全双工，不使用 CSMA/CD                 |

**吉比特以太网不采用曼彻斯特编码。** 不要将传统 10 Mbit/s 以太网的编码方式推广到吉比特以太网。

**使用以太网帧格式，不等于必须使用 CSMA/CD。** 全双工点对点链路没有共享式半双工链路的碰撞竞争问题。

### 3.6.3 IEEE 802.11 无线局域网

#### 基本结构

| 概念       | 含义                                                 |
| ---------- | ---------------------------------------------------- |
| AP         | 无线接入点，连接无线站点与分配系统                   |
| BSS        | 基本服务集，基础设施模式下包含一个 AP 及其服务的站点 |
| SSID       | 用于标识无线网络的服务集标识符                       |
| DS         | 分配系统，连接多个 BSS                               |
| ESS        | 通过 DS 连接形成的扩展服务集                         |
| 自组织网络 | 无固定 AP，由站点直接组织通信                        |

基础设施模式下，同一 BSS 中站点之间的通信通常经 AP 转发。多个 BSS 可组成 ESS，支持站点在覆盖区域内移动。

#### 帧类型与地址字段

802.11 帧分为**数据帧、控制帧、管理帧**。RTS、CTS、ACK 属于控制帧。

无线传输的一跳收发方与最终源、目的站可能不同，因此数据帧可能需要多个地址字段。以下讨论教材中常见的三地址基础设施模式：

| To DS（去往 AP） | From DS（来自 AP） | 地址 1               | 地址 2             | 地址 3       |
| ---------------- | ------------------ | -------------------- | ------------------ | ------------ |
| 1                | 0                  | 接收地址：AP         | 发送地址：无线源站 | 最终目的地址 |
| 0                | 1                  | 接收地址：无线目的站 | 发送地址：AP       | 原始源地址   |

**地址 1 看无线这一跳发给谁，地址 2 看这一跳是谁发的；地址 3 补充端到端的源或目的地址。** To DS 与 From DS 都为 1 的情况可使用第 4 个地址，本表不展开。

例：无线站 A 经 AP 向同一局域网内的 B 发数据，A→AP 的地址 1 为 AP、地址 2 为 A、地址 3 为 B。AP 再向无线 B 转发时，地址 1 为 B、地址 2 为 AP、地址 3 为 A。

若 B 在另一个 IP 网络，A 发给本地 AP 的帧中，地址 3 应为本地下一跳路由器接口的 MAC 地址，不能直接写远程 B 的 MAC 地址。跨路由器后会为下一段链路重新封装。

### 3.6.4 虚拟局域网 VLAN

**虚拟局域网（VLAN）通过软件配置方式实现设备的逻辑分组与管理**，把同一物理局域网中的设备按逻辑划分成不同的**广播域**，不要求同一 VLAN 的设备处于同一交换机上。

- 同一 VLAN 可以跨交换机，通过相应链路延伸。
- 同一交换机上的不同 VLAN 不能仅靠普通二层转发直接通信。
- VLAN 间通信通常需要路由器或具有三层转发功能的交换机。
- VLAN 是逻辑划分与服务，不是一种新的物理传输介质。

常见划分依据包括交换机端口、MAC 地址、网络层信息等。本章重点掌握按端口划分的 VLAN。

#### IEEE 802.1Q 标签

在源 MAC 地址之后、原类型字段之前插入 4 B 标签：

```text
目的地址  源地址  802.1Q标签  原类型  数据与填充  FCS
  6 B      6 B      4 B       2 B      可变      4 B
```

标签包含标识标签类型的字段以及控制信息，其中 **VID 占 12 位**。12 位可以表示 $2^{12}=4096$ 个编码值，但不能把这直接等同于全部可分配的普通 VLAN 数量。

标签改变了帧内容，FCS 必须相应重新计算。标准模型下，带标签帧的最大长度由 1518 B 增加到 1522 B，1500 B 的上层数据上限不因此增加；最小 MAC 帧仍可为 64 B。不要对所有帧机械地一律加 4 B，最小帧情形还要考虑填充。

#### 接入链路与干线链路

| 链路           | 典型连接       | 本章常见处理                                  |
| -------------- | -------------- | --------------------------------------------- |
| 接入链路       | 主机与交换机   | 主机收发普通未标记帧，交换机依据端口确定 VLAN |
| 干线链路 Trunk | 交换机与交换机 | 可承载多个 VLAN，通过标签区分所属 VLAN        |

**设置 VLAN 后，两台主机之间通信不一定使用带 IEEE 802.1Q 标签的帧。** 是否携带标签取决于帧经过的链路及端口配置：普通主机通过接入端口通信时，通常收发不带标签的以太网帧；跨交换机的 Trunk 链路上通常使用带标签的帧来区分 VLAN。因此，不能认为划分 VLAN 后，通信全程都使用 802.1Q 帧。

发送给普通终端时，交换机按端口配置移除标签。同一 VLAN 内的广播或未知单播泛洪，也只能在该 VLAN 的相关转发端口间进行。

## 3.7 广域网与 PPP

### 3.7.1 广域网的基本概念

广域网覆盖范围通常较大，通过通信链路和交换设备连接较远的主机、网络或局域网。**覆盖范围只是区别之一，还要结合网络采用的协议与技术。**

#### 存储转发、结点交换机与点对点链路

- **存储转发**：分组交换广域网中的中间结点先接收并存储分组，再根据转发信息选择下一跳，经输出链路转发，分组逐跳到达目的地。
- **结点交换机**：是广域网交换网络中的交换结点，负责分组的存储转发；不要直接等同于局域网中的二层以太网交换机。
- **路由器**：用于互联不同网络，按网络层地址选择下一跳并转发分组；在 IP 广域网中，也可以承担内部交换结点的作用。
- **点对点链路**：广域网中的交换结点之间通常通过点对点链路连接，一条链路直接连接两个结点，多条链路组成交换网络。

这里的存储转发针对**分组交换广域网**；点对点描述一段链路的连接方式，不表示源主机与目的主机之间只有一跳。

| 对比项       | 局域网                   | 广域网                 |
| ------------ | ------------------------ | ---------------------- |
| 典型范围     | 楼宇、园区等较小区域     | 城市、地区乃至更大范围 |
| 典型连接     | 共享介质或交换式接入     | 点对点链路及交换网络   |
| 本章代表技术 | 以太网、无线局域网、VLAN | PPP 等点对点链路协议   |

广域网和互联网不是同义词。互联网强调多个网络通过路由设备互联，可包含局域网与广域网。

### 3.7.2 PPP 的组成与特点

点对点协议（PPP）是**面向字节的数据链路层协议**，用于两个直接相连节点之间的**全双工通信**。

**PPP 有链路建立过程**：先建立并配置链路，再传输数据，通信结束后终止链路；有链路建立过程不等于提供可靠传输。

PPP 主要由三部分组成：

| 组成                | 作用                               |
| ------------------- | ---------------------------------- |
| 帧封装方法          | 封装上层分组，并提供定界和透明传输 |
| LCP，链路控制协议   | 建立、配置、测试和终止数据链路     |
| NCP，网络控制协议族 | 为不同网络层协议配置相应参数       |

PPP **支持可选的身份验证**，可在链路建立后、网络层配置前验证对端身份；也**支持动态分配 IP 地址**，例如通过 NCP 中的 IPCP 协商 IPv4 地址。

PPP 支持在同一链路上承载多种网络层协议，通过协议字段区分。它使用 CRC 检错，但普通数据传输**不使用帧序号、逐帧确认和超时重传提供可靠交付**。

PPP 的链路建立阶段可以存在控制报文的确认，这不等于其数据传输阶段提供可靠传输。也不要把“建立了链路”与“可靠交付”当成同一个属性。

### 3.7.3 PPP 帧格式

以下为教材中的未压缩基本格式：

```text
F       A       C       协议       信息字段       FCS      F
1 B     1 B     1 B      2 B       0～1500 B       2 B     1 B
7E      FF      03
```

| 字段 | 作用                                                     |
| ---- | -------------------------------------------------------- |
| F    | 标志字段，`0x7E`，即 `01111110`                          |
| A    | 地址字段，固定为 `0xFF`；点对点链路不靠它寻找多个目的站  |
| C    | 控制字段，固定为 `0x03`                                  |
| 协议 | 标识信息字段的内容；如 `0x0021` 为 IPv4，`0xC021` 为 LCP |
| 信息 | 上层分组或控制协议报文                                   |
| FCS  | CRC 检验字段，本章按 2 B 基本格式计算                    |

PPP 无需为了碰撞检测规定以太网式的最小数据字段，信息字段可以为 0 B。不要把以太网的 46 B 最小数据长度用于 PPP。

### 3.7.4 透明传输与工作过程

| 传输方式     | 透明传输方法                                  |
| ------------ | --------------------------------------------- |
| 异步传输     | 字符（字节）填充，使用转义字节 `0x7D`         |
| 同步比特传输 | 零比特（0 bit）填充，连续 5 个 `1` 后插入 `0` |

这两种填充方法均用于实现**透明传输**。字节填充和比特填充是不同场景的方法，不是在每次 PPP 传输中都叠加使用；同步比特传输采用零比特填充，也不改变 PPP 面向字节的协议特点。

PPP 的典型过程为：

```text
链路静止 → 物理连接建立 → LCP协商 → 可选身份鉴别
         → NCP配置网络层 → 数据通信 → 链路终止 → 链路静止
```

LCP 管链路参数，NCP 管网络层参数。PPP 工作在点对点链路上，不需要用 CSMA/CD 来解决多个站点争用共享介质的问题。

## 3.8 数据链路层设备

### 3.8.1 网桥与以太网交换机

网桥根据 MAC 地址和转发表连接不同网段，可以隔离冲突域。二层以太网交换机可看作多端口网桥，支持多个端口并行转发。

| 设备                   | 工作层次   | 转发依据           | 冲突域 | 广播域                   |
| ---------------------- | ---------- | ------------------ | ------ | ------------------------ |
| 中继器、集线器         | 物理层     | 不分析 MAC/IP 地址 | 不隔离 | 不隔离                   |
| 网桥、二层交换机       | 数据链路层 | MAC 地址           | 隔离   | 同一 VLAN 内不隔离       |
| 支持 VLAN 的二层交换机 | 数据链路层 | VLAN 与 MAC 地址   | 隔离   | 不同 VLAN 分属不同广播域 |
| 路由器                 | 网络层     | IP 地址及路由表    | 隔离   | 隔离链路层广播域         |

**冲突域与广播域速记：**

- **集线器**：不隔离冲突域，也不隔离广播域。
- **交换机**：隔离冲突域，不隔离广播域（默认未划分 VLAN）。
- **路由器**：隔离冲突域，也隔离广播域。

全双工交换机端口不发生共享式以太网碰撞；做冲突域计数题时，通常按交换机端口分隔各段。若一个端口下接集线器，集线器下的站点仍共享一个冲突域。

### 3.8.2 两种交换方式

| 方式     | 转发时机                             | 优点                                       | 局限                                                    |
| -------- | ------------------------------------ | ------------------------------------------ | ------------------------------------------------------- |
| 直通交换 | 收到足以确定目的端口的首部后开始转发 | 转发时延较小                               | 尚未收齐 FCS，不能先完成整帧 CRC 检验；不同速率适配受限 |
| 存储转发 | 收齐整帧并检查后再转发               | 可丢弃检出的错误帧，便于不同速率端口间转发 | 增加接收整帧与处理时延                                  |

计算存储转发时延时，每一跳必须收齐该帧才能开始下一跳发送。直通交换题则按题目给出的“收齐多少字节后开始转发”计算，不能统一当成收到完整帧。

### 3.8.3 交换机的自学习与转发

核心规则：**根据源 MAC 地址学习，根据目的 MAC 地址转发。**

交换机收到从端口 $p$ 进入的帧后：

1. 根据源地址学习或更新“源 MAC → 入端口 $p$”的对应关系；支持 VLAN 时在对应 VLAN 内维护。
2. 查询目的地址并决定动作。
3. 根据老化机制清除长期未更新的动态表项。

| 目的地址查询结果             | 动作                                                     |
| ---------------------------- | -------------------------------------------------------- |
| 已知单播，出端口与入端口不同 | 只向查到的出端口转发                                     |
| 已知单播，出端口与入端口相同 | 过滤，不再转回原网段                                     |
| 未知单播                     | 在所属 VLAN 内向除入端口外的其他允许转发端口泛洪         |
| 广播                         | 在所属 VLAN 内向除入端口外的其他允许转发端口泛洪         |
| 组播                         | 本章基础模型按泛洪理解；实际行为还可能受组播管理配置影响 |

**未知单播泛洪不等于把目的地址改成广播地址。** 帧仍保留原来的单播目的地址。

#### 自学习例题

设交换机端口 1、2、3 分别连接 A、B、C，均在同一 VLAN，初始转发表为空。

| 事件                 | 新学习内容 | 转发动作                 |
| -------------------- | ---------- | ------------------------ |
| A 从端口 1 向 B 发送 | A → 1      | B 未知，向端口 2、3 泛洪 |
| B 从端口 2 向 A 回复 | B → 2      | A 已知，仅向端口 1 转发  |
| A 再向 B 发送        | 刷新 A → 1 | B 已知，仅向端口 2 转发  |
| C 从端口 3 向 A 发送 | C → 3      | A 已知，仅向端口 1 转发  |

收到目的为 B 的帧，只能让交换机学习**源 A**的位置，不能据此学习 B 的位置；B 必须作为源发送帧，才会触发相应学习。

### 3.8.4 生成树与二层环路

交换机之间的冗余链路可能形成二层环路，使广播或未知单播帧反复转发，造成广播风暴及转发表不稳定。

生成树协议（STP）通过逻辑阻塞部分冗余端口，使当前用于转发的拓扑无环。物理连接仍保留；链路失效后可以重新调整转发拓扑。

### 3.8.5 共享式与交换式以太网

| 比较项           | 集线器组成的共享式以太网 | 交换机组成的交换式以太网       |
| ---------------- | ------------------------ | ------------------------------ |
| 设备层次         | 物理层                   | 数据链路层                     |
| 介质和带宽       | 所有站点共享             | 各端口链路可独立工作           |
| 通信方式         | 半双工                   | 主机点对点连接通常为全双工     |
| 多对主机同时通信 | 互相争用介质，可能冲突   | 无输出端口等资源冲突时可以并行 |
| 单播处理         | 向其他端口复制信号       | 已知目的时选择端口转发         |
| 广播处理         | 信号扩散到其他端口       | 在相同 VLAN 内泛洪             |
| CSMA/CD          | 使用                     | 全双工时不使用                 |

若 $N$ 个站点理想均分速率为 $R$ 的集线器，平均份额为 $R/N$。交换机不能简单照搬该除法，各端口可独享其链路速率，但仍受交换容量、输出端口竞争等条件限制。

**交换机每个接口所连接结点的独享链路带宽，不会因接入结点数量增加而被均分、减少。** 在交换容量充足、无输出端口竞争等瓶颈的理想条件下，随着参与并行通信的接口结点增加，交换机可同时提供的总带宽也随之增加；这不表示一台既定交换机的硬件交换容量会自动增大。

若题目问 $N$ 个速率为 $R$ 的全双工端口的总收发容量，按收发两个方向合计可写 $2NR$；若只统计单方向端口速率总和则为 $NR$。先看题目统计口径，不要将“交换容量”与一次通信的有效吞吐量混为一谈。

## 3.9 公式与易错点速查

### 3.9.1 常用公式

| 内容                             | 公式                                     | 前提或口径                                                 |
| -------------------------------- | ---------------------------------------- | ---------------------------------------------------------- |
| 检测 $e$ 位错误                  | $d_{\min}\ge e+1$                        | 最小码距                                                   |
| 纠正 $t$ 位错误                  | $d_{\min}\ge2t+1$                        | 保证纠正任意至多 $t$ 位错误                                |
| 同时纠正 $t$ 位、检测 $e$ 位错误 | $d_{\min}\ge t+e+1$                      | $e\ge t$；超过 $t$ 且不超过 $e$ 位的错误须检出，不能误纠正 |
| 海明码校验位数                   | $2^k\ge m+k+1$                           | $m$ 位信息、$k$ 位校验，纠单错                             |
| CRC 的 FCS 长度                  | $r$ 位                                   | 生成多项式阶数为 $r$，位串长 $r+1$                         |
| GBN 窗口                         | $W_T\le2^n-1,\ W_R=1$                    | 序号 $n$ 位                                                |
| SR 等大窗口                      | $W_T=W_R\le2^{n-1}$                      | 序号 $n$ 位                                                |
| 停止—等待利用率                  | $U=T_D/(T_D+RTT+T_A)$                    | 无差错，忽略处理时延，RTT 为往返传播时间                   |
| 滑动窗口利用率                   | $U=\min(1,WT_D/(T_D+RTT+T_A))$           | 理想流水线模型                                             |
| 最小连续发送窗口                 | $W_{\min}=\lceil(T_D+RTT+T_A)/T_D\rceil$ | 防止 ACK 返回前用尽窗口                                    |
| 碰撞检测最小帧长                 | $L_{\min}\ge2\tau R$                     | 单程传播时延为 $\tau$，长度单位 bit                        |
| 指数退避                         | $r\cdot2\tau$                            | $r\in[0,2^{\min(i,10)}-1]$，取整数                         |
| CDMA 解码                        | $X\cdot S/m$                             | 理想同步正交码片，$m$ 为码片数                             |

### 3.9.2 考前辨析

1. **CRC 余数为零不等于可靠交付**：可能漏检，也不处理丢失与重复。
2. **发送窗口不是“剩余还能发送的帧数”**：其中还包括已发未确认的位置。
3. **GBN 接收窗口为 1，SR 才缓存窗口内乱序帧**；两者的最大发送窗口不同。
4. **ACK 编号先看定义**：确认到 $i$ 与期望 $i$ 相差一个序号。
5. **帧长先统一单位**：B 转 bit 要乘 8；传播时间、发送时间不可混用。
6. **最小帧长服务于碰撞检测**；以太网 MTU 1500 B 描述最大上层数据部分。
7. **普通 MAC 帧 64～1518 B**，不含 8 B 前导码与 SFD，也不含帧间间隔。
8. **CSMA/CD 不能用于概括全部以太网**：全双工以太网不需要碰撞检测。
9. **CSMA/CA 仍可能碰撞**；RTS/CTS 也不是必选的万能防碰撞机制。
10. **交换机学源地址、查目的地址**；未知单播泛洪后仍是单播帧。
11. **普通交换机隔离冲突域**；广播域边界要结合 VLAN 和路由设备判断。
12. **PPP 有链路建立过程，也不代表其数据传输可靠**；LCP 和 NCP 的职责不同。
