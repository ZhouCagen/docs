# 第 1 章 计算机网络体系结构

## 1.1 计算机网络概述

### 1.1.1 概念、组成与功能

**计算机网络：通过通信设备和线路，将分散、自治的计算机系统互连，按照协议实现信息传递和资源共享的系统。** “自治”表示各计算机能够独立运行；网络把这些计算机连接起来，并不意味着它们变成一台计算机。

网络由节点和链路连接而成。节点既可能是产生、使用数据的主机，也可能是转发数据的交换机、路由器。链路连接节点，路径则由一串链路组成。

| 划分角度 | 组成               | 理解重点                                         |
| -------- | ------------------ | ------------------------------------------------ |
| 组成部分 | 硬件、软件、协议   | 硬件承载通信，软件实现功能，协议约束通信规则     |
| 工作方式 | 边缘部分、核心部分 | 边缘主机运行应用；核心网络和路由器提供连通与转发 |
| 功能组成 | 资源子网、通信子网 | 前者提供资源和处理能力，后者负责数据通信         |

基本功能是**数据通信和资源共享** ；还可实现分布式处理、负载均衡和通过冗余提高可靠性。

- **internet（互联网）** ：多个网络互连形成的网络，泛称。
- **Internet（因特网）** ：采用 TCP/IP 协议族的全球性互联网，专称。
- **ISP** ：互联网服务提供商，为用户提供接入服务；不同 ISP 之间还要互连。
- **Web（万维网）** ：运行在因特网上的一种应用系统，不等于整个因特网。

### 1.1.2 客户/服务器与对等方式

主机通信的实质是主机中**进程之间通信** 。

| 方式               | 特征                                 | 易错点                                         |
| ------------------ | ------------------------------------ | ---------------------------------------------- |
| 客户/服务器（C/S） | 客户进程主动请求，服务器进程提供服务 | 客户、服务器首先描述进程角色，不由机器性能决定 |
| 对等（P2P）        | 对等进程既可请求资源，也可提供资源   | 仍可有集中管理或发现机制，不等于完全没有服务器 |

同一台主机可以同时运行客户进程和服务器进程。网络核心负责转发数据，并不替代边缘应用完成全部业务处理。

### 1.1.3 网络分类与拓扑

| 分类依据 | 常见类型                 | 判断依据                                           |
| -------- | ------------------------ | -------------------------------------------------- |
| 覆盖范围 | PAN、LAN、MAN、WAN       | 个人区域、局域、城域、广域；不要只靠固定公里数死分 |
| 使用者   | 公用网、专用网           | 服务对象是否面向公众                               |
| 传输技术 | 广播式、点对点式         | 是否共享广播信道，或由点对点链路连接节点           |
| 传输介质 | 有线网、无线网           | 信号使用的传输介质                                 |
| 拓扑结构 | 总线形、星形、环形、网状 | 节点与链路的连接关系                               |

**物理拓扑看布线，逻辑拓扑看通信方式。** 例如集线器以星形布线，但各节点共享介质，逻辑上按总线方式工作。

| 拓扑   | 主要特点                                                                 |
| ------ | ------------------------------------------------------------------------ |
| 总线形 | 共享一条主干，布线较省；主干故障影响大，共享介质需要协调访问             |
| 星形   | 节点连接中心设备，便于管理；中心设备故障影响整体，单条支线故障通常局部化 |
| 环形   | 节点组成环，数据按协议沿环传递；可靠性取决于是否有旁路、双环等机制       |
| 网状   | 节点间有多条路径，冗余性强；链路成本和管理复杂度较高                     |

## 1.2 数据交换方式

### 1.2.1 三种交换方式

**电路交换：先建立连接、预留资源，再传数据，最后释放连接。** 预留的是沿途资源，可以是频带或时隙，不一定独占整根物理线路。建立后通常不逐报文存储转发，适合持续通信；即使暂时不发送，预留资源也不能随意让其他连接占用。

**报文交换：以整个报文为单位存储转发。** 中间节点必须收完完整报文才能转发，较长报文会带来较大的存储需求和等待时间。

**分组交换：把报文分成若干分组，以分组为单位存储转发。** 节点收完一个分组就可转发，不必等待整个报文；不同分组可以在不同链路上同时推进，形成流水线。

#### 三种交换方式对比

| 比较项                 | 电路交换                                                   | 报文交换                                           | 分组交换                                     |
| ---------------------- | ---------------------------------------------------------- | -------------------------------------------------- | -------------------------------------------- |
| 完成传输所需时间       | 已建立电路时通常最少                                       | 整报文逐跳转发，通常最多                           | 可以流水线传输，通常较少                     |
| 存储转发时延           | 无逐报文存储转发时延                                       | 较高，须收完完整报文                               | 较低，收完一个分组即可转发                   |
| 通信前是否需要建立连接 | 是                                                         | 否                                                 | 数据报方式否；虚电路方式是                   |
| 缓存开销               | 无报文级存储转发缓存需求                                   | 高，须缓存整个报文                                 | 单个转发单元的缓存需求较低                   |
| 是否支持差错控制       | 交换机制本身不提供报文级差错控制                           | 可实现差错检测与重传等控制                         | 可实现分组级差错控制，具体取决于协议         |
| 报文数据是否有序到达   | 同一电路按序传送                                           | 单个报文不拆分，其内部顺序保持；多个报文不保证按序 | 数据报可能失序；虚电路通常按序               |
| 是否需要额外控制信息   | 数据传送阶段无须给每个分组添加转发首部；建立、释放仍需信令 | 需要，通常每个报文附加控制信息                     | 需要，每个分组均有控制信息，开销占比通常较大 |
| 线路分配灵活性         | 较低，沿已建立电路预留资源                                 | 较高，按需选择线路转发                             | 数据报方式灵活，可逐分组选择下一跳           |
| 线路利用率             | 突发通信时较低，空闲期间仍占预留资源                       | 通常较高，按需共享                                 | 通常较高，适合多用户突发通信                 |
| 存储转发单位           | 不按完整报文存储转发                                       | 整个报文                                           | 分组                                         |
| 主要代价               | 建立连接与闲置资源开销                                     | 大缓存、长等待                                     | 分组首部、转发处理与必要的重组开销           |

读对比表时注意：

- **“分组交换较低”指相对于整报文存储转发的等待，不是没有时延。** 有竞争流量时，分组仍可能经历较长排队。
- **“支持差错控制”表示便于实现，不表示一定可靠。** 端系统也可在电路交换之上实现差错控制；不能把表中的简写理解成端到端完全不允许检错。
- **“报文交换有序”要看比较对象。** 单份报文作为整体转发，不存在其内部各分组走不同路径的问题；先后发送的多份报文仍可能因路径和排队不同而失序。
- **分组交换并非任何时候线路利用率都最高。** 频繁首部开销、拥塞与重传都会影响有效利用率；“高、低”是典型场景的定性比较。

**分组不是越小越好：** 小分组可缩短单次存储转发等待和重传数据量，但首部比例上升，分组处理次数增加。

### 1.2.2 数据报与虚电路

两者都属于**分组交换** 。

| 比较项   | 数据报                         | 虚电路                               |
| -------- | ------------------------------ | ------------------------------------ |
| 发送前   | 不先建立逻辑连接               | 建立虚电路                           |
| 转发信息 | 通常依据目的地址               | 依据虚电路标识及节点中的连接状态     |
| 路径     | 各分组独立转发，可能走不同路径 | 同一虚电路的分组通常沿已建立路径传输 |
| 顺序     | 可能失序                       | 通常按发送顺序到达                   |
| 节点状态 | 不要求为每个连接保存虚电路状态 | 需要维护虚电路状态                   |
| 资源性质 | 动态共享                       | 仍可共享链路，不等于独占物理电路     |

**虚电路不是电路交换；TCP 连接也不是网络层虚电路。** Internet 的 IP 层提供数据报服务，TCP 在端系统中实现面向连接的可靠传输。

## 1.3 性能指标与计算

### 1.3.1 速率、带宽、吞吐量

| 概念         | 含义                                                     | 常见单位               |
| ------------ | -------------------------------------------------------- | ---------------------- |
| 数据传输速率 | 每秒传送的比特数                                         | bit/s，写作 b/s 或 bps |
| 网络带宽     | 链路传输能力，常指额定或最大比特率                       | b/s                    |
| 频率带宽     | 信号或信道占用的频率范围宽度                             | Hz，详见物理层         |
| 吞吐量       | 一段时间内实际通过网络或接口的数据量除以时间             | b/s                    |
| 有效吞吐量   | 单位时间成功交付的有效业务数据，不计协议开销、重复重传等 | b/s                    |

端到端吞吐量受**瓶颈链路、共享流量、协议开销及端系统处理能力** 等共同限制。链路标称带宽高，不表示应用一定达到该速率。

单位先统一：

$$
1\ \mathrm{B}=8\ \mathrm{bit},\qquad
1\ \mathrm{Mb/s}=10^6\ \mathrm{bit/s}.
$$

网络速率的 k、M、G 通常按 $10^3,10^6,10^9$；文件大小按题设换算，MiB 明确表示 $2^{20}$ B。不能把 MB 与 Mb 混为一谈。

### 1.3.2 四种时延

$$
\boxed{d=d_{\mathrm{发送}}+d_{\mathrm{传播}}+d_{\mathrm{处理}}+d_{\mathrm{排队}}}.
$$

| 时延                 | 含义                                       | 计算或影响因素                 |
| -------------------- | ------------------------------------------ | ------------------------------ |
| 发送时延（传输时延） | 从第一个比特开始发，到最后一个比特进入链路 | $L/R$                          |
| 传播时延             | 一个比特的信号从链路一端传播到另一端       | $\ell/v$                       |
| 处理时延             | 检查首部、检错、查表等                     | 设备与处理任务                 |
| 排队时延             | 等待输出链路可用                           | 负载、缓存、调度，具有不确定性 |

其中 $L$ 为发送长度（bit），$R$ 为链路速率（bit/s），$\ell$ 为链路长度（m），$v$ 为传播速度（m/s）。

**发送是“把比特放上链路”，传播是“比特沿链路走”。** 提高 $R$ 能缩短发送时延，不能直接提高介质中的传播速度；减小报文长度也不能缩短固定链路的传播时延。

单条链路、不计处理与排队时，从开始发送到最后一个比特到达：

$$
\boxed{T=\frac LR+\frac\ell v}.
$$

例：发送 $1500$ B，速率 $10$ Mb/s，距离 $100$ km，传播速度 $2\times10^8$ m/s：

$$
d_{\mathrm{发送}}=\frac{1500\times8}{10^7}=1.2\ \mathrm{ms},\qquad
d_{\mathrm{传播}}=\frac{10^5}{2\times10^8}=0.5\ \mathrm{ms}.
$$

最后一个比特在开始发送后 $1.7$ ms 到达。

### 1.3.3 多跳存储转发与流水线

**先数链路：经过 $r$ 台中间路由器，一条简单路径通常有 $r+1$ 段链路。** 下列公式均假设整分组存储转发，不计处理、排队和竞争流量。

一个长度为 $L$ 的分组经过 $k$ 段链路，每段速率为 $R_i$、传播时延为 $\tau_i$：

$$
\boxed{T_1=\sum_{i=1}^k\left(\frac L{R_i}+\tau_i\right)}.
$$

若将报文分为 $N$ 个**等长分组** ，每组总长度为 $L$（包含首部），且各段速率相同为 $R$：

$$
\boxed{T_N=(N+k-1)\frac LR+\sum_{i=1}^k\tau_i}.
$$

理由：第一个分组要经历 $k$ 次发送；流水线充满后，每隔 $L/R$，目的主机又完整收到一个分组。传播时延沿路径累加一次，不能再乘 $N$。

若各段速率不同、等长分组连续发送，仍不计其他流量和处理开销，则

$$
T_N=\sum_{i=1}^k\left(\frac L{R_i}+\tau_i\right)
+(N-1)\max_i\frac L{R_i}.
$$

**不能直接套等长公式的情况：** 最后一个分组较短、分组走不同路径、各节点有额外处理瓶颈、存在竞争流量，或题目采用直通交换。此时按“完整到达时间”和“输出链路空闲时间”逐项递推。

**例：** $12000$ bit 报文经过 $3$ 段 $1$ Mb/s 链路，忽略传播和首部开销。

- 整报文存储转发：$3\times12000/10^6=36$ ms。
- 分为 $12$ 个 $1000$ bit 分组：$(12+3-1)\times1000/10^6=14$ ms。

若每个分组另有 $100$ bit 首部，则发送长度变为 $1100$ bit，总时间为 $15.4$ ms。**划分分组用有效载荷，计算发送时延用包含开销的总长度。**

理想电路交换若建立时间为 $t_s$、端到端预留速率为 $R$，则可按

$$
T_{\mathrm{电路}}=t_s+\frac MR+\sum_i\tau_i
$$

计算发送 $M$ bit 的完成时间。电路已建立时，不按存储转发模型把 $M/R$ 乘链路数。

### 1.3.4 时延带宽积、RTT 与利用率

**链路时延带宽积：**

$$
\boxed{\mathrm{BDP}=R\,d_{\mathrm{传播}}}.
$$

单位为 bit，表示链路连续发送时，传播路径上可容纳的“在途比特量”。例如 $100$ Mb/s、单程传播时延 $10$ ms，积为 $10^6$ bit，即 $125000$ B。

**RTT（往返时延）：** 一次往返经历的时间。若只有对称的传播时延，可取 RTT $=2d_{\mathrm{传播}}$；实际题目可能还计入处理、排队和确认发送，必须按题设口径。

讨论可靠传输窗口时，常用 $R\times\mathrm{RTT}$ 估算维持流水发送所需的在途数据量。它与单条链路的 $R\times d_{\mathrm{传播}}$ 含义不同，不能混用。

**利用率：** 信道被使用的时间占总观察时间的比例。更高利用率不一定带来更低时延；当业务到达速度逼近服务能力时，排队会显著增加。

若题目采用理想 M/M/1 排队模型，以 $\rho$ 表示利用率、$D_0$ 表示平均服务时间，则平均系统逗留时间为 $D_0/(1-\rho)$。**这是特定排队模型的结果，不是所有网络通用的时延公式。**

## 1.4 分层、协议、服务与接口

### 1.4.1 为什么分层

网络体系结构是**网络各层及其协议的集合** ，描述各层完成什么功能及如何协作；具体设备、程序和部署属于实现。

分层使每层依赖下层提供的服务、向上层提供服务。只要服务接口不变，内部实现可以替换。代价是增加首部和层间处理开销，也可能出现功能重复。

#### 哪些不是分层的目的？

| 说法                       | 是否属于目的 |
| -------------------------- | ------------ |
| 降低网络设计的复杂性       | ✓            |
| 提高各层独立性             | ✓            |
| 定义标准接口               | ✓            |
| 提供标准语言               | ✓            |
| 促进标准化                 | ✓            |
| 规定各层功能的具体实现方法 | ✗            |
| 保证网络通信效率一定提高   | ✗            |

这里的“提供标准语言”指提供描述网络功能与通信过程的共同术语，并非统一编程语言。分层规定各层的功能及接口，**不规定具体实现方法** ；由于存在首部和层间处理等开销，也**不保证通信效率一定提高** 。

**对等层是逻辑通信；相邻层通过接口交互；真实数据经过发送端逐层向下、物理介质传送、接收端逐层向上。**

### 1.4.2 协议、服务、接口

**OSI 参考模型的三个主要概念是：服务、接口、协议。** 注意与下文的“协议三要素：语法、语义、同步”区分。

| 概念 | 解决什么问题               | 方向                 |
| ---- | -------------------------- | -------------------- |
| 协议 | 不同系统的对等实体如何通信 | 水平                 |
| 服务 | 下层向上层提供什么能力     | 垂直                 |
| 接口 | 相邻层如何访问这些能力     | 同一系统中的层间边界 |

**协议三要素：语法、语义、同步（时序）。**

- 语法：字段、格式、编码，例如某字段占多少位。
- 语义：字段和操作的含义，例如某标志表示确认。
- 同步：事件的先后、配合与时序，例如先建立连接再传数据。

**服务访问点 SAP** 是上层使用下层服务的逻辑访问位置。服务原语描述请求、指示、响应、证实等交互；无确认服务不必包含完整的四类交互。

本层利用下层服务，通过本层协议与对等实体配合，再向上层提供服务。**协议实现细节对上层隐藏，不表示上层看不到服务结果。**

### 1.4.3 服务的不同分类

| 分类维度          | 区别                                         |
| ----------------- | -------------------------------------------- |
| 面向连接 / 无连接 | 是否先建立逻辑联系并维护相应连接状态         |
| 可靠 / 不可靠     | 是否由该服务保证相应的正确交付，而非尽力而为 |
| 有应答 / 无应答   | 是否对某次操作反馈应答                       |

这些维度不能简单画等号。连接不一定预留独占线路；有检错不等于有重传；有应答也不等于已经实现完整可靠传输。

TCP 在不可靠的 IP 服务上，通过序号、确认、重传等实现可靠传输。这说明**下层不可靠，不代表上层无法提供可靠服务** 。

### 1.4.4 封装：SDU、PCI、PDU

- **SDU（服务数据单元）** ：本层从上层接收、需要承载的数据。
- **PCI（协议控制信息）** ：本层协议所需的控制信息，可位于首部或尾部。
- **PDU（协议数据单元）** ：本层对等实体交换的单位。

不考虑分段、合并等处理时：

$$
\boxed{\text{本层 PDU}=\text{本层 PCI}+\text{本层 SDU}}.
$$

“+”表示组合，不限定控制信息全在开头。本层 PDU 交给下一层后，通常成为下一层的 SDU；实际协议也可能先分段或合并，因此不总是一一对应。

```text
应用数据
→ [TCP 首部 | 应用数据]
→ [IP 首部 | TCP 首部 | 应用数据]
→ [帧首部 | IP 首部 | TCP 首部 | 应用数据 | 帧尾部]
→ 比特流对应的物理信号
```

接收端逆向解封装，并依据协议号、端口号等把数据交给相应的上层处理实体。

## 1.5 OSI、TCP/IP 与五层模型

### 1.5.1 OSI 七层的职责

| 层次（自上而下） | 主要职责                                                                                      |
| ---------------- | --------------------------------------------------------------------------------------------- |
| 应用层           | 提供应用与网络的接口                                                                          |
| 表示层           | 数据格式转换                                                                                  |
| 会话层           | 会话管理                                                                                      |
| 传输层           | 复用和分用、差错控制、流量控制、连接管理、可靠传输管理、端口寻址（端口号）                    |
| 网络层           | 路由选择、拥塞控制、网际互联、差错控制、流量控制、连接管理、可靠传输管理、逻辑寻址（IP 地址） |
| 数据链路层       | 差错控制、流量控制、物理寻址（MAC 地址）                                                      |
| 物理层           | 定义电路接口参数、信号的含义及电气特性等                                                      |

这是参考模型的功能划分，不意味着每个实际协议都实现表中全部功能。例如以太网可检错但不因此保证可靠交付；加密也并非只能出现在表示层。

**三个通信范围：链路层是相邻节点，网络层是主机到主机，传输层是进程到进程。**

### 1.5.2 三种模型的对应

| OSI 七层               | TCP/IP 四层          | 教学五层模型       |
| ---------------------- | -------------------- | ------------------ |
| 应用层、表示层、会话层 | 应用层               | 应用层             |
| 传输层                 | 传输层               | 传输层             |
| 网络层                 | 网际层               | 网络层             |
| 数据链路层、物理层     | 网络接口层（链路层） | 数据链路层、物理层 |

OSI 先形成通用参考模型，再发展相应协议；TCP/IP 从实际协议发展出体系结构。教学五层模型结合两者的表达方式，不是把 TCP/IP 标准硬拆成五层。

#### 网络层与传输层的服务类型对比

| 模型         | 网络层                 | 传输层                 |
| ------------ | ---------------------- | ---------------------- |
| OSI 七层模型 | 面向连接、无连接都支持 | 面向连接               |
| TCP/IP 模型  | 只提供无连接服务       | 面向连接、无连接都支持 |

**OSI 模型：**

- **网络层：** 既可以采用面向连接的虚电路方式，也可以采用无连接的数据报方式。
- **传输层：** 只提供面向连接的服务。

**TCP/IP 模型：**

- **网络层：** IP 提供无连接的数据报服务。每个 IP 数据报独立转发，不需要先建立网络层连接。
- **传输层：** TCP 提供面向连接的可靠传输；UDP 提供无连接的数据报传输。

**可靠性考点：TCP/IP 模型由传输层处理端到端的可靠传输问题。** 网络层 IP 提供尽力而为的服务，不保证可靠交付；传输层中的 TCP 通过序号、确认、重传等机制实现可靠传输。**这不表示所有传输层协议都可靠，UDP 不保证可靠传输。**

| 五层模型   | 常见协议或技术         | 常见数据单位               |
| ---------- | ---------------------- | -------------------------- |
| 应用层     | HTTP、DNS、SMTP、FTP   | 应用报文                   |
| 传输层     | TCP、UDP               | TCP 报文段、UDP 用户数据报 |
| 网络层     | IP、ICMP               | IP 数据报、分组            |
| 数据链路层 | 以太网 MAC、PPP        | 帧                         |
| 物理层     | 各种物理接口、线路编码 | 比特                       |

以太网标准包含链路层与物理层内容，不能把整套以太网技术限定在单一层。ARP 的归属存在教材划分差异；记住它解决本地链路上的 IP 地址到链路地址映射，做层次题时按指定模型判断。

### 1.5.3 设备与转发范围

| 设备             | 典型工作层 | 转发依据             | 广播与冲突范围                           |
| ---------------- | ---------- | -------------------- | ---------------------------------------- |
| 中继器、集线器   | 物理层     | 信号，不识别地址     | 不隔离冲突域或广播域                     |
| 网桥、二层交换机 | 数据链路层 | MAC 地址和转发表     | 隔离冲突域；同一 VLAN 默认属于一个广播域 |
| 路由器           | 网络层     | 目的 IP 地址和转发表 | 隔离链路层广播域                         |

多层设备按题目实际功能判断；“网关”一词也不唯一对应某一层。

例：主机 A 经路由器 R 向异网主机 B 发送数据。

1. A 按层封装；第一跳帧的目的地址是下一跳 R 的链路地址，不是远端 B 的链路地址。
2. R 接收帧并取出 IP 数据报，依据目的 IP 决定下一跳，再为新链路封装新的帧。
3. B 逐层解封装，最终按传输层端口等信息交给进程。

普通转发且不考虑 NAT、隧道等机制时，源和目的 IP 通常保持不变，链路层地址随链路改变；IP 首部中的 TTL 等字段仍会变化。路由器转发过境流量一般不需要把应用数据上交给应用进程。
