## 8.1 基本概念

**对应：书页 331—332 的知识部分。**

排序：重新排列记录，使关键字非递减或非递增。本章默认**升序（非递减）** 。

**稳定性：** 若记录 $R_i$ 与 $R_j$ 关键字相同，原先 $R_i$ 在前，排序后仍在前，则算法稳定。保持的是**相对次序** ，不是绝对下标。关键字全部互异时，稳定性不影响结果；要证明不稳定，只需找一个相等记录颠倒的反例。

| 分类 | 含义 | 主要成本 |
| --- | --- | --- |
| 内部排序 | 所有待排记录都能放在内存 | 关键字比较、记录移动、辅助空间 |
| 外部排序 | 数据不能一次装入内存，需要内外存交换 | 磁盘块读写 / I/O，兼顾内部处理 |
| 比较排序 | 通过比较关键字决定次序 | 插入、交换、选择、归并等 |
| 非比较排序 | 利用关键字取值或数位结构 | 基数、计数等 |

辅助空间不包括原始输入，默认计入递归栈；输出数组是否计入需另作说明。一次交换通常按 **3 次记录赋值移动** 计算，代码直接写出这三步，不能把交换次数与移动次数混为一谈。

### 代码公共定义与下标约定

```cpp
#define MaxSize 1000
typedef int ElemType;
```

| 算法 | 有效元素 | A[0] 的用途 / 调用方式 |
| --- | --- | --- |
| 直接插入、折半插入、希尔、堆排序 | A[1..n]，分配 n+1 个单元 | 哨兵或暂存单元，不是待排记录 |
| 冒泡、简单选择、计数 | A[0..n−1] | 正常数据 |
| 快排、归并 | A[low..high] 闭区间 | 普通数组调用范围为 0 到 n−1 |

## 8.2 插入排序

**对应：书页 333—336 的知识部分。**

### 8.2.1 直接插入排序

维护前缀 `A[1..i-1]` 有序，将 `A[i]` 插入合适位置。查找插入位置时，边比较边后移，共处理 $n-1$ 个待插入元素。

```cpp
void InsertSort(ElemType A[], int n)
{
    for (int i = 2; i <= n; i++)
    {
        if (A[i] < A[i - 1])
        {
            A[0] = A[i];             // 哨兵 + 暂存
            int j = i - 1;
            for (; A[0] < A[j]; j--)
                A[j + 1] = A[j];
            A[j + 1] = A[0];
        }
    }
}
```

`A[0] < A[j]` 为严格小于：遇到相等元素就停，新记录插在旧的相等记录后面，保证稳定。到 `j=0` 时哨兵与自身比较为假，无须额外检查 `j>=1`。

用 `49a`、`49b` 表示身份不同的相等记录：

| 状态 | 已有序前缀 | 未处理部分 |
| --- | --- | --- |
| 初始 | 49a | 38 65 97 76 13 27 49b |
| 插入 38 | 38 49a | 65 97 76 13 27 49b |
| 插入 65 | 38 49a 65 | 97 76 13 27 49b |
| 插入 97 | 38 49a 65 97 | 76 13 27 49b |
| 插入 76 | 38 49a 65 76 97 | 13 27 49b |
| 插入 13 | 13 38 49a 65 76 97 | 27 49b |
| 插入 27 | 13 27 38 49a 65 76 97 | 49b |
| 插入 49b | 13 27 38 49a 49b 65 76 97 | 空 |

- 最好：已有序，比较 $n-1$ 次，无须移动有效记录，$O(n)$。
- 最坏：逆序，需大量后移，$O(n^2)$；忽略哨兵及额外预判时，典型关键字比较总数为 $n(n-1)/2$。精确比较次数要按具体代码计数。
- 平均：比较与移动均为平方级，$O(n^2)$。
- 空间 $O(1)$，稳定；可改写为链表版，通过修改链接插入。
- 有序前缀只有**局部有序性** ，其中元素不一定已到最终位置。

### 8.2.2 折半插入排序

先在有序前缀里折半定位，再统一后移元素。减少了比较次数，**没有减少必须后移的元素数** 。

```cpp
void BInsertSort(ElemType A[], int n)
{
    for (int i = 2; i <= n; i++)
    {
        A[0] = A[i];
        int low = 1, high = i - 1;
        while (low <= high)
        {
            int mid = low + (high - low) / 2;
            if (A[mid] > A[0])
                high = mid - 1;
            else
                low = mid + 1;  // 相等时往右，插在旧相等记录之后
        }
        for (int j = i - 1; j >= high + 1; j--)
            A[j + 1] = A[j];
        A[high + 1] = A[0];
    }
}
```

结束时 `low = high + 1`，插入位置就是 `low`。

| 项目 | 结论 |
| --- | --- |
| 总比较次数的量级 | O(n log n) |
| 最好时间（上述无预判版本） | O(n log n)，已有序仍逐次折半定位 |
| 平均、最坏时间 | O(n²)，移动占主导 |
| 辅助空间 | O(1) |
| 稳定性 | 稳定，关键是相等时向右定位 |
| 存储 | 适合顺序表，需要随机访问 |

比较次数的**阶** 由 n 决定，具体次数仍可能受搜索路径影响。若另加“已不小于前驱就跳过”的优化，最好时间可到 $O(n)$，但那已不是上面直接照书整理的版本。

### 8.2.3 希尔排序（缩小增量排序）

选择递减增量 $d_1>d_2>\cdots>d_t=1$；每趟将下标相差 d 的元素划为同一子序列，对各子序列分别做直接插入排序。最后 d=1 才是对全表做直接插入。

**分组按下标间隔，不是切成若干连续块。**

```cpp
void ShellSort(ElemType A[], int n)
{
    for (int dk = n / 2; dk >= 1; dk /= 2)
    {
        for (int i = dk + 1; i <= n; i++)
        {
            if (A[i] < A[i - dk])
            {
                A[0] = A[i];  // 仅暂存，不是保证循环停止的哨兵
                int j = i - dk;
                for (; j > 0 && A[0] < A[j]; j -= dk)
                    A[j + dk] = A[j];
                A[j + dk] = A[0];
            }
        }
    }
}
```

必须有 `j > 0`，因为步长不为 1 时可能跳过下标 0。

书中示例采用增量 **5、3、1** （不同于上述代码的折半增量）：

| 增量 | 一趟后的整个序列 |
| --- | --- |
| 初始 | 49a 38 65 97 76 13 27 49b 55 4 |
| 5 | 13 27 49b 55 4 49a 38 65 97 76 |
| 3 | 13 4 49b 38 27 49a 55 65 97 76 |
| 1 | 4 13 27 38 49b 49a 55 65 76 97 |

49a 与 49b 相对次序改变，说明希尔排序不稳定，尽管每个子序列的直接插入本身稳定。

时间复杂度依赖增量序列，不能给所有希尔排序统一写成 $O(n\log n)$ 或 $O(n^{1.3})$。书中提到的约 $O(n^{1.3})$ 不是对任意增量的保证；上面折半增量版本常用最坏界为 $O(n^2)$，已有序时仍需多趟扫描，最好为 $\Theta(n\log n)$。空间 $O(1)$，适合顺序存储。

## 8.3 交换排序

**对应：书页 340—343 的知识部分。**

### 8.3.1 冒泡排序

比较相邻记录，逆序就交换。下面从后向前扫描，一趟把未排序部分的最小值放到前端最终位置。

```cpp
void BubbleSort(ElemType A[], int n)
{
    for (int i = 0; i < n - 1; i++)
    {
        bool flag = false;
        for (int j = n - 1; j > i; j--)
        {
            if (A[j - 1] > A[j])
            {
                ElemType temp = A[j - 1];
                A[j - 1] = A[j];
                A[j] = temp;
                flag = true;
            }
        }
        if (!flag)
            return;  // 一整趟无交换，说明已经有序
    }
}
```

- 最好：已有序，1 趟、$n-1$ 次比较、0 次交换，$O(n)$。没有提前退出标志的版本不具备这个最好界。
- 最坏：逆序，$n-1$ 趟，比较和交换均为 $n(n-1)/2$ 次；按三次赋值完成交换，移动数为 $3n(n-1)/2$。
- 平均与最坏 $O(n^2)$，空间 $O(1)$。
- 相等不交换，因此稳定。
- 每趟至少一个元素归位；有序部分具有全局次序，剩余记录不会再排到它之前。
- 可用链表实现，但扫描方向须适应链表的访问方式，不能直接照搬单链表的逆向下标循环。

### 8.3.2 快速排序

#### 1. 思想与一趟划分

选枢轴 pivot，划分后左侧都不大于它、右侧都不小于它；枢轴就位，再递归处理左右两段。**左右段各自未必有序。**

以下采用书中的首元素枢轴、双向扫描、“挖坑填数”写法：

```cpp
int Partition(ElemType A[], int low, int high)
{
    ElemType pivot = A[low];
    while (low < high)
    {
        while (low < high && A[high] >= pivot)
            high--;
        A[low] = A[high];
        while (low < high && A[low] <= pivot)
            low++;
        A[high] = A[low];
    }
    A[low] = pivot;
    return low;
}

void QuickSort(ElemType A[], int low, int high)
{
    if (low < high)
    {
        int pivotpos = Partition(A, low, high);
        QuickSort(A, low, pivotpos - 1);
        QuickSort(A, pivotpos + 1, high);
    }
}
```

- 枢轴先保存，原位置成为“坑”；先从右找小元素填左坑，再从左找大元素填右坑。
- 相遇后将枢轴放回，返回其位置，递归范围不包含它。
- 两个扫描条件包含等号，可推进相等关键字，避免某些错误写法的死循环。
- **本代码保证左边 ≤ pivot、右边 ≥ pivot** ；相等元素可能分布于两侧，不要强行记成“左边一定严格小于”。

书中序列的一趟划分：

```text
初始：49a 38 65 97 76 13 27 49b
枢轴：49a
一趟：27 38 13 | 49a | 76 97 65 49b
      左段未排序        右段未排序
```

#### 2. 时间与栈空间

| 划分状态 | 递推 / 过程 | 时间 | 递归辅助空间 |
| --- | --- | --- | --- |
| 每次近似均分 | T(n)=2T(n/2)+O(n) | O(n log n) | O(log n) |
| 通常平均情况 | 分治树平均深度为对数量级 | O(n log n) | O(log n) |
| 每次一边为空 | T(n)=T(n−1)+O(n) | O(n²) | O(n) |

固定首元素作枢轴时，已有序、逆序以及本代码处理大量相等元素时都可能发生严重退化。随机枢轴、三数取中可改善通常情况；它们不意味着所有输入都获得最坏 $O(n\log n)$ 的保证。

一次划分只需常数辅助变量，但**完整递归快排须计算栈空间** 。快排平均性能常较好，不能理解为所有场景必定最快。

#### 3. 稳定性与适用性

不稳定。例如 `3,2a,2b`，首元素枢轴划分可得到 `2b,2a,3`。书中数组实现适合顺序存储，依赖双向定位。每次划分至少确定一个枢轴位置；谈“第几趟”时需分清一次 Partition 与处理同一递归层全部子段的区别。

## 8.4 选择排序与堆

**对应：书页 351—354 的知识部分。**

### 8.4.1 简单选择排序

第 i 趟在未排序部分选最小值，与当前位置交换，扩大已归位前缀。

```cpp
void SelectSort(ElemType A[], int n)
{
    for (int i = 0; i < n - 1; i++)
    {
        int minpos = i;
        for (int j = i + 1; j < n; j++)
            if (A[j] < A[minpos])
                minpos = j;
        if (minpos != i)
        {
            ElemType temp = A[i];
            A[i] = A[minpos];
            A[minpos] = temp;
        }
    }
}
```

比较次数与初始状态无关：

$$
(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}2.
$$

最好、平均、最坏均为 $O(n^2)$；最多 $n-1$ 次交换，即 $3(n-1)$ 次移动，最好 0 次移动；空间 $O(1)$。

不稳定：`2a,2b,1 → 1,2b,2a`。选择时遇到相等值不更新最小位置，也不能阻止远距离交换破坏稳定性。可用于顺序表或链表；记录大且移动成本高时，移动次数少具有优势。

### 8.4.2 堆的结构与性质

堆的逻辑形态是**完全二叉树** ，通常用数组存储。下标从 1 开始：父亲 $\lfloor i/2\rfloor$，左孩子 $2i$，右孩子 $2i+1$，存在时才比较。

- 大根堆：父关键字不小于孩子，堆顶为最大值。
- 小根堆：父关键字不大于孩子，堆顶为最小值。
- 只约束祖先与后代，不要求兄弟或左右子树整体有序；堆不是 BST。
- 最后一个非叶结点为 $\lfloor n/2\rfloor$；叶结点为 $\lfloor n/2\rfloor+1,\ldots,n$，共 $\lceil n/2\rceil$ 个。
- n≥1 时，高度 $\lfloor\log_2 n\rfloor+1$。小根堆最大值一定可以在叶层找到，大根堆最小值同理；若有重复值，极值也可能同时在内部出现。

```text
大根堆：              87
                    /    \
                   45     78
                  / \    / \
                 32 17  65 53
                /
               9

数组：下标  1  2  3  4  5  6  7  8
      数值 87 45 78 32 17 65 53  9
```

### 8.4.3 向下调整与自底向上建堆（书中代码）

`HeapAdjust(A,k,len)` 的前提：**k 的左右子树已分别是大根堆，只有根位置可能违反堆序。** 每次选较大的孩子上移，暂存值沿这条路径下沉。

```cpp
void HeapAdjust(ElemType A[], int k, int len)
{
    A[0] = A[k];
    for (int i = 2 * k; i <= len; i *= 2)
    {
        if (i < len && A[i] < A[i + 1])
            i++;                   // 选较大的孩子，且防止右孩子越界
        if (A[0] >= A[i])
            break;
        A[k] = A[i];
        k = i;                     // 坑下移，继续沿该路径筛选
    }
    A[k] = A[0];
}

void BuildMaxHeap(ElemType A[], int len)
{
    for (int i = len / 2; i > 0; i--)
        HeapAdjust(A, i, len);
}
```

**建堆顺序自底向上，每次调整方向自上向下。** 叶结点自然已成堆，从最后一个非叶结点开始才能保证每次调整的前提。

书中序列 `53,17,78,9,45,65,87,32` 的建堆过程：

| 调整根 | 调整后的数组 |
| --- | --- |
| i=4 | 53 17 78 32 45 65 87 9 |
| i=3 | 53 17 87 32 45 65 78 9 |
| i=2 | 53 45 87 32 17 65 78 9 |
| i=1 | 87 45 78 32 17 65 53 9 |

单次向下调整最坏 $O(\log n)$，但建堆**不是** 简单地把所有结点都乘以树高：多数结点靠近叶层，最多移动很短距离。

$$
T_{\text{建堆}}
=O\!\left(\sum_{j\ge1}\frac{n}{2^{j+1}}j\right)
=O(n).
$$

书中给出的比较次数上界为不超过 4n，关键是记住**批量自底向上建堆为线性时间** 。

### 8.4.4 堆排序（书中代码）

升序原地堆排序使用大根堆：堆顶最大值与当前堆尾交换，缩小有效堆，再向下调整。

```cpp
void HeapSort(ElemType A[], int len)
{
    BuildMaxHeap(A, len);
    for (int i = len; i > 1; i--)
    {
        ElemType temp = A[1];
        A[1] = A[i];
        A[i] = temp;
        HeapAdjust(A, 1, i - 1);  // 已就位的 A[i] 不再参与调整
    }
}
```

- 建堆 $O(n)$，随后 $n-1$ 次取堆顶和调整，总体教材口径为 $O(n\log n)$。
- 堆顶交换到尾部后，右侧后缀已处于最终位置。
- 空间 $O(1)$，不稳定，适合顺序存储。
- 小根堆若同样“堆顶与尾部交换”，最终得到降序；若逐个弹出最小值另行输出，则输出流为升序。不要混淆两种输出方式。

### 8.4.5 堆的基本操作复杂度（参考图 2 转写）

以下空间复杂度指已有堆数组之外的**辅助空间** ，假设迭代调整且容量已足够；堆本身占 $O(n)$。

| 操作 | 步骤 | 最坏时间 | 辅助空间 | 说明 |
| --- | --- | --- | --- | --- |
| 读取堆顶 | 直接读 A[1] | O(1) | O(1) | 最大 / 最小值 |
| 插入 | 新元素放数组末尾，与父结点比较并向上调整 | O(log n) | O(1) | 上浮至多走到根 |
| 删除堆顶 | 末元素覆盖堆顶，长度减 1，向下调整 | O(log n) | O(1) | 每层选择较大 / 较小孩子 |
| 删除已知位置 i | 末元素覆盖 i，根据堆序向上或向下调整 | O(log n) | O(1) | “已知下标”是前提 |
| 按值查找再删除 | 先在堆中定位，再做上述删除 | O(n) | O(1) | 普通堆不提供按值快速定位 |
| 自底向上建堆 | i 从 ⌊n/2⌋ 到 1，分别下滤 | O(n) | O(1) | 不是 O(n log n) |
| 逐个插入建堆 | 从空堆连续插入 n 次 | O(n log n) | O(1) | 上界针对整个建堆过程 |
| 堆排序 | 建堆 + n−1 次堆顶交换、调整 | O(n log n) | O(1) | 不计原堆数组 |

参考图中的三步复杂度推导写为：

$$
T(n)=\underbrace{O(n)}_{\text{建堆}}
+\underbrace{\sum_{i=2}^{n}O(\log i)}_{n-1\text{ 次调整}}
=O(n\log n).
$$

“删除元素 $O(\log n)$”不能省略位置已知或删除堆顶的条件。使用递归调整时需计入递归栈；数组扩容也有单独代价，上表不包含扩容。

### 8.4.6 堆的应用：优先队列与 Top-K

**优先队列：** 优先级最高者从堆顶出队；入队用上浮，出队用下滤；读取最高优先级为 $O(1)$，入队出队最坏 $O(\log n)$。

**在 n 个数中保留最大的 k 个：维护容量 k 的小根堆。**

1. 先用前 k 个数建小根堆。
2. 对后续数 x，若 x 不大于堆顶，不影响所保留的最大 k 个；否则替换堆顶并向下调整。
3. 扫描结束，堆内就是最大 k 个数，但堆数组本身还不是排序结果。

选最小 k 个则反过来用大根堆。k≥2 时常写时间 $O(n\log k)$；空间 $O(k)$。k=1 时直接维护一个极值即可，时间 $O(n)$、空间 $O(1)$。若还要有序输出这 k 个数，需再排序或逐个弹出。

## 8.5 归并排序、基数排序和计数排序

**对应：书页 363—367 的知识部分。**

### 8.5.1 二路归并排序

#### 1. 思想和过程

把序列分成两半，各自递归排好，再将两个有序子表合成一个。自底向上理解：每个元素先视为长度 1 的有序段，再将相邻段两两合并。

```text
初始：[49] [38] [65] [97] [76] [13] [27]
一趟：[38 49] [65 97] [13 76] [27]
二趟：[38 49 65 97] [13 27 76]
三趟：[13 27 38 49 65 76 97]
```

#### 2. 归并与递归排序（书中代码整理）

原书使用全局辅助数组 B。这里改为**调用前统一分配并显式传入** ，避免全局 n 未定义；算法逻辑不变。B 与 A 等长，不能是同一块内存。

```cpp
void Merge(ElemType A[], ElemType B[], int low, int mid, int high)
{
    for (int k = low; k <= high; k++)
        B[k] = A[k];
    int i = low, j = mid + 1, k = low;
    while (i <= mid && j <= high)
    {
        if (B[i] <= B[j])
            A[k++] = B[i++];  // 相等时先取左段，保证稳定
        else
            A[k++] = B[j++];
    }
    while (i <= mid)
        A[k++] = B[i++];
    while (j <= high)
        A[k++] = B[j++];
}

void MergeSort(ElemType A[], ElemType B[], int low, int high)
{
    if (low < high)
    {
        int mid = low + (high - low) / 2;
        MergeSort(A, B, low, mid);
        MergeSort(A, B, mid + 1, high);
        Merge(A, B, low, mid, high);
    }
}
```

调用示意：声明 `ElemType B[MaxSize];`，在 n≤MaxSize 时调用 `MergeSort(A, B, 0, n-1)`。主比较循环结束后，左右段至多一段尚有剩余。

#### 3. 性能与比较次数

- 一次归并长度 a、b 的两个非空有序段，最少比较 $\min(a,b)$ 次，最多 $a+b-1$ 次；剩余元素直接复制。
- 一趟二路归并覆盖全部元素，时间 $O(n)$；共 $\lceil\log_2 n\rceil$ 趟。
- 最好、平均、最坏均为 $O(n\log n)$，这里按标准无跳过优化的实现。
- 辅助数组 $O(n)$，递归栈 $O(\log n)$，合计 $O(n)$。
- 稳定；适合顺序表和链表。链表合并可重连指针，空间情况不应直接套用数组版。
- 分组和每层整体搬移规模由 n 决定，具体关键字比较次数仍随数据变化。

对于自底向上的一趟，当前段长 s，下一趟段长 2s；孤立尾段不足以配对时可直接保留。不要把“段的数量”与“实际调用 Merge 的次数”无条件等同。

### 8.5.2 基数排序

#### 1. 多关键字思想

将一个关键字拆成 d 个数位，每位取值在 $0\sim r-1$，r 为基数。不是靠关键字两两比较，而是按数位分配、收集。

| 方法 | 顺序 | 做法 |
| --- | --- | --- |
| MSD，最高位优先 | 高位到低位 | 先按高位划桶，再在各桶内部处理下一位 |
| LSD，最低位优先 | 低位到高位 | 每位对全体记录做稳定分配、收集 |

不能把“按高位排一次，再对全体按低位排一次”当作 MSD，那会破坏高位的优先级。

#### 2. LSD：分配与收集

每趟准备 r 个队列 $Q_0,\ldots,Q_{r-1}$：

1. **分配：** 顺序扫描当前序列，按本位数字将记录从相应队尾入队。
2. **收集：** 按桶号 0 到 r−1，依次连接所有队列。
3. 对下一更高位重复，共 d 趟。

每一趟都必须稳定，这样新处理的高位相等时，才能保留已经排好的低位次序。位数不足时按前导零补齐。

书中例，r=10、d=3：

| 步骤 | 收集后的序列 |
| --- | --- |
| 初始 | 278 109 063 930 589 184 505 269 008 083 |
| 个位 | 930 063 083 184 505 278 008 109 589 269 |
| 十位 | 505 008 109 930 063 269 278 083 184 589 |
| 百位 | 008 063 083 109 184 269 278 505 589 930 |

例如个位为 9 的 `109,589,269`，第一次入同一队列后顺序不变。经过第 i 趟，整个序列按最低 i 位有序。

#### 3. 时间与空间

$$
T(n)=O(d(n+r)).
$$

每趟分配 O(n)，收集 O(r)，一共 d 趟，与初始有序程度无关。稳定；关键字要可分解成适合分配的数位，负数和其他类型需要额外约定。

**空间须区分实现：**

- 书中的链式基数排序：输入本来就是链表，只增加 r 个队头、队尾，辅助空间 **O(r)** 。
- 数组实现：通常另开 n 个记录的输出数组及 r 个计数槽，辅助空间 **O(n+r)** 。
- 若从数组新建 n 个链结点，这 n 个新结点也要计入额外空间。

书中本节仅给分配、收集过程，没有完整程序，因此这里保留过程和模拟表，不将额外实现冒充书中代码。

### 8.5.3 计数排序（书中带 * 的补充知识）

适合整数关键字，取值范围不能过大。设取值为 $0\sim k-1$，使用计数数组 C[k] 和输出数组 B[n]。

#### 1. 四步与代码

```cpp
void CountSort(const ElemType A[], ElemType B[], int n, int k)
{
    int C[MaxSize];
    for (int i = 0; i < k; i++)
        C[i] = 0;
    for (int i = 0; i < n; i++)
        C[A[i]]++;              // 当前 C[x] = x 的出现次数
    for (int i = 1; i < k; i++)
        C[i] += C[i - 1];        // 当前 C[x] = 不大于 x 的元素总数
    for (int i = n - 1; i >= 0; i--)
    {
        B[C[A[i]] - 1] = A[i];   // C 按数量计，B 的下标从 0 起
        C[A[i]]--;
    }
}
```

前提：0<k≤MaxSize，所有 `0 <= A[i] < k`，B 容量至少 n，A 与 B 不重叠。四步分别是清零、统计频次、前缀累加、反向回填。排序结果在 **B** ，A 未改动。

对于 `2a,4,3a,0,2b,3b`：

| 关键字 x | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| 频次 C[x] | 1 | 0 | 2 | 2 | 1 |
| 累加后 C[x] | 1 | 1 | 3 | 5 | 6 |

从右往左放：`3b→B[4]`、`2b→B[2]`、`0→B[0]`、`3a→B[3]`、`4→B[5]`、`2a→B[1]`，结果为 `0,2a,2b,3a,3b,4`。

反向扫描使靠后的同值记录先占据靠后的空位；计数递减后，靠前记录仍能排在它前面，故稳定。

#### 2. 复杂度与条件

时间最好、平均、最坏均为 $O(n+k)$；按所需计数槽 k 和结果槽 n 分析，标准稳定版空间 $O(n+k)$。手写代码以 MaxSize 预留计数容量，实际分配为 O(MaxSize)，这里只初始化、使用前 k 个槽；复杂度总表按问题规模配置容量的通常算法口径填写。若输出数组不算辅助空间，则工作空间记为 $O(k)$，但必须说明口径。

当 k=O(n) 时可达线性时间。取值范围很稀疏、k 远大于 n 时，计数数组可能不划算。负整数可按最小值做偏移，将取值范围映射到 `0..k-1`，此时 k 是范围宽度。

如果只需输出整数值，按频次直接写回可省输出数组；但这不能保留一般记录的身份及稳定次序，应与上述稳定版区分。

## 8.6 内部排序的比较与应用

**对应：书页 373—374，以及 390—391 的知识总结。完整复杂度大表放在本章最后。**

### 8.6.1 从中间状态识别算法

| 算法 | 一趟完成后的特征 | 是否至少一个元素到最终位置 |
| --- | --- | --- |
| 直接 / 折半插入 | 前缀内部有序，但其中元素还可能后移 | 不保证 |
| 希尔 | 各个间隔 d 的子序列分别有序 | 不保证 |
| 冒泡 | 最小值到前端或最大值到后端，取决于方向 | 是 |
| 简单选择 | 每次把剩余最小值放到当前前端 | 是 |
| 堆排序 | 堆顶移至末尾，剩余部分仍是堆 | 是 |
| 快排划分 | 枢轴两侧满足大小界，但各自不一定有序 | 是，至少枢轴 |
| 二路归并 | 有序段长度扩大，两段合一段 | 不保证 |
| LSD 基数 | 按已处理的低位有序 | 不保证 |

插入、冒泡和简单选择都可能出现“前缀有序”，区别在于这个前缀是否已是全表最小的一批。快排不能只看有没有某个元素位置碰巧正确，还要看两侧是否满足划分条件。

### 8.6.2 稳定性的记忆与判断

- 稳定：**直接插入、折半插入、冒泡、归并、基数、标准稳定版计数** 。
- 不稳定：**希尔、快速、简单选择、堆** 。
- 相邻逆序交换、插入时不跨过相等元素、合并时相等优先左段、队列分配保持先后，都有助于保证稳定。
- “代码中不交换相等值”不是充分条件，其他记录的远距离交换仍会颠倒同值记录。

### 8.6.3 选择排序方法

| 场景 | 可优先考虑 | 原因 |
| --- | --- | --- |
| 规模较小，或基本有序 | 直接插入 | 实现简单，已有序接近线性 |
| 规模小且移动记录代价大 | 简单选择，或只排序指针 / 下标 | 选择排序交换次数少 |
| 一般数组，追求通常平均速度 | 改进枢轴的快速排序 | 平均 O(n log n)，局部划分开销较小 |
| 需要最坏 O(n log n) 且辅助空间小 | 堆排序 | 不依赖幸运的划分，辅助空间 O(1) |
| 需要稳定且 O(n log n) | 归并排序 | 稳定，代价是数组辅助空间 O(n) |
| 链表排序 | 归并或直接插入 | 可用指针链接操作，归并适合大规模 |
| 整数范围较小 | 计数排序 | 利用取值范围，O(n+k) |
| 位数少、数位范围适中 | 基数排序 | O(d(n+r)) |
| 只求最大 / 最小 k 个 | 容量 k 的堆 | 不必对所有数据排序 |
| 数据放不进内存 | 外部归并排序 | 按块读写，控制 I/O |

还要考虑稳定性、关键字类型、辅助空间、输入分布等。书中“小规模”“中等规模”的示例数值不是通用阈值；实际也会在快排、归并的短子段上改用直接插入。

### 8.6.4 比较排序的下界

n 个互异关键字共有 $n!$ 种排列，比较判定树需要足够多的叶结点区分结果。若最坏比较次数为 h：

$$
2^h\ge n!,\qquad h\ge\lceil\log_2(n!)\rceil=\Omega(n\log n).
$$

因此一般比较排序的最坏时间下界是 **Ω(n log n)** 。计数、基数利用关键字结构，不属于仅靠比较的模型，所以可以在一定条件下达到线性时间，并不违背下界。

## 8.7 外部排序

**对应：书页 380—385 的知识部分。**

### 8.7.1 基本概念和两阶段

数据无法一次性装入内存，需要按磁盘块分批处理。总耗时可分为

$$
T=T_{\text{内部排序}}+T_{\text{外存读写}}+T_{\text{内部归并}}.
$$

教材模型中磁盘 I/O 往往是主要代价，因此目标是减少数据反复读写，而非只追求最少关键字比较。

1. **生成初始归并段：** 每次读入内存可容纳的数据，内部排序后写回，得到若干有序段。
2. **多路归并：** 每次合并若干段，逐步变成长段，最终只剩一个完整有序文件。

最简单的 k 路归并需 k 个输入缓冲区和 1 个输出缓冲区，另需选择结构及控制信息。若内存共 M 个块且每个缓冲至少 1 块，忽略其他开销时 $k\le M-1$。

```text
外存段 R1 → 输入缓冲1 ┐
外存段 R2 → 输入缓冲2 ├→ 选择当前最小记录 → 输出缓冲 → 外存新段
       …             │
外存段 Rk → 输入缓冲k ┘
```

输入缓冲取空就续读对应段的下一块；输出缓冲写满就落盘。整个归并段不需要同时装入内存。

### 8.7.2 归并趟数与 I/O

设初始有 r 个有序段，采用 k 路归并，k≥2：

$$
S=\lceil\log_k r\rceil.
$$

每趟段数变为原来的约 1/k，即 $r_{i+1}=\lceil r_i/k\rceil$。S 不包含最开始生成初始段的阶段。

若文件共 B 个磁盘块，每一阶段均完整读写整个文件，忽略取整、缓存及尾块差异：

$$
\text{每趟 I/O}=2B,\qquad
\text{总 I/O}=2B(1+S).
$$

书中例：2000 条记录，每块 125 条，共 16 块；生成 8 个初始段：

| 方案 | 归并趟数 S | 初始阶段 I/O | 归并 I/O | 总 I/O |
| --- | --- | --- | --- | --- |
| 二路归并 | 3 | 32 | 3×32=96 | 128 |
| 四路归并 | 2 | 32 | 2×32=64 | 96 |

减少趟数的两个方向：**增大归并路数 k，减少初始段数 r。** 前者受到缓冲空间与选择开销限制，后者可通过置换—选择排序实现。

若题目不计初始阶段、最终输出无需写回，或不同段参与归并的层数不同，应按实际读写过程计算，不能一律套用 $2B(1+S)$。

### 8.7.3 多路平衡归并与败者树

#### 1. 为什么需要败者树

直接从 k 个段首候选中选最小值，每轮需 O(k) 比较。增加 k 虽减少 I/O 趟数，却增加选择成本。

败者树是树形选择结构：

- k 个叶结点对应 k 个段的当前候选。
- 内部结点记录比赛的**败者** （较大者的段号）。
- 胜者继续向上比较，最终冠军的段号另存 `ls[0]`。
- 输出冠军后，只更新它所在段的候选，并沿该叶到根的路径重赛。

`ls[1]` 保存最后一场的败者，不是冠军；冠军另存在 `ls[0]`。结点中通常记的是**段号** ，不是关键字本身。

#### 2. 五路示例（重画书中图 8.17）

初始候选：`b0=10, b1=9, b2=20, b3=6, b4=12`。

```text
                    ls[0]=3（冠军：b3=6）
                              ↑
                    ls[1]=1（败者：b1=9）
                   /                         \
      ls[2]=0（败者：b0=10）       ls[3]=2（败者：b2=20）
             /       \                   /       \
 ls[4]=4（败者：b4=12） b0=10           b1=9      b2=20
        /      \
      b3=6     b4=12
```

比赛顺序：6 胜 12，败者段号 4 留在 `ls[4]`；6 胜 10，败者 0 留在 `ls[2]`；9 胜 20，败者 2 留在 `ls[3]`；6 胜 9，败者 1 留在 `ls[1]`，冠军 3 存 `ls[0]`。

输出 6 后，b3 读入 15：

| 重赛 | 结果 | 更新位置 |
| --- | --- | --- |
| 15 与 12 | 12 胜，15 败 | ls[4]=3 |
| 12 与 10 | 10 胜，12 败 | ls[2]=4 |
| 10 与 9 | 9 胜，10 败 | ls[1]=0；ls[0]=1 |

新冠军变为 b1=9，其他未受影响的子树无须重建。某段耗尽后，可将其候选设为概念上的 $+\infty$，不再抢占最小值。

#### 3. 性能

- 建树 O(k)，选择结构空间 O(k)，不含输入输出缓冲。
- 每输出一条后的重赛为 O(log k)，比直接线性选择的 O(k) 更好。
- k 为 2 的幂时，完整更新路径为 $\log_2 k$ 层；一般规模最多 $\lceil\log_2 k\rceil$ 次比较。
- 全部 S 趟内部选择成本约 $O(nS\log k)$；忽略取整时 $S\log k\approx\log r$，解释了增大归并路数不再线性增大总比较成本。

书中“总比较次数与 k 无关”是这种近似分析，**不能把带上下取整的对数乘积当作严格恒等式** 。实际还受树形、尾段、缓冲和常数开销影响。

k 并非越大越好：内存固定时，更多输入缓冲会挤压各缓冲容量，并增加调度等开销，要与实际外存访问方式匹配。

### 8.7.4 置换—选择排序：生成更长初始段

设输入文件 FI，输出文件 FO，工作区 WA 可容纳 w 条记录。核心是：**输出当前段还能接纳的最小记录，腾出空间后立即补读新记录。**

1. 先读 w 条记录到 WA，全部标记为当前段可用。
2. 选可用记录中最小者，记作 MINIMAX，输出。
3. 从 FI 补入一条新记录；若它不小于刚输出值，可继续用于本段；否则冻结到下一段。
4. 重复选择和补入，直到 WA 不再有当前段可用记录。
5. 结束当前段，解除剩余记录冻结状态，开始下一段。
6. 直到输入和工作区都空。

“冻结”只是保留在工作区等下一段，不是丢弃。当前段输出必须单调不下降；内部选最小可借助败者树。

书中例：FI 为 `17,21,5,44,10,12,56,32,29`，w=3。

| 本次输出 | 补入 | 下一轮可用于本段 | 冻结到下一段 |
| --- | --- | --- | --- |
| 初始 | 17,21,5 | 5,17,21 | 无 |
| 5 | 44 | 17,21,44 | 无 |
| 17 | 10 | 21,44 | 10 |
| 21 | 12 | 44 | 10,12 |
| 44 | 56 | 56 | 10,12 |
| 56 | 32 | 无，本段结束 | 10,12,32 |
| 新段输出 10 | 29 | 12,29,32 | 无 |
| 12 | 输入耗尽 | 29,32 | 无 |
| 29 | 无 | 32 | 无 |
| 32 | 无 | 无，结束 | 无 |

生成两段：`5,17,21,44,56` 和 `10,12,29,32`。

初始段长度不再受 w 严格限制，也不保证相等：输入本来升序时可生成一个长度 n 的段；严格逆序时一般每段约 w 条（末段可不足）。不能把“平均可能更长”背成“每段必为 2w”。

### 8.7.5 最佳归并树

#### 1. 为什么要优化归并顺序

初始段长短不一时，让长段反复参加多层归并会增加 I/O。应优先合并短段，使长段尽量靠近最终归并，构造 **k 叉哈夫曼树式的最佳归并树** 。

- 叶结点权值：初始段长度。
- 内部结点权值：本次合并后新段长度，即孩子权值之和。
- 叶到根边数：该段参加归并的次数。
- $WPL=\sum_i w_i l_i$：各段长度乘参与次数，也等于全部内部结点权值之和。

在每层完整读写的线性成本模型下：

$$
\text{归并读写量}=2WPL.
$$

**单位必须一致：** 权值是记录数，则 2WPL 是记录读写量；权值是块数且按该模型归并，则对应块 I/O。把记录数换算成实际磁盘块次数时，还要考虑每段尾块取整。此式通常不包含生成初始段阶段的成本。

#### 2. 构造步骤和例子

先补必要的零权虚段，再每次取最小的 k 个权值相加形成新权值，放回集合，直至只剩一个根。

书中 9 段长度：`9,30,12,18,3,17,2,6,24`，做三路最佳归并：

| 次序 | 取最小三段 | 新段长度 |
| --- | --- | --- |
| 1 | 2,3,6 | 11 |
| 2 | 9,11,12 | 32 |
| 3 | 17,18,24 | 59 |
| 4 | 30,32,59 | 121 |

$$
WPL=11+32+59+121=223,\qquad2WPL=446.
$$

若 9 段都固定参加两层归并，WPL 为 $2\times121=242$，读写量为 484，成本更高。

#### 3. 为什么要补虚段

严格 k 叉树只有度 0 和度 k 的结点。设叶数 r、内部结点数 I，按边数计：

$$
r+I-1=kI\quad\Longrightarrow\quad r=(k-1)I+1.
$$

因此必须满足 $(r-1)\bmod(k-1)=0$。令 $u=(r-1)\bmod(k-1)$，应补的虚段数为

$$
z=\begin{cases}
0,&u=0,\\
k-1-u,&u\ne0.
\end{cases}
$$

也可统一写作

$$
\boxed{z=((k-1)-(r-1)\bmod(k-1))\bmod(k-1)}.
$$

虚段权值为 0，不带来真实数据读写。它保证短段在合适位置先合并，不应把“不足 k 路的归并”随意留到最后。

删去前例长度 30 的段后，r=8、k=3，补 1 个零段：

```text
0+2+3 = 5
5+6+9 = 20
12+17+18 = 47
20+24+47 = 91
```

$WPL=5+20+47+91=163$，归并读写量 $2WPL=326$。

### 8.7.6 外部排序四个工具对照

| 工具 | 直接解决的问题 | 关键点 |
| --- | --- | --- |
| 多路平衡归并 | 减少归并趟数 | S=⌈logₖr⌉，路数受内存限制 |
| 败者树 | 减少多路选择的比较开销 | 败者留结点，冠军另存，只更新一条路径 |
| 置换—选择排序 | 生成更长初始段，减少段数 | 小于刚输出值的新记录冻结到下一段 |
| 最佳归并树 | 不等长段如何安排才能少读写 | 补零后做 k 叉哈夫曼合并，最小化 WPL |

1. **折半插入：** 对应每次都做折半定位的书中版本；另加有序预判后，最好时间可到 O(n)。总比较次数为 O(n log n)，平均总时间仍为 O(n²)。
2. **希尔：** 不脱离增量序列给唯一复杂度。本文代码增量为 n/2、n/4、…、1，已有序时为 Θ(n log n)，最坏常用界 O(n²)；书中约 O(n¹·³) 是概括性描述，不是通用界。
3. **堆排序：** 表中沿用考研教材最好、平均、最坏均记 O(n log n) 的口径。若讨论严格紧界，并允许大量重复关键字，本文带提前停止的下滤在全部相等时可只需 Θ(n)；“每次调整至多 O(log n)”不能推出每次必需 Θ(log n)。
4. **归并：** O(n) 空间对应数组版。链式合并可通过重连指针实现；递归链表归并仍有 O(log n) 栈，自底向上链表版可做到常数额外链接空间。
5. **计数：** 计入输出数组 B 时为 O(n+k)；不计输出，仅计算数数组时为 O(k)。本章及参考图采用计入输出的口径。
6. **基数：** 书中基于现有链结点，仅加桶头尾指针，所以 O(r)；参考图记 O(n+r)，适合常见数组辅助输出版本。必须配合实现区分。
