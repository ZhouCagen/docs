# 5.1 I/O 管理概述

## 5.1.1 I/O 设备

### 一、设备的分类

一个 I/O 设备通常可分为**设备本身**与**设备控制器**：前者执行实际输入、输出动作；后者接收主机命令，控制设备并协调数据传输。

| 分类依据     | 类型                 | 特点与例子                                                         |
| ------------ | -------------------- | ------------------------------------------------------------------ |
| 信息交换单位 | 块设备               | 以固定大小的数据块交换信息，可寻址，如磁盘；常采用 DMA             |
| 信息交换单位 | 字符设备             | 以字符或字节交换信息，通常不可寻址，如键盘、打印机；常采用中断方式 |
| 传输速率     | 低速、中速、高速设备 | 教材典型例子依次为键盘、打印机、磁盘；速率范围不作为固定界限死记   |
| 使用特性     | 人机交互设备         | 键盘、显示器、打印机等                                             |
| 使用特性     | 存储设备             | 磁盘、磁带、光盘等                                                 |
| 使用特性     | 网络通信设备         | 网卡、调制解调器等                                                 |
| 共享属性     | 独占设备             | 分配给一个进程后由其独占，使用完再释放，如打印机                   |
| 共享属性     | 共享设备             | 多个进程可在逻辑上并发使用，物理访问仍需协调，如磁盘               |
| 共享属性     | 虚拟设备             | 利用 SPOOLing 将一台独占设备虚拟成多台逻辑设备                     |

**分类依据彼此独立。** 磁盘既是块设备，也是存储设备和共享设备；共享不表示同一物理设备能在同一时刻执行任意多个操作。

### 二、I/O 接口（设备控制器）

这里的 **I/O 接口是硬件**，不要与后面的“应用程序 I/O 接口”混淆。

```text
CPU ── 数据线、地址线、控制线 ── 设备控制器 ── 数据、状态、控制信号 ── 设备
                                 │
                      寄存器 + I/O 逻辑 + 设备接口
```

控制器包含三部分：

1. **与 CPU 的接口**：数据线传输数据及寄存器中的命令、状态；地址线选择寄存器；控制线传送读、写等控制信号。
2. **与设备的接口**：连接一个或多个设备，交换数据、状态与控制信号。
3. **I/O 逻辑**：识别地址、解释命令并控制设备执行操作。

主要功能：**接收与识别命令、交换数据、标识和报告设备状态、地址识别、数据缓冲、差错控制**。

按不同角度，硬件接口还可分为并行 / 串行接口、程序查询 / 中断 / DMA 接口、可编程 / 不可编程接口，以及字符 / 块 / 网络设备接口。

### 三、I/O 端口

**I/O 端口是设备控制器中可被 CPU 访问的寄存器**，不是这里所说的整个控制器，也不是网络端口号。

| 寄存器     | 作用                           | 典型访问方向               |
| ---------- | ------------------------------ | -------------------------- |
| 数据寄存器 | 暂存输入或输出数据             | CPU 读输入数据、写输出数据 |
| 状态寄存器 | 保存忙、就绪、完成、故障等状态 | CPU 读取                   |
| 控制寄存器 | 保存操作命令、工作模式等       | CPU 写入                   |

#### 两种端口编址方式

| 对比项   | 独立编址（I/O 映射方式）       | 统一编址（内存映射方式，MMIO）       |
| -------- | ------------------------------ | ------------------------------------ |
| 地址空间 | I/O 与内存各有独立地址空间     | I/O 与内存使用同一地址空间           |
| 地址值   | 端口地址与内存地址数值可相同   | 同一地址空间中须区分分配范围         |
| 访问指令 | 专用 I/O 指令，如 `IN`、`OUT`  | 普通访存指令，如加载、存储           |
| 优点     | 不占内存地址空间，I/O 操作清晰 | 编程灵活，可利用统一的地址保护机制   |
| 代价     | 需专用指令及相应控制逻辑       | 占用部分内存地址空间，需进行地址译码 |

**“占用内存地址空间”不等于把设备寄存器放进 RAM，也不等于消耗同等容量的物理内存条。**

## 5.1.2 I/O 控制方式

演进主线：**程序直接控制 → 中断驱动 → DMA → 通道控制**，逐步减少 CPU 对 I/O 细节的干预。

### 一、程序直接控制（程序查询、轮询）

输入一个字 / 字节的典型过程：

```text
CPU 发出读命令 → 反复读取设备状态 → 就绪后读取数据寄存器
             → CPU 将数据写入内存 → 判断是否继续传输
```

- CPU 在等待设备时不断查询，处于**忙等**状态。
- 每个数据单元的搬运都由 CPU 执行，数据经过 CPU 寄存器。
- 实现简单，但 CPU 利用率低；教材模型中 CPU 与设备串行工作。

### 二、中断驱动

```text
CPU 启动设备 → CPU 执行其他任务
设备准备好数据 → 发出中断 → CPU 响应并执行中断处理程序
             → CPU 搬运数据、处理状态 → 恢复被中断的执行现场
```

- 等待设备准备期间，CPU 可执行其他任务，避免持续轮询。
- 教材基本模型按字 / 字节中断，**实际数据搬运仍经过 CPU**。
- 每次中断有保存现场、执行处理程序、恢复现场的开销；高速、批量传输时中断过于频繁。

**中断处理程序由 CPU 执行。** 设备控制器发出的是中断请求，不是替 CPU 执行处理程序。

### 三、DMA（直接存储器存取）

核心：**由 DMA 控制器组织设备与内存之间的数据传输，数据不经过 CPU 通用寄存器中转。**

一次 DMA 请求通常面向一块数据，但控制器在总线上仍可按字等较小单位逐次传送。

#### 1. 主要寄存器

| 寄存器 | 含义              | 作用                           |
| ------ | ----------------- | ------------------------------ |
| CR     | 命令 / 状态寄存器 | 保存传送命令、方向及相关状态   |
| MAR    | 内存地址寄存器    | 保存下一次传送所访问的内存地址 |
| DR     | 数据寄存器        | 暂存传送中的数据               |
| DC     | 数据计数器        | 记录剩余待传送的字 / 字节数    |

#### 2. 工作过程

1. **预处理**：CPU 设置传送方向、内存起始地址、传送长度等参数，启动 DMA。
2. **数据传送**：DMA 取得总线使用权，直接在设备与内存之间搬运数据，并更新地址和计数。
3. **后处理**：一块数据传送结束后，以中断通知 CPU；CPU 检查状态并作后续处理。

**DMA 不是完全不需要 CPU，而是不需要 CPU 逐字搬运。** CPU 主要参与开始和结束阶段；DMA 与 CPU 争用内存 / 总线时，CPU 的访存可能受到影响。

### 四、通道控制

通道是专门负责 I/O 的处理部件，可以执行存放在主存中的**通道程序**。

- CPU 指明设备、通道程序位置等并启动通道。
- 通道执行一组通道指令，组织多个数据块及多个设备的 I/O 操作。
- 完成后通知 CPU，进一步减少 CPU 干预。

**DMA 按 CPU 预设参数完成数据块传送；通道能执行通道程序，组织更复杂的一组 I/O 操作。**

### 五、四种方式对比

| 方式         | 谁检查 / 报告状态  | 谁组织实际搬运 | CPU 干预粒度（教材模型） | 主要问题或特点           |
| ------------ | ------------------ | -------------- | ------------------------ | ------------------------ |
| 程序直接控制 | CPU 不断轮询       | CPU            | 每个字 / 字节            | 忙等，CPU 开销大         |
| 中断驱动     | 设备中断通知 CPU   | CPU            | 每个字 / 字节            | 等待可并行，中断开销较大 |
| DMA          | DMA 完成后通知 CPU | DMA 控制器     | 数据块                   | 不经 CPU 寄存器中转      |
| 通道控制     | 通道完成后通知 CPU | 通道及控制器   | 一组 I/O 操作            | 可执行通道程序           |

#### 中断开销计算

若线路传输速率为 $R$ bit/s，每字符在线路上占 $k$ bit，每字符产生一次中断，每次中断耗时 $t$ 秒，则：

$$
\text{每秒中断次数}=\frac{R}{k},\qquad
\text{CPU 时间占比}=\frac{R}{k}\,t
$$

教材例：$R=56000$ bit/s，每字符含起止位共 10 bit，$t=0.1$ ms：

$$
\frac{56000}{10}\times0.0001=0.56=56\%
$$

**先统一秒与毫秒；字符的有效数据位数不一定等于线路实际传送位数。**

## 5.1.3 I/O 软件层次结构

### 一、四层软件与硬件

| 从上到下           | 主要职责                     | 典型关键词                                       |
| ------------------ | ---------------------------- | ------------------------------------------------ |
| 用户层 I/O 软件    | 提供库函数，格式化输入输出等 | `printf`、`scanf`、用户缓冲、SPOOLing 服务       |
| 设备独立性软件     | 实现各类设备的公共管理功能   | 统一接口、逻辑名映射、分配回收、缓冲、统一逻辑块 |
| 设备驱动程序       | 将抽象请求转成特定设备的操作 | 检查状态、设置寄存器、启动设备                   |
| 中断处理程序       | 处理完成 / 异常通知          | 保存与恢复现场、检查结果、唤醒等待进程           |
| 硬件（不算软件层） | 执行实际 I/O                 | 控制器、设备                                     |

```text
I/O 请求：用户层 → 设备独立性软件 → 驱动程序 → 硬件
完成通知：硬件中断 → 中断处理程序 → 上层完成处理 → 用户进程
```

分层的好处：**隐藏实现细节，提高可移植性、可维护性和扩展性**。各层职责是教材抽象模型，实际系统中部分功能会交叉，驱动也可包含中断处理例程。

### 二、设备独立性

应用程序使用**逻辑设备名**提出请求，系统将它映射为物理设备并定位驱动程序。

- 更换物理设备时，尽量不修改应用程序。
- 便于 I/O 重定向，例如将标准输出从终端改为文件。
- 统一完成设备分配、保护、缓冲和差错处理等公共工作。

### 三、设备驱动程序

典型流程：**解析抽象请求 → 检查合法性 → 检查设备状态 → 设置参数 → 启动设备 → 配合中断处理完成请求**。

驱动与设备硬件及控制方式密切相关。例如，教材磁盘模型中可将逻辑块号转换为柱面号、磁头号、扇区号；采用逻辑块寻址的控制器也可在内部完成映射。

### 四、中断处理程序

1. CPU 在允许响应中断时转入相应入口。
2. 保存必要的执行现场；硬件与软件分别承担部分保存工作。
3. 识别中断来源，读取状态，处理数据、完成或错误信息。
4. 确认 / 清除中断，必要时唤醒等待该 I/O 的进程。
5. 恢复现场，中断返回。

驱动初始化时需注册相应的中断处理例程；停用时撤销注册。中断处理应尽量简短，不能把可能睡眠的普通操作随意放进中断上下文。

**“被中断的进程”与“等待该 I/O 的进程”不一定是同一个。唤醒只使进程进入就绪态，不代表立即得到 CPU。**

### 五、一次输出请求如何经过各层

以需要实际输出的 `printf()` 为例：

```text
用户程序调用 printf（用户态，格式化并使用库缓冲）
    → 必要时调用 write 的系统调用封装
    → 执行陷入指令，进入内核态
    → 内核检查参数、解析设备、完成公共处理
    → 驱动设置控制器，启动输出
    → 设备完成后发出中断，内核处理完成状态
    → 满足返回条件后，系统调用返回用户态
```

**库函数调用不一定每次触发系统调用；系统调用返回也不一定表示物理设备已经完成输出。** 是否等待取决于缓冲机制、设备类型及接口语义。教材中的 `int 0x80` 是特定体系结构示例，不是所有系统唯一的陷入方式。

## 5.1.4 应用程序 I/O 接口

### 一、三类设备接口

| 接口         | 特点                                     | 典型操作                           |
| ------------ | ---------------------------------------- | ---------------------------------- |
| 字符设备接口 | 顺序存取字符，通常不可寻址               | `get`、`put`，以及设备特定控制操作 |
| 块设备接口   | 以块存取，可定位块地址；隐藏底层物理结构 | `read`、`write`、`seek`            |
| 网络设备接口 | 建立通信端点并收发数据                   | Socket（套接字）相关操作           |

打开、关闭及 `ioctl` 一类控制接口可用于设备管理；上表表示接口的抽象能力，不要求所有系统使用完全相同的函数名。

### 二、阻塞 I/O 与非阻塞 I/O

| 对比项           | 阻塞 I/O                       | 非阻塞 I/O                               |
| ---------------- | ------------------------------ | ---------------------------------------- |
| 请求暂时不能满足 | 调用进程进入等待状态           | 立即返回暂时不可用等结果                 |
| 进程能否继续执行 | 要等满足返回条件并重新获得 CPU | 可以继续执行其他代码并稍后重试           |
| 优点             | 编程直观                       | 便于处理多个任务、提高响应性             |
| 代价             | 调用线程等待                   | 反复轮询可能浪费 CPU，需合理组织等待机制 |

**阻塞的是调用进程 / 线程，不是整台机器的 CPU。** 多道程序系统中，CPU 可以调度其他就绪进程。

**非阻塞不等于异步完成。** “暂时不可用后立即返回”与“提交请求后由系统在完成时通知”是不同概念。

## 易混点速记

- **控制器是硬件，驱动程序是软件，端口是控制器中的可访问寄存器。**
- **中断方式避免忙等；DMA 进一步避免 CPU 逐字搬运。**
- **设备独立性软件处理共性，驱动程序处理设备特性。**
- **系统调用通过陷入进入内核；I/O 完成通常通过外部中断通知。**
- **进程被唤醒：阻塞 → 就绪；被调度运行：就绪 → 运行。**
- **控制方式与阻塞方式是两个维度**：采用 DMA 的请求也可以让调用进程阻塞等待。
