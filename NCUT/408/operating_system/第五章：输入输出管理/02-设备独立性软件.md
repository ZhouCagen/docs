# 5.2 设备独立性软件

## 5.2.1 设备独立性软件的功能

设备独立性软件又称**设备无关软件**，位于设备驱动程序之上，承担各类设备的公共操作，向上提供统一、抽象的 I/O 接口。

| 公共功能             | 具体含义                                                 |
| -------------------- | -------------------------------------------------------- |
| 统一的驱动程序接口   | 各驱动遵循约定接口，使上层能用统一方式调用不同设备       |
| 缓冲管理             | 设置单缓冲、双缓冲、循环缓冲、缓冲池，协调速度与数据粒度 |
| 差错控制             | 处理驱动无法解决的错误，统一向上报告结果                 |
| 独占设备的分配与回收 | 管理设备占用、等待队列及释放后的唤醒                     |
| 统一逻辑数据块       | 屏蔽不同设备的物理数据单位及块大小差异                   |

还包括逻辑设备名到物理设备的映射、访问保护等工作。**设备无关不表示不管理设备，而表示其处理方法不依赖某一具体硬件。**

差错处理通常分层完成：暂时性错误可由底层重试；持续失败再向上报告。坏块等问题可通过标记或重映射绕过，不能认为所有错误都由设备无关层独自处理。

## 5.2.2 高速缓存与缓冲区

### 一、磁盘高速缓存（Disk Cache）

利用**内存空间**保存近期访问的磁盘块内容。再次访问命中时，可减少实际读盘次数。

- 可开辟固定大小的专用内存区。
- 也可利用空闲内存构成动态缓存，与内存管理协调使用。
- 此处指操作系统管理的磁盘缓存，**不是 CPU 与主存之间的硬件 Cache**。

### 二、为什么设置缓冲区

1. 缓和 CPU 与 I/O 设备之间的速度差异。
2. 减少中断频率，放宽中断响应时间要求。
3. 匹配两端的数据交换单位，如按字符产生、按块传输。
4. 提高 CPU 与设备的并行程度。

缓冲可用硬件寄存器实现，也可在内存中开辟区域；下面讨论**内存缓冲区**。

### 三、单缓冲（计算重点）

#### 1. 模型与变量

```text
I/O 设备 ── 输入 T ──→ 系统缓冲区 ── 传送 M ──→ 用户工作区 ── 处理 C
```

- $T$：设备向系统缓冲区输入一块数据的时间。
- $M$：将该块从系统缓冲区搬到用户工作区的时间。
- $C$：CPU 处理工作区内一块数据的时间。

教材模型假定：**整块输入完成后才能搬运；同一缓冲区的填入与取出互斥；只有一个用户工作区。**

#### 2. 哪些阶段能重叠

- 搬运 $M_i$ 时，系统缓冲区尚未释放，不能向它输入下一块。
- 搬运完成后，CPU 处理当前块 $C_i$，同时设备输入下一块 $T_{i+1}$。
- 下一次搬运必须等上述两项都完成，既要有完整数据，又要工作区空闲。

因此，连续处理时每块的**稳态周期**为：

$$
\boxed{P_{\text{单}}=\max(T,C)+M}
$$

| 条件     | 稳态周期 | 主要限制     |
| -------- | -------- | ------------ |
| $T\ge C$ | $T+M$    | 设备输入较慢 |
| $T<C$    | $C+M$    | CPU 处理较慢 |

**单缓冲仍能让“下一块输入”与“当前块处理”并行，不能直接把每块周期写成 $T+M+C$。**

### 四、双缓冲（计算重点）

设置两个系统缓冲区交替使用：设备填充其中一个时，系统可以从另一个取出数据并处理。

```text
设备填充缓冲区 1 ──→ 切换到缓冲区 2 ──→ 再切回缓冲区 1
                       同时搬运并处理前一个缓冲区中的数据
```

在上述教材模型中，**输入时间 $T$ 可与搬运加处理时间 $M+C$ 重叠**：

$$
\boxed{P_{\text{双}}=\max(T,M+C)}
$$

| 条件       | 稳态周期 | 主要限制                   |
| ---------- | -------- | -------------------------- |
| $T\ge M+C$ | $T$      | 输入慢，CPU 可能等待       |
| $T<M+C$    | $M+C$    | 消费慢，设备可能等空缓冲区 |

**双缓冲不能保证速度翻倍，也不能消除设备与 CPU 的全部等待。** 它使更多阶段重叠，系统吞吐率仍受慢的一端限制。

教材双机通信模型中，若要同时发送和接收，每台机器需分别有发送缓冲区和接收缓冲区；只有一个互斥使用的缓冲区时不能同时收发。

### 五、连续处理 n 块的总时间

若开始时缓冲区、工作区均为空，从首块开始输入计时，到第 $n$ 块处理完成结束，且 $n\ge1$，则在上述模型下：

$$
\boxed{t_{\text{单}}=T+M+C+(n-1)[\max(T,C)+M]}
$$

$$
\boxed{t_{\text{双}}=T+M+C+(n-1)\max(T,M+C)}
$$

理解：**首块先走完 $T+M+C$，此后按稳态周期不断完成新块。**

例：$T=10$ ms，$M=2$ ms，$C=6$ ms，连续处理 5 块：

| 方式   | 首块完成时间   | 稳态周期             | 5 块总时间           |
| ------ | -------------- | -------------------- | -------------------- |
| 单缓冲 | $10+2+6=18$ ms | $\max(10,6)+2=12$ ms | $18+4\times12=66$ ms |
| 双缓冲 | $18$ ms        | $\max(10,2+6)=10$ ms | $18+4\times10=58$ ms |

**题目若预先装满缓冲区，或只问最后一块输入完成的时刻，起止条件就变了，应画时间线重新分析。** 不能不看条件直接套 $n\times P$。

### 六、循环缓冲

将多个大小相等的缓冲区连成循环队列，输入进程和计算进程分别推进指针。

- `in`：指向下一个待填充的空缓冲区。
- `out`：指向下一个待取出的满缓冲区。
- 输入完成后，空缓冲变为满缓冲；取完后，满缓冲变为空缓冲。

| 情况           | 原因                        | 谁等待             |
| -------------- | --------------------------- | ------------------ |
| 缓冲区全部装满 | 输入快、处理慢，受计算限制  | 输入进程等待空缓冲 |
| 缓冲区全部为空 | 处理快、输入慢，受 I/O 限制 | 计算进程等待数据   |

本质是**生产者—消费者问题**，需保证队列操作互斥及满 / 空状态同步。仅看到 `in == out` 无法直接区分满和空，还需计数、状态位或保留空位等约定。

多缓冲可以吸收短时间的速度波动，但**有限缓冲不能永久弥补生产速率持续大于消费速率的问题**。

### 七、缓冲池

缓冲池由系统统一管理，供多个进程共享。空闲或等待处理的缓冲区按状态组织为三个队列：

| 队列       | 内容                             |
| ---------- | -------------------------------- |
| 空缓冲队列 | 可用于装入新数据的缓冲区         |
| 输入队列   | 已装满输入数据，等待计算进程取用 |
| 输出队列   | 已装满输出数据，等待输出设备取用 |

缓冲区被取出使用时，可担任四种工作角色：

| 操作     | 工作缓冲区 | 从哪取     | 做什么                 | 完成后放到哪 |
| -------- | ---------- | ---------- | ---------------------- | ------------ |
| 收容输入 | `hin`      | 空缓冲队列 | 输入设备写入数据       | 输入队列     |
| 提取输入 | `sin`      | 输入队列   | 计算进程读取数据       | 空缓冲队列   |
| 收容输出 | `hout`     | 空缓冲队列 | 计算进程写入输出数据   | 输出队列     |
| 提取输出 | `sout`     | 输出队列   | 输出进程取数据送往设备 | 空缓冲队列   |

**三个队列、四种工作角色**，不是“四个队列”，也不是整个池只有四块缓冲区。

### 八、高速缓存与缓冲区的区别

| 对比项   | 高速缓存 Cache                               | 缓冲区 Buffer                        |
| -------- | -------------------------------------------- | ------------------------------------ |
| 主要目的 | 利用重复访问，减少慢设备访问                 | 暂存传输中的数据，协调两端速度和粒度 |
| 数据角色 | 慢设备内容的缓存副本；修改后可暂时形成脏数据 | 生产者与消费者之间正在传递的数据     |
| 使用方式 | 查找命中后复用，必要时替换                   | 写入、取出、释放、再次利用           |
| 共同点   | 都可使用内存，都有助于改善 I/O 性能          | 实际实现可与缓存结合                 |

**看目的区分：为复用而留存是缓存，为协调传输而暂存是缓冲。**

## 5.2.3 设备分配与回收

### 一、分配的目标与考虑因素

目标：在提高设备利用率的同时，避免因不当分配产生死锁。

需考虑：**设备固有属性、分配算法、分配安全性、设备独立性**。

- 独占设备：一段时间内只分配给一个进程。
- 共享设备：允许多个进程逻辑上并发访问，通过调度协调。
- 虚拟设备：为进程分配逻辑使用条件，例如输出井空间与请求表。
- 常见分配算法：**先来先服务 FCFS、最高优先级优先**。

### 二、四类设备分配数据结构

硬件从属关系：**通道 → 控制器 → 设备**。

| 表   | 全称         | 数量与作用           | 主要信息                                               |
| ---- | ------------ | -------------------- | ------------------------------------------------------ |
| DCT  | 设备控制表   | 每个设备一张         | 类型、标识、忙闲、控制器表指针、重试参数、设备等待队列 |
| COCT | 控制器控制表 | 每个控制器一张       | 控制器标识、忙闲、通道表指针、控制器等待队列           |
| CHCT | 通道控制表   | 每个通道一张         | 通道标识、忙闲、下属控制器信息、通道等待队列           |
| SDT  | 系统设备表   | 全系统一张全局索引表 | 各设备类型、标识、DCT 指针、驱动入口等                 |

```text
物理设备名 → SDT → DCT → COCT → CHCT
                     设备   控制器   通道
```

**DCT 描述单个设备；SDT 汇总全系统设备；LUT 负责逻辑名映射。**

### 三、分配安全性

| 方式           | 教材中的行为                                             | 特点                                                           |
| -------------- | -------------------------------------------------------- | -------------------------------------------------------------- |
| 安全分配方式   | 发出 I/O 请求后阻塞，完成前不再请求其他资源              | 限制继续占有并请求的行为，降低死锁风险，但限制该进程的并行活动 |
| 不安全分配方式 | 发出请求后仍可继续运行并请求其他设备；资源不可用时才等待 | 并行性较高，但可能形成循环等待                                 |

这里的“安全分配方式”是教材的特定设备分配策略，**不要与银行家算法中的安全状态直接混为一谈**。单个进程阻塞，也不表示系统中所有进程均停止运行。

### 四、分配步骤

以教材的独占设备与通道模型为例：

1. **分配设备**：按设备名查 SDT、DCT；忙则排入设备等待队列，空闲则分配。
2. **分配控制器**：由 DCT 找 COCT；忙则排入控制器等待队列，空闲则分配。
3. **分配通道**：由 COCT 找 CHCT；忙则排入通道等待队列，空闲则分配。
4. 三者均可用后，才具备启动该次 I/O 的完整通路。

**设备空闲不等于 I/O 立刻可执行，还要看控制器和通道是否可用。**

回收时更新相应状态：有等待进程则按策略分配并唤醒；没有等待者则标为空闲。设备回收主要更新管理信息，不等于清除设备中保存的数据。

### 五、逻辑设备名与 LUT

为实现设备独立性，进程通过逻辑设备名请求设备，系统使用**逻辑设备表 LUT（Logical Unit Table）**进行映射。

典型表项：**逻辑设备名 + 物理设备名 + 驱动程序入口地址**。

```text
应用程序使用逻辑设备名
    → LUT 定位实际物理设备与驱动
    → SDT / DCT 等检查并管理设备资源
    → 调用驱动完成操作
```

| 设置方式             | 特点                                       |
| -------------------- | ------------------------------------------ |
| 全系统共用一张 LUT   | 教材模型要求逻辑名在该全局表中唯一         |
| 每个用户设置一张 LUT | 不同用户可使用相同逻辑名，映射到各自的设备 |

若请求允许使用任一同类设备，系统可从同类设备中选择可用者，而不是只等待某一台固定设备。这提高了分配灵活性，也支持设备替换与 I/O 重定向。

## 5.2.4 SPOOLing 技术（假脱机技术）

### 一、基本思想

**利用磁盘作为大容量缓冲，由输入 / 输出进程模拟脱机 I/O，将独占设备改造成可供多个进程逻辑共享的虚拟设备。**

- 早期脱机 I/O：借助独立外围机完成低速输入、输出。
- 假脱机：仍由主机控制，以软件进程和磁盘空间模拟外围机的功能。
- 依赖多道程序并发运行，使计算与低速 I/O 能重叠。

### 二、组成与数据流

| 组成                   | 所在位置 | 作用                                        |
| ---------------------- | -------- | ------------------------------------------- |
| 输入井、输出井         | **磁盘** | 保存输入、输出数据，按作业 / 请求组织井文件 |
| 输入缓冲区、输出缓冲区 | **内存** | 暂存设备与磁盘井之间传送的数据              |
| 输入进程、输出进程     | 软件     | 模拟外围控制机，负责输入、输出传送          |
| 井管理程序             | 软件     | 管理作业与磁盘井之间的数据交换              |

```text
输入：输入设备 → 内存输入缓冲区 → 磁盘输入井 → 用户程序
输出：用户程序 → 磁盘输出井 → 内存输出缓冲区 → 输出设备
```

**井在磁盘，缓冲区在内存；“假脱机”仍在主机控制之下。**

### 三、共享打印机的实现

1. 用户提交打印请求，系统在输出井分配空间，保存待打印数据。
2. 建立打印请求表，记录用户、数据位置等，并挂入打印队列。
3. 请求被接收后，用户进程可以继续执行，不必一直等待纸张打印完成。
4. 后台打印进程在打印机空闲时取出请求，将数据从输出井经缓冲区送往打印机。
5. 完成后处理下一项；队列为空则等待新请求。

**分配给用户的是输出井空间和请求表等逻辑资源，用户进程不直接独占物理打印机。** 物理打印机仍逐项工作，不能同时在一张纸上执行多个独立打印任务。

### 四、特点

- 将低速设备操作转化为对磁盘井的存取，减少用户等待。
- 将独占设备改造成逻辑上共享的设备，实现设备虚拟化。
- 以磁盘空间换取计算与 I/O 重叠的机会，提高整体效率。

**SPOOLing 不会提高打印机本身的机械打印速度，也不等于内存中的普通单 / 双缓冲。**

## 5.2.5 设备驱动程序接口

驱动是上层 I/O 软件与设备控制器之间的软件桥梁。

主要职责：**接收命令和参数、将逻辑请求转成设备操作、检查合法性和状态、设置工作方式、启动设备、配合中断及错误处理**。

特点：

- 与设备类型、控制器特性及 I/O 控制方式密切相关。
- 封装硬件细节，上层只需使用约定接口。
- 需要考虑并发访问和共享状态保护；可重入不等于允许无保护地同时修改设备状态。
- 部分底层功能可由固件实现。

系统通过统一驱动接口、逻辑名映射及访问权限检查，使不同驱动可被统一管理。应用程序一般不能绕过内核任意操作设备寄存器。

## 5.2.6 一次键盘输入的完整过程

以 `char d; scanf("%c", &d);` 为例，假设库缓冲与内核缓冲均无可用字符，采用阻塞读取和中断驱动：

1. `scanf` 检查用户空间的库缓冲，无数据时通过 `read` 请求输入。
2. 准备文件描述符 `fd`、用户缓冲区地址 `buf`、最大字节数 `count` 等参数。
3. 执行陷入指令，从用户态进入内核态，执行系统调用服务例程。
4. 读取条件尚未满足，进程 P 阻塞，CPU 调度其他就绪进程。
5. 用户按键，键盘控制器收到数据并向 CPU 发出中断请求。
6. CPU 执行相应中断处理例程，读取设备数据并放入内核缓冲区。
7. 满足读取条件后唤醒 P：**阻塞 → 就绪**。
8. P 被重新调度后，将内核缓冲中的数据复制到用户缓冲区，系统调用返回。
9. `scanf` 在用户态解释数据，并将字符存入 `d`。

```text
键盘 → 控制器数据端口 → 内核缓冲区 → 用户缓冲区 → 变量 d
           驱动 / 中断处理        系统调用        库函数
```

这是教材简化流程：实际终端是否需要回车等条件取决于输入模式。**若用户缓冲已有数据，库函数可能直接完成；若内核缓冲已有数据，系统调用也可能无需阻塞。**

## 易混点速记

- **单缓冲：$\max(T,C)+M$；双缓冲：$\max(T,M+C)$。** 总时间还要考虑起始、结束阶段。
- **缓冲池：三个队列、四种工作角色。**
- **分配顺序：设备 → 控制器 → 通道。**
- **LUT 管映射，DCT 管单设备，SDT 管全局索引。**
- **SPOOLing 的井在磁盘，缓冲区在内存，后台进程负责实际输出。**
- **中断到来不意味着等待进程立即运行；唤醒之后还要调度。**
