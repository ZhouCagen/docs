# 1.5 操作系统的引导

## 1. 什么是操作系统引导？

**操作系统引导（Boot）就是开机时，将操作系统装入内存并使其开始运行的过程。**

本节按传统的 **BIOS + MBR** 启动方式理解，并以 Windows 的启动管理器为例；UEFI 的启动流程有所不同。

## 2. 引导程序存放在哪里？

### 固件与 RAM

- **ROM BIOS**：BIOS 固件存放在非易失性存储器中，教材通常称为 ROM，其中包含启动所需的引导代码，即 ROM 引导程序／自举程序。
- **RAM**：用于装入从磁盘读取的引导代码，以及后续的操作系统内核等内容。

**开机后，CPU 先从规定的入口执行固件代码，再逐步加载磁盘上的引导程序。** BIOS 不需要先由操作系统启动。

### 磁盘上的引导信息

| 名称                                       | 位置                                | 主要内容或作用                                                               |
| ------------------------------------------ | ----------------------------------- | ---------------------------------------------------------------------------- |
| 主引导记录（MBR，Master Boot Record）      | 采用 MBR 分区方式的磁盘的第一个扇区 | 包含磁盘引导程序、分区表等信息                                               |
| 分区引导记录（PBR，Partition Boot Record） | 分区的起始位置                      | 负责找到“启动管理器”，包含分区引导代码等信息，用于继续查找、加载后续启动程序 |
| 启动管理器                                 | 启动所用分区的文件系统中            | 根据启动配置选择并启动操作系统加载程序                                       |

**MBR 对应整块磁盘，PBR 对应某个分区，不要混淆。**

教材若以 C 盘作为启动所用分区，可以记作“找到 C 盘，再读取其开头的 PBR”。但严格来说，引导代码根据分区表定位分区，**不是根据 C 盘盘符定位**；启动文件也可能位于单独的系统分区。

> 分区中还包含文件系统元数据、根目录和其他文件数据。“PBR → 根目录 → 其他内容”可以作为简化示意，但根目录并不一定紧接 PBR，具体布局由文件系统决定。

## 3. 传统 BIOS + MBR 引导过程

1. **CPU 从特定地址开始取指令**：上电或复位后，CPU 从硬件规定的入口地址（复位向量）开始取指执行；该入口映射到固件代码，进而执行 ROM 中的 BIOS 启动程序。先完成硬件自检和必要的初始化，再选择启动设备，继续引导操作系统。
2. **将 MBR 读入 RAM**：CPU 执行 BIOS 引导代码，把启动磁盘的第一块（此处指第一个扇区），即主引导记录，读入内存。
3. **执行磁盘引导程序，扫描分区表**：CPU 执行 MBR 中的主引导代码，扫描分区表，找到标记为活动的主分区。
4. **读取并执行 PBR**：将该分区起始位置的分区引导记录读入 RAM，转去执行其中的引导代码。
5. **查找并加载启动管理器**：CPU 执行 PBR 中的分区引导代码，按文件系统信息查找启动管理程序。在本节的 Windows BIOS 启动示例中，从启动所用分区的根目录找到 `BOOTMGR`，将其装入主存 RAM，再由 CPU 执行。
6. **加载操作系统**：启动管理器根据启动配置启动相应的操作系统加载程序，由其装入内核等必要内容，并将控制权交给内核。
7. **内核开始运行**：初始化系统、启动必要服务，逐步建立可供用户使用的运行环境。

- **特定地址不等于 RAM 中预先装好了操作系统**：教材所说的“从特定主存地址开始取指”，重点是 CPU 有硬件规定的启动入口，此时执行的是固件中的代码。
- **硬件自检是开机过程的一部分**：“先自检，再开机”更准确地说是“先自检，再继续加载和启动操作系统”。
- **活动分区是被标记为用于启动的主分区**，不是所有主分区都是活动分区，也不一定就是安装操作系统文件的分区；启动文件和操作系统文件可以位于不同分区。
- **启动管理器不等于完整的操作系统初始化程序**：它负责选择、启动操作系统加载程序；后续还需要加载内核、执行内核初始化、启动系统服务等，共同完成“开机”的一系列动作。

**记忆链条：BIOS → MBR → PBR → 启动管理器 → 操作系统加载程序 → 内核。**

**PBR 之后的细化过程：执行分区引导代码 → 在分区根目录找到启动管理程序 → 装入主存 RAM → CPU 执行启动管理程序。**

注意：**主存负责存放程序和数据，CPU 负责执行指令。** “装入主存后运行”是指 CPU 执行已装入主存的程序，不是主存自己执行程序。

**核心：前一级引导代码找到并加载后一级，再把 CPU 控制权交给它，最终让操作系统内核运行起来。**
