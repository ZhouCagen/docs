# 1.3 操作系统的运行环境

## 1.3.1 操作系统内核

### 1. CPU 的两种状态

| 状态           | 运行的程序       | 可执行的指令         |
| -------------- | ---------------- | -------------------- |
| 内核态（管态） | 操作系统内核程序 | 特权指令和非特权指令 |
| 用户态（目态） | 应用程序         | 只能执行非特权指令   |

**程序状态字寄存器 PSW** 中的状态位用于标识 CPU 当前状态。

> 1、0 分别代表哪种状态，取决于具体机器。若教材规定 1 为内核态、0 为用户态，按教材记忆。

### 2. 特权指令与非特权指令

- **特权指令**：只能在内核态执行，涉及系统资源管理等操作。
  - 例如：开／关中断、设置内存管理寄存器等。
  - 用户态试图执行特权指令，会被 CPU 阻止并触发异常。
- **非特权指令**：内核态和用户态都能执行。
  - 例如：普通运算、跳转、数据传送等指令。
  - 非特权指令也不能越权访问受保护的内存。

**陷入指令是非特权指令**，允许应用程序主动请求操作系统服务。

### 3. 开机与程序运行

1. 开机启动阶段，CPU 在内核态执行操作系统初始化等工作。
2. 进入桌面后，CPU 已经随着程序执行，在用户态和内核态之间切换。
3. 用户打开一个程序，内核处理启动请求，创建进程、准备运行环境。
4. 内核通过中断返回／异常返回等特权指令，恢复或设置 PC、PSW 等状态，转入用户态执行应用程序。

例：程序中被黑客植入了一条特权指令

1. CPU 在用户态执行这个程序的普通指令。
2. 执行到特权指令时，CPU 硬件检查权限，发现当前是用户态。
3. CPU 阻止该特权指令执行，触发异常（内中断）。
4. 硬件自动将 CPU 切换到内核态，转去执行内核规定的异常处理程序。
5. 操作系统处理违规，通常会终止该程序，之后调度其他程序运行；执行用户程序时回到用户态。

> 进入内核态后，执行的是内核的异常处理代码，
> 不是继续替黑客执行那条特权指令。

### 4. 两种状态的切换

| 切换方向        | 实现方式                                                         |
| --------------- | ---------------------------------------------------------------- |
| 内核态 → 用户态 | 内核执行特权指令，恢复或设置 PSW 等状态，主动将 CPU 交给用户程序 |
| 用户态 → 内核态 | 由中断或异常引发，硬件自动完成状态切换，转去执行内核代码         |

**用户态进入内核态的常见情况：**

- **外中断**：时钟中断、键盘等设备中断。
- **异常**：缺页、用户态执行特权指令等。
- **陷入**：应用程序执行陷入指令，请求系统调用，属于异常的一种。

**核心：进入内核态，是把 CPU 交给内核代码，不是把特权交给应用程序。**

## 1.3.2 中断和异常

### 1. 中断的作用

**“中断”是让操作系统内核夺回 CPU 使用权的唯一途径。**

这里的“中断”指广义中断，包括内中断和外中断。当 CPU 正在用户态运行应用程序时，中断或异常使 CPU 转入内核态，执行相应的内核处理程序。

### 2. 内中断与外中断

| 对比项           | 内中断                       | 外中断                  |
| ---------------- | ---------------------------- | ----------------------- |
| 与当前指令的关系 | 与当前执行的指令有关         | 与当前执行的指令无关    |
| 信号来源         | CPU 内部                     | CPU 外部                |
| 通常的名称       | 异常（Exception）            | 中断（Interrupt，狭义） |
| 例子             | 非法指令、缺页、执行陷入指令 | 时钟中断、I/O 中断      |

**内中断的例子：**

- 当前指令非法，或应用程序在用户态执行特权指令，会引发异常。
- 应用程序执行**陷入指令**，主动请求操作系统内核服务，会引发内中断。
- **系统调用通过陷入指令等机制进入内核**；系统调用是请求内核服务的过程，不能直接等同于一条陷入指令。
- **陷入指令是非特权指令**，可以在用户态执行。

**外中断的例子：**

- **时钟中断**：由时钟部件发来的中断信号，操作系统可据此进行计时、进程调度等。
- **I/O 中断**：由 I/O 设备或其控制器发来的中断信号，例如通知 CPU 输入输出操作已完成。

> **CPU 每执行完一条指令，都会检查是否有外部中断信号**

### 3. 异常的分类

异常包括**陷入（Trap）、故障（Fault）、终止（Abort）**。

| 类型          | 产生原因                           | 处理后能否继续执行                                   | 典型例子       |
| ------------- | ---------------------------------- | ---------------------------------------------------- | -------------- |
| 陷入（Trap）  | 程序主动执行陷入指令，请求内核服务 | 服务完成后，通常返回陷入指令的下一条指令             | 系统调用       |
| 故障（Fault） | 当前指令遇到错误条件               | 若内核成功修复，通常重新执行引发故障的指令           | 缺页故障       |
| 终止（Abort） | 严重、通常不可恢复的错误           | 通常无法恢复原程序的执行，可能终止程序或导致系统停止 | 严重硬件错误等 |

**缺页故障的处理过程：**

1. 当前指令需要访问的页面不在内存中，引发缺页故障。
2. CPU 转入内核，执行缺页处理程序。
3. 若访问合法且页面能够调入，内核将所需页面调入内存。
4. 进程恢复运行时，重新执行刚才引发缺页的指令。

> **易混点：程序被终止，不代表异常类型一定是 Abort。**

### 4. 中断机制的基本原理

**不同类型的中断信号，需要由相应的中断处理程序处理。**

**中断处理程序属于操作系统内核程序，必须在内核态运行。** 若中断发生前 CPU 处于用户态，硬件会自动将 CPU 切换到内核态，再执行中断处理程序；若原本就在内核态，则保持内核态。

1. CPU 接收到可响应的中断，或执行指令时发生异常。
2. 根据中断或异常的类型，确定对应的**中断向量号**。
3. 根据中断向量号查询**中断向量表**，找到对应处理程序的入口地址。
4. 保存被中断程序的必要状态，转入内核态，执行相应的处理程序。
5. 处理结束后，根据处理结果恢复程序运行、调度其他程序，或终止无法继续运行的程序。

**记忆链条：中断类型 → 中断向量号 → 中断向量表 → 中断处理程序入口。**

## 1.3.3 系统调用

### 1. 系统调用的概念

**系统调用是操作系统提供给应用程序使用的接口。应用程序可以通过系统调用，请求获得操作系统内核的服务。**

普通应用程序既可以直接发起系统调用，也可以调用库函数，由库函数间接发起系统调用。

### 2. 应用程序、库函数、操作系统与硬件

从上到下，可以按以下层次理解：

| 层次 | 作用 |
| ---- | ---- |
| 应用程序 | 完成用户任务，可以调用库函数，也可以直接发起系统调用 |
| 编程语言的运行库／库函数 | 向应用程序提供函数，其中一部分封装了系统调用 |
| 操作系统 | 向上提供系统调用接口，由内核管理资源、提供服务 |
| 裸机（硬件） | CPU、内存、I/O 设备等，实际执行指令、存储数据和完成输入输出 |

这里的“编程语言层”更准确地说是**运行库或库函数层**。编程语言本身并不是每次执行时都必须经过的一层。

**库函数层可以省略。** 应用程序可以通过相应的机器指令直接发起系统调用，不一定要经过库函数封装。

| 库函数类型 | 例子 | 是否需要进入内核态 |
| ---------- | ---- | ------------------ |
| 不涉及系统调用 | 求绝对值的函数 | 计算本身可以完全在用户态完成 |
| 涉及系统调用 | 创建新文件的函数 | 请求内核创建文件时，需要通过系统调用进入内核态 |

**调用库函数，不等于一定发生系统调用。** 库函数本身通常在用户态执行，只有涉及内核服务的部分才通过系统调用进入内核。

### 3. 不涉及系统调用，是否就用不上操作系统？

**对于一段纯计算代码，CPU 可以直接在用户态执行它的机器指令，不需要每条指令都经过操作系统。** 例如求绝对值、加减运算等，通常不需要主动请求内核服务。

但在操作系统环境中，整个程序的运行仍依赖操作系统：

- 程序启动时，需要操作系统创建进程、装入程序、准备运行环境。
- 程序运行时，由操作系统调度 CPU，并提供内存管理和保护。
- 即使没有主动发起系统调用，也可能因为时钟中断、缺页异常等进入内核。
- 程序结束时，需要操作系统回收资源。

因此，**“这段计算不需要系统调用”不等于“整个程序不依赖操作系统”。**

> 编译器可以把源代码编译成机器指令，CPU 直接执行这些指令；操作系统负责管理程序运行所需的资源。专门为裸机编写的程序可以不依赖操作系统，但这与普通应用程序在操作系统中运行是不同的场景。

### 4. 系统调用的分类（按功能）

| 分类 | 主要功能举例 |
| ---- | ------------ |
| 设备管理 | 请求、释放设备，进行设备读写 |
| 文件管理 | 创建、删除、打开、关闭、读写文件 |
| 进程控制 | 创建、终止进程等 |
| 进程通信 | 在进程之间传递消息、交换数据等 |
| 内存管理 | 申请、释放内存映射等 |

**凡是涉及由内核管理的共享资源，且需要内核权限或协调的操作，都必须通过系统调用向内核提出服务请求。**

例如，应用程序不能绕过操作系统，随意操纵磁盘来创建文件。内核统一检查权限、协调资源使用，可以维护系统的稳定性和安全性。

> 这里强调的是需要内核管理的资源操作，并非每一次数据访问都需要系统调用。例如，已建立映射且允许访问的共享内存，可以在用户态直接读写。

### 5. 系统调用的执行过程

**传递系统调用参数 → 执行陷入指令（用户态）→ 执行相应的内核程序，处理系统调用（内核态）→ 返回应用程序（用户态）。**

1. **准备参数**：应用程序准备系统调用号及所需参数，用于说明请求哪种服务、处理哪些数据。
2. **执行陷入指令**：应用程序在用户态执行陷入指令，主动发出系统调用请求。
3. **进入内核态**：执行陷入指令引发内中断，硬件使 CPU 转入内核态，并进入相应的内核入口。
4. **处理系统调用**：内核根据系统调用号找到相应的服务程序，检查参数和权限，执行所请求的操作。
5. **返回应用程序**：处理完成后返回结果，恢复用户态执行；若请求需要等待，进程可能先阻塞，之后再恢复运行。

**注意：**

- **陷入指令是非特权指令，可以在用户态执行。**
- 在上述应用程序发起系统调用的过程中，**执行陷入指令、发出请求是在用户态**；执行该指令触发进入内核的过程。
- **对系统调用的响应和处理在内核态进行。**
- 中断向量用于定位相应的中断／异常入口，系统调用号用于进一步确定请求的内核服务，两者不要混淆。

**记忆：用户态提出请求，内核态提供服务。**
