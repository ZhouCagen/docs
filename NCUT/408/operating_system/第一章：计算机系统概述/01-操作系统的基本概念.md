# 1.1 操作系统的基本概念

## 1.1.1 操作系统的概念

**操作系统（OS）**是指控制和管理整个计算机系统的硬件和软件资源，合理地组织、调度计算机的工作和资源的分配，为用户和其他软件提供方便的接口和环境的程序集合。

操作系统是计算机系统中**最基本的系统软件**。

简单理解：

- **管理资源**：管理计算机的硬件和软件资源。
- **提供环境**：为程序提供运行环境。
- **提供接口**：充当用户、应用程序与计算机硬件之间的桥梁。

## 1.1.2 操作系统的功能和目标

### 一、操作系统作为计算机系统资源的管理者

主要目标：**安全、高效地管理和使用计算机资源**。

| 功能           | 主要内容                                         |
| -------------- | ------------------------------------------------ |
| **处理机管理** | 进程控制、进程同步与互斥、进程通信、处理机调度等 |
| **存储器管理** | 内存分配与回收、地址转换、存储保护、内存扩充等   |
| **文件管理**   | 文件存储空间管理、目录管理、文件读写与保护等     |
| **设备管理**   | 设备分配与回收、缓冲管理、设备驱动等             |

### 二、操作系统作为用户与计算机硬件系统之间的接口

主要目标：**方便用户使用计算机**。

#### 1. 用户接口

用户可以直接使用，包括**命令接口**和**图形用户接口**。

| 接口             | 别称           | 使用方式                                                               |
| ---------------- | -------------- | ---------------------------------------------------------------------- |
| **联机命令接口** | 交互式命令接口 | 用户输入一条命令，系统执行一条，用户根据结果继续输入命令               |
| **脱机命令接口** | 批处理命令接口 | 用户事先用作业控制语言写好一组命令，系统按照要求执行，无须用户逐条干预 |
| **图形用户接口** | GUI            | 用户通过窗口、图标、菜单、按钮等进行操作                               |

> **联机、脱机不是指是否联网，而是强调用户是否在作业执行过程中进行交互。**

#### 2. 程序接口

程序接口由一组**系统调用**组成，供程序请求操作系统服务。

- 用户不能像输入命令那样直接使用程序接口，而是通过程序代码**间接使用**。
- 程序通过系统调用请求操作系统提供服务，如读写文件、创建设备访问请求等。
- **系统调用又称广义指令**。

> 用户接口供人使用，程序接口供程序使用。
>
> “广义指令”不等于处理机指令集中的一条普通机器指令。

### 三、操作系统实现对计算机资源的扩充

操作系统在硬件基础上提供更方便、更强大的功能，实现对硬件机器的扩展。

- **裸机**：没有安装任何软件的计算机。
- **扩充机器**：覆盖了软件的机器，又称**虚拟机**。
- 操作系统在裸机之上提供资源管理和服务，使计算机更方便使用。

例如：保存文件时，用户使用文件名即可，无须直接控制磁盘的具体读写操作。

> 这里的“虚拟机”是“扩充机器”的广义概念，不专指运行另一套操作系统的虚拟机软件。

## 1.1.3 操作系统的特征

操作系统具有四个基本特征：

**并发、共享、虚拟、异步。**

其中，**并发和共享是两个最基本的特征，二者互为存在条件**。

### 一、并发

#### 1. 并发与并行

- **并发**：两个或多个事件在**同一时间间隔内**发生。
- **并行**：两个或多个事件在**同一时刻**发生。

| 比较项               | 并发                       | 并行                         |
| -------------------- | -------------------------- | ---------------------------- |
| 时间尺度             | 同一时间间隔               | 同一时刻                     |
| 是否要求真正同时执行 | 不要求                     | 要求                         |
| 典型例子             | 单核处理机交替执行多个程序 | 多个处理核心同时执行不同程序 |

#### 2. 操作系统的并发性

操作系统的并发性，是指计算机系统中“同时”运行着多个程序。

在单核处理机上：

- **宏观上同时运行**。
- **微观上交替执行**。

例如：一个处理机交替执行程序 A 和程序 B，在一段时间内两个程序都得到推进，但同一时刻只执行其中一个。

> **单核可以实现并发；多核可以实现并行。**
>
> 并发不排斥并行，多核系统中的并发程序也可能真正并行执行。

### 二、共享

**资源共享**：系统中的资源可供内存中多个并发执行的进程共同使用。

资源共享分为**互斥共享**和**同时共享**。

#### 1. 互斥共享

**在一段时间内，只允许一个进程访问该资源。**

- 当一个进程正在使用时，其他需要访问的进程必须等待。
- 这种资源称为**临界资源**。

例如：打印机。一个打印任务占用打印机时，另一个任务不能随意插入打印内容。

#### 2. 同时共享

**允许在一段时间内，由多个进程“同时”访问资源。**

- “同时”通常指宏观意义上的同时。
- 微观上，多个进程对资源的访问仍可能交替进行。

例如：多个进程在同一时间段内访问磁盘中的文件。

> **同时共享不一定意味着同一时刻真正同时访问。**

#### 3. 并发与共享的关系

**并发和共享互为存在条件。**

- **资源共享以程序的并发执行为前提**：有多个程序并发执行，才需要考虑它们共同使用资源的问题。
- **有效的资源共享是程序并发执行的基础**：系统需要合理分配资源、协调访问，才能支持多个程序正确地并发执行。

### 三、虚拟

**虚拟**：把一个物理上的实体变为若干个逻辑上的对应物。

- **物理实体**：实际存在的硬件资源。
- **逻辑对应物**：用户或程序感受到的资源。

实现虚拟主要采用**时分复用技术**和**空分复用技术**。

#### 1. 时分复用技术

通过让多个程序**分时、交替使用同一物理资源**，形成多个逻辑上的对应物。

典型例子：**虚拟处理机技术**。

- 实际上只有一个处理机。
- 处理机轮流执行多个进程。
- 每个进程都好像拥有自己的处理机。

#### 2. 空分复用技术

通过对空间资源的划分和复用，形成逻辑上的资源视图。

典型例子：**虚拟存储器技术**。

- 利用内存和外存，以及相应的地址转换、调入调出机制。
- 使程序感受到的逻辑存储空间可以大于实际物理内存。

> 教材通常把虚拟处理机作为时分复用的典型，把虚拟存储器作为空分复用的典型。
>
> 虚拟存储器并不是简单地把内存分区，也不会使实际物理内存容量增加。

#### 3. 虚拟设备技术

典型例子：**SPOOLing（假脱机）技术**。

以打印机为例：

1. 多个进程先把打印内容提交到磁盘缓冲区。
2. 系统保存并组织这些打印任务。
3. 再由系统按序送给打印机输出。

这样，就把一台独占设备改造成了可供多个进程共享的逻辑设备。

### 四、异步

**异步**：在多道程序环境下，由于资源有限，进程的执行走走停停，以不可预知的速度向前推进。

#### 1. 产生原因

- 多个进程并发执行。
- 处理机、内存、设备等资源有限。
- 进程可能因为等待资源或事件而暂停。
- 条件满足后再继续执行，因此执行速度和先后次序不固定。

例如：进程 A 等待磁盘读入数据时暂停，处理机先执行进程 B；等数据准备好后，系统再安排进程 A 继续运行。

#### 2. 异步与同步机制

- 异步可能引发与执行时序有关的错误。
- 操作系统通过**同步和互斥机制**，协调进程执行顺序和资源访问。

> **异步指执行速度不可预知，不意味着运行结果一定不确定或一定错误。**

## 易错点总结

| 易错点                     | 正确理解                                           |
| -------------------------- | -------------------------------------------------- |
| 并发就是并行               | 并发看时间间隔，并行看同一时刻                     |
| 单核不能运行多个程序       | 单核可以交替执行多个程序，实现并发                 |
| 联机接口就是联网使用       | 联机强调用户与系统交互                             |
| 系统调用是普通机器指令     | 系统调用是程序请求操作系统服务的接口，又称广义指令 |
| 同时共享必须在同一时刻访问 | 可以是一个时间段内宏观上的同时访问                 |
| 虚拟存储器增加了物理内存   | 扩充的是程序感受到的逻辑存储空间                   |
| 异步一定导致结果错误       | 异步指推进速度不确定，可通过同步和互斥进行协调     |

## 记忆提纲

- **四项管理**：处理机、存储器、文件、设备。
- **三种角色**：资源管理者、接口提供者、扩充机器。
- **四个特征**：并发、共享、虚拟、异步。
- **两个最基本特征**：并发、共享，互为存在条件。
- **两种共享方式**：互斥共享、同时共享。
- **两种复用技术**：时分复用、空分复用。

## 补充：操作系统、编译器、库函数与系统调用的关系

### 一、先分清“管理”和“处理”

**操作系统管理程序运行所需的资源，但不负责完成程序的一切具体工作。**

例如：

- 保存源程序文件：操作系统负责文件管理。
- 把源程序翻译成机器代码：编译器负责。
- 程序运行时分配内存、调度处理机：操作系统负责。
- 程序计算两个数的最大值：程序自己的代码负责。

> **被操作系统管理，不等于其具体功能由操作系统完成。**

### 二、源程序由谁管理？由谁翻译？

#### 1. 源程序是什么？

源程序是程序员用某种程序设计语言编写的代码。

例如，使用 C 语言编写的 `main.c` 文件就是源程序文件。

#### 2. 源程序由谁管理？

**作为文件，源程序由操作系统的文件管理功能管理。**

操作系统负责：

- 保存、读取、修改和删除文件。
- 管理文件目录和访问权限。
- 管理文件占用的存储空间。

但是，操作系统通常不负责理解代码的语法和含义。

#### 3. 源程序由谁翻译？

**高级语言源程序的编译由编译器完成，不属于操作系统的基本功能。**

| 工作                       | 负责者                 |
| -------------------------- | ---------------------- |
| 编辑源程序                 | 编辑器或集成开发环境   |
| 保存、读取源程序文件       | 操作系统的文件管理功能 |
| 检查语法、进行编译         | 编译器                 |
| 将目标文件与所需库连接起来 | 链接器                 |
| 程序运行时的资源分配与调度 | 操作系统               |

典型的编译型程序处理过程：

源程序 → 编译、汇编 → 目标文件 → 链接 → 可执行文件 → 装入运行

> 不同语言的实现方式不同，也可能采用解释执行、即时编译等方式。

### 三、编译器为什么不属于操作系统的功能？

因为**编译器和操作系统承担不同的任务**：

- **编译器**负责语言翻译，把源程序转换为目标代码。
- **操作系统**负责资源管理，并为编译器运行提供环境。

编译器本身也是一个程序。它运行时：

- 需要读源文件，由操作系统提供文件访问服务。
- 需要内存，由操作系统管理和分配相关资源。
- 需要使用处理机，由操作系统进行调度。
- 需要保存编译结果，由操作系统提供文件写入服务。

**操作系统负责让编译器运行，编译器负责完成编译。**

> 考试常见结论：
>
> **编译程序通常属于系统软件，但不属于操作系统。**
>
> 系统软件的范围比操作系统大，不能把“系统软件”全部当成“操作系统”。

### 四、系统软件和用户态程序是一回事吗？

不是。这里有两套不同的分类标准。

| 分类角度 | 分类               | 关注的问题             |
| -------- | ------------------ | ---------------------- |
| 软件用途 | 系统软件、应用软件 | 软件用来做什么         |
| 执行权限 | 用户态、内核态     | 当前代码能执行哪些操作 |

例如：

- 编译器按用途通常属于**系统软件**。
- 但普通编译器运行时通常处于**用户态**。
- 它需要操作系统服务时，同样要通过系统调用请求。

> **系统软件不一定在内核态运行。**
>
> **在用户态运行，也不等于按用途一定属于应用软件。**

### 五、库函数是什么？属于谁？

**库函数是预先编写好的、供程序调用的函数。**

例如，C 语言中的：

- `strlen()`：计算字符串长度。
- `memcpy()`：复制一段内存中的数据。
- `printf()`：格式化输出。
- `sqrt()`：计算平方根。

通常讨论的标准库函数，属于**用户态代码**，不是操作系统内核本身。

程序调用库函数时，一般是在自己的进程中执行这段函数代码。

> 库函数通常不是一个独立进程，不需要操作系统把它当成独立程序来调度。

### 六、库函数是否都依赖系统调用？

**不是。不是所有库函数都需要通过系统调用来完成其功能。**

#### 1. 不需要系统调用的库函数

有些功能通过用户态计算、访问已有内存就能完成。

例如：

| 库函数     | 功能           | 通常是否需要系统调用完成该功能 |
| ---------- | -------------- | ------------------------------ |
| `strlen()` | 计算字符串长度 | 不需要                         |
| `memcpy()` | 复制内存数据   | 不需要                         |
| `sqrt()`   | 计算平方根     | 不需要                         |

例如，`strlen()` 只需依次检查字符串中的字符，直到遇到结束标志即可。

#### 2. 需要操作系统服务的库函数

有些功能涉及文件、设备等资源，需要借助系统调用。

例如：

- 文件读写函数需要通过系统调用请求文件服务。
- 输出函数向终端实际输出数据时，通常需要操作系统提供服务。

但要注意**缓冲**：

- 调用一次 `printf()`，数据可能先进入用户态缓冲区。
- 等缓冲区刷新时，才通过系统调用实际输出。
- 因此，**一次库函数调用不一定对应一次系统调用**。

> “不需要系统调用”指完成该函数功能不必主动请求内核服务。
>
> 不代表程序运行脱离了操作系统的调度和内存管理。

### 七、用户程序由谁管理？

**用户程序运行时，由操作系统管理其使用的资源。**

程序运行后形成进程；现代操作系统通常以线程作为处理机调度单位。

| 操作系统功能 | 对运行中的程序提供什么管理                   |
| ------------ | -------------------------------------------- |
| 处理机管理   | 安排何时执行、何时暂停，以及进程或线程的协调 |
| 存储器管理   | 管理地址空间、内存分配和访问保护             |
| 文件管理     | 提供文件读写、目录和权限管理                 |
| 设备管理     | 管理程序对输入输出设备的使用                 |

但是，**程序中的普通指令由处理机直接执行，不是每一步都交给操作系统完成**。

例如：

- 加减运算：由处理机执行程序指令。
- 调用 `strlen()`：由处理机执行库函数代码。
- 请求读取文件：通过系统调用请求操作系统服务。

> **操作系统管理运行，处理机执行指令，程序代码决定具体业务逻辑。**

### 八、系统调用的上层是什么？

系统调用是**操作系统向用户态程序提供服务的程序接口**。

从下到上可以理解为：

| 层次               | 作用                                   |
| ------------------ | -------------------------------------- |
| 硬件               | 提供处理机、内存、设备等物理资源       |
| 操作系统内核       | 管理资源，实现文件、进程、设备等服务   |
| 系统调用接口       | 提供请求内核服务的入口                 |
| 用户态库、运行时等 | 封装常用功能，其中一部分会使用系统调用 |
| 应用程序           | 调用库函数或相关接口完成任务           |

这只是常见的分层方式，**不是每次执行都必须逐层经过**。

常见情况有三种：

1. **普通计算**：应用程序在用户态直接完成。
2. **调用纯计算库函数**：应用程序 → 库函数，在用户态完成。
3. **请求内核服务**：应用程序 → 库函数或系统调用封装 → 系统调用 → 内核服务。

应用程序也可以绕过高层库函数，通过较低层接口发起系统调用。

> **系统调用的上层可以是库函数、语言运行时，也可以是直接发起调用的用户态程序。**

### 九、库函数调用与系统调用的区别

| 比较项                   | 普通库函数调用           | 系统调用                         |
| ------------------------ | ------------------------ | -------------------------------- |
| 本质                     | 调用预先编写好的函数代码 | 请求操作系统内核服务             |
| 执行位置                 | 通常在用户态             | 进入内核态执行相应服务           |
| 是否一定切换到内核态     | 不一定                   | 是                               |
| 是否属于操作系统程序接口 | 不一定                   | 是                               |
| 例子                     | `strlen()`、`sqrt()`     | 请求文件读写、创建进程等内核服务 |

**库函数内部可以发起系统调用，但库函数本身不等于系统调用。**
