# 1.6 虚拟机

## 1. 虚拟机的概念

**虚拟机（Virtual Machine，VM）：使用虚拟化技术，将一台物理机器虚拟化为多台虚拟机器，每台虚拟机器都可以独立运行一个操作系统。**

各虚拟机拥有各自的虚拟 CPU、内存、磁盘等资源，其底层物理资源由同一台物理机器提供。

虚拟机中运行的操作系统称为**客户操作系统（Guest OS）**。

## 2. 虚拟机监控程序（VMM）

**VMM（Virtual Machine Monitor）即虚拟机监控程序，也称虚拟机管理程序或 Hypervisor。**

VMM 负责为虚拟机提供虚拟硬件环境，分配和协调底层物理资源，并隔离不同虚拟机的运行。

## 3. 第一类虚拟机监控程序

**第一类 VMM（Type 1）直接运行在物理硬件上，也称裸机型虚拟机监控程序。**

**按教材的简化模型，第一类 VMM 运行在内核态**，具有管理和控制底层硬件资源的权限。实际硬件虚拟化还会区分 VMM 与客户操作系统的执行模式，不能只用普通的用户态／内核态概括二者关系。

从下到上的结构为：

| 层次             | 内容                             |
| ---------------- | -------------------------------- |
| 最底层           | 物理硬件                         |
| 硬件之上         | 第一类 VMM                       |
| VMM 之上         | 多台虚拟机，各自运行客户操作系统 |
| 客户操作系统之上 | 各自的应用程序                   |

**核心特点：VMM 直接管理物理硬件，不需要先运行一个普通宿主操作系统来承载它。**

各客户操作系统通过 VMM 提供的虚拟硬件环境运行；VMM 负责协调它们对物理资源的使用。

**当上层客户操作系统执行需要由 VMM 接管的特权操作时，控制权转交给 VMM；VMM 检查并模拟或完成相应操作后，将处理结果和控制权交还客户操作系统，使其继续运行。**

可简记为：**客户操作系统发起特权操作 → VMM 截获并处理 → 返回客户操作系统继续执行。** 具体哪些操作需要被截获，取决于硬件虚拟化机制及 VMM 的配置，并非所有特权指令都会被截获。

## 4. 第二类虚拟机监控程序

**第二类 VMM（Type 2）运行在宿主操作系统（Host OS）之上，也称宿主型虚拟机监控程序。** 它依赖 Host OS 为其分配和管理物理资源。

**结构：物理硬件 → Host OS → 第二类 VMM → Guest OS → 客户应用程序。**

- **Host OS**：物理机器上承载 VMM 的宿主操作系统。
- **Guest OS**：虚拟机中运行的客户操作系统。
- 第二类 VMM 通常包含用户态程序，以及配合它工作的内核态驱动或虚拟化组件，不能简单理解成全部运行在用户态。

两类 VMM 的定义参见 [Red Hat：什么是 Hypervisor](https://www.redhat.com/en/topics/virtualization/what-is-a-hypervisor)。

## 5. 对物理资源的控制与分配

### 第一类 VMM

**直接管理底层硬件，可以直接控制、分配物理资源。** 创建虚拟机、安装 Guest OS 前，需要为虚拟机配置磁盘、内存等资源。

### 第二类 VMM

**通过 Host OS 获得资源，再向 Guest OS 提供虚拟硬件。**

- **虚拟磁盘**：Guest OS 看到的是自己的磁盘；在 Host OS 中，它通常对应一个或多个磁盘镜像文件，**不是一个大文件夹**。保存整台虚拟机的文件夹还可能包含配置文件、快照等。
- **内存**：Guest OS 看到的是“客户物理内存”，由 VMM 和 Host OS 提供后端存储并映射到宿主物理内存；常见实现会使用宿主进程的虚拟地址空间管理这些内存。
- **资源竞争**：Host OS 自身和其上运行的其他程序也需要 CPU、内存等物理资源。

## 6. 两类 VMM 的对比

| 对比项             | 第一类 VMM                                                  | 第二类 VMM                                               |
| ------------------ | ----------------------------------------------------------- | -------------------------------------------------------- |
| 运行位置           | 直接运行在硬件上                                            | 运行在 Host OS 上                                        |
| 对物理资源的控制   | 直接管理和分配                                              | 依赖 Host OS 分配与管理                                  |
| 性能               | 通常开销较小、性能较高                                      | 有 Host OS 参与，可能增加开销                            |
| 可支持的虚拟机数量 | 无需与普通 Host OS 及其应用竞争，通常更有利于承载较多虚拟机 | Host OS 和其他应用也占用资源，可用于虚拟机的资源相对减少 |
| 运行模式           | 核心监控代码处于有权控制硬件的特权执行环境                  | 通常由用户态组件与内核态组件共同实现                     |
| 迁移方式           | 可借助镜像导入导出、平台迁移功能等                          | 常可通过复制或导出镜像及配置迁移                         |

**第一类 VMM 自身及其管理组件也会消耗资源，并非零开销。**

### 可迁移性与应用范围

第二类 VMM 常便于把虚拟机打包后搬到另一台宿主机上，但需要目标 VMM、镜像格式、CPU 架构和虚拟硬件配置等兼容，不能理解为导出后就能在任意 Host OS 上运行。

**不能仅凭第一类／第二类就断定可迁移性更差／更好。** 第一类虚拟化平台也可以提供完善的迁移能力。两类都有商业应用，第一类常用于服务器和数据中心，第二类常用于桌面开发、测试和学习，不宜笼统记成“第二类商业化应用更广泛”。

## 7. 特权级与系统调用的处理

### 特权级

第一类 VMM 运行在最高控制权限下；在传统 x86 特权级模型中，**Ring 0 是最高特权级**。

### 客户系统的系统调用

**客户应用程序发出的系统调用，首先由 Guest OS 的内核处理，并不是全部由 VMM 截获后翻译成 Host OS 的系统调用。**

在第二类 VMM 中，若后续操作涉及需要接管的虚拟设备访问等，VMM 才通过相应机制介入，并可能调用 Host OS 提供的服务。例如，虚拟磁盘读写可以由 VMM 转为对宿主磁盘镜像文件的读写。

**示例链条：客户应用读取文件 → Guest OS 处理系统调用 → 访问虚拟磁盘 → VMM 处理虚拟设备请求 → 通过 Host OS 读写镜像文件。**
