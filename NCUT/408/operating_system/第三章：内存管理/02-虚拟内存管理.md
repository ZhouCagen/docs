# 3.2 虚拟内存管理

## 3.2.1 虚拟内存的基本概念

### 一、传统存储管理方式的局限

本节对比的传统方式指前面的基本连续分配、基本分页和基本分段等，不包括请求调页。

- **一次性**：作业必须全部装入内存后才能运行。大作业可能无法装入；内存不足也限制并发进程数。
- **驻留性**：装入后一直驻留到运行结束，暂时不用的代码、数据仍占据内存。

核心问题：**运行时不需要同时使用全部程序，却要为全部程序持续占用内存。**

### 二、局部性原理

**虚拟存储管理系统的理论基础是程序的局部性原理（局部性理论）**，包括时间局部性和空间局部性。程序在一段时间内通常只需访问部分代码和数据，因此只装入当前需要的部分，也能支持程序运行。

| 类型       | 含义                               | 常见原因                   |
| ---------- | ---------------------------------- | -------------------------- |
| 时间局部性 | 刚访问过的内容，不久后可能再次访问 | 循环、重复使用变量         |
| 空间局部性 | 访问某单元后，可能继续访问附近单元 | 指令顺序执行、连续访问数组 |

- **时间局部性**：保留近期访问过的内容，便于复用。
- **空间局部性**：按块调入相邻内容，或适当预取。
- TLB、Cache、虚拟内存都利用局部性，但缓存的内容和层次不同。

**虚拟内存的依据：进程在一段时间内，通常只集中访问少量页面。**

### 三、定义与特征

**虚拟内存**：基于局部性，只把当前所需部分装入内存，其余暂留外存；通过请求调入和置换，为进程提供逻辑上可大于物理内存的地址空间。

1. **部分装入**：无需全部装入即可运行。
2. **请求调入**：访问的合法页面不在内存时，由 OS 调入。
3. **页面置换**：可用页框不足时，选择暂时不用的页面换出，腾出空间。

| 特征   | 含义                           | 突破的限制       |
| ------ | ------------------------------ | ---------------- |
| 多次性 | 一个作业可分多次装入           | 一次性           |
| 对换性 | 运行期间可换出、再换入部分内容 | 驻留性           |
| 虚拟性 | 从用户角度扩大可用地址空间     | 物理内存容量限制 |

**虚拟性是根本目标，多次性和对换性是实现手段。** 容量扩充是逻辑上的，CPU 实际访问的代码、数据仍需位于内存中；调页过程对用户透明。

#### 虚拟地址空间与实际虚存容量

**虚拟地址空间大小由硬件支持的虚拟地址位数、虚拟内存机制和操作系统决定，不由物理内存、磁盘大小直接决定。** 按字节编址时，$n$ 位有效虚拟地址对应的理论寻址上限为 $2^n$ B；操作系统还可能限制进程实际可用的地址范围。

**实际可承载的虚存容量还受主存和可用外存后备空间限制。** 教材简化模型中常写为：

$$
\boxed{\text{实际虚存容量}\le\min\left(2^n\text{ B},\ \text{主存容量}+\text{外存容量}\right)}
$$

这里的外存容量指可用于支持虚拟存储的后备空间，不能直接把整块磁盘的标称容量都算进去；该公式用于教材容量估算，不表示进程必须为整个虚拟地址空间预先准备等量的物理存储。

**辨析：“最大容量”若指理论虚拟地址空间上限，看地址位数及系统支持；若指实际可实现的容量上限，还要看主存和外存。** 不能笼统记成“虚拟地址空间与磁盘无关，但最大虚拟地址空间与磁盘有关”。

### 四、实现方式与支持条件

教材中的虚拟存储管理建立在**离散分配**基础上，主要有：

- **请求分页**：以页为调入、置换单位。
- **请求分段**：以段为单位。
- **请求段页式**：按段组织，按页调入、置换。

所需支持：**内存与外存 + 页表 / 段表 + 缺页 / 缺段异常机制 + 动态地址变换机制**。

## 3.2.2 请求分页管理方式

**请求分页 = 基本分页 + 请求调页 + 页面置换。** 只需部分页面在内存即可运行，访问未驻留的合法页面时再调入。

**与基本分页的区别：**

- **基本分页**：程序运行前，所有页面都要先装入主存。
- **请求分页**：运行前只需装入一部分页面；访问到尚未装入主存的合法页面时，发生缺页中断，由 OS 将所需页面调入，再继续执行。

记忆：**基本分页先全部装入，请求分页按需调入。** 两者都允许各页分散存放在不同页框中，“是否全部装入”与“是否连续存放”是两个不同的问题。

### 一、页表机制

请求分页的页表项除物理页框号外，还需记录页面是否在内存、如何置换、是否写回及从何处调入。

| 字段                | 作用                                                 |
| ------------------- | ---------------------------------------------------- |
| 物理页框号          | 页面在内存时，用于形成物理地址                       |
| 状态位 / 存在位 $P$ | 表示页面是否已在内存，教材通常取 1 表示在内存        |
| 访问字段 $A$        | 记录访问情况，为置换算法提供依据；可为访问位、计数等 |
| 修改位 $M$（脏位）  | 表示页面调入后是否被修改，用于判断换出时是否需要写回 |
| 外存地址            | 定位页面在外存中的后备副本                           |

- 页号仍是隐含索引，不必作为单独字段存储。
- 读、写访问都更新访问信息；**写操作还需将修改位置 1**。
- **读操作不会把已有的修改位清零**；只有完成相应写回等操作后，才能按规则清除脏状态。
- 此处 $P$ 表示存在位，不是前一节公式中的页号，需按上下文区分。

### 二、缺页中断机制

**缺页中断属于内中断，更准确地说是可恢复的故障类异常。** 由当前指令访问尚未驻留的页面触发。

处理过程：

1. 硬件发现所需页面不在内存，触发缺页异常，保存现场并转入 OS。
2. OS 检查访问是否合法，确定页面的外存位置。
3. **有可用空闲页框**：直接分配；**需置换**：选择淘汰页，必要时先写回。
4. 将所需页面调入页框，更新页表，并维护 TLB，使旧映射失效、建立有效映射。
5. 页面准备好后恢复进程，**重新执行引发缺页的指令**。

需要等待磁盘 I/O 时，进程通常进入阻塞态，CPU 可调度其他进程；I/O 完成后进入就绪态，获得 CPU 后继续执行。

**缺页异常的两个特点：**

- 在指令执行期间触发，不是等指令执行结束才检查。
- **一条指令可能触发多次缺页**。例如，指令本身及两个操作数各跨两页，且涉及 6 个不同页面，在这些页初始均不在内存、调入后不再被换出的条件下，可产生 6 次缺页。

**缺页不一定发生置换；置换也不一定需要写磁盘。** 干净页在外存已有有效副本时可直接丢弃，脏页则需要先保存修改。

### 三、地址变换过程

**检查地址与权限 → 查 TLB → 必要时查页表或处理缺页 → 形成物理地址 → 访问数据。**

1. **TLB 命中**：取得页框号，更新相关访问 / 修改信息。
2. **TLB 未命中，页面在内存**：查页表取得页框号，并填入 TLB；TLB 满时替换一个表项。
3. **TLB 未命中，页面不在内存**：触发缺页，调页并更新映射后重试。
4. 将页框号与页内偏移组合成物理地址，进行实际访问。

$$
\text{物理地址}=\text{页框号}\times\text{页面大小}+\text{页内偏移}
$$

**TLB 表项替换只替换缓存的映射；页面置换才涉及实际页面的驻留状态。** 非法地址或权限错误不能按普通缺页调入处理。

## 3.2.3 页框分配

### 一、最小页框数与驻留集

#### 1. 最小页框数

**最小页框数**：保证进程正常运行所需的最少页框数，取决于指令格式、功能及寻址方式等硬件条件。

**进程最少页框数由一条指令执行过程中最多需要同时驻留的页面数决定，而这个数主要取决于指令系统的寻址方式。** 统计时要考虑指令本身、间接寻址所需的指针及操作数涉及的不同页面，以及是否跨页；这里的“同时”指为完成该指令而需要同时保留在内存中。

教材典型模型：

- 单地址指令、直接寻址，且指令和数据各在一页：至少 **2 个**，分别存指令和数据。
- 再增加一次间接寻址，指针单独占一页：至少 **3 个**，存指令、指针、数据。
- 指令及两个操作数各跨两页，需要这 6 页同时驻留：至少 **6 个**。

这些数字依赖题目条件，**不能脱离指令访问了哪些页面直接套用**。

#### 2. 驻留集

**驻留集**：进程当前驻留在物理内存中的页面集合；大小为当前占用的页框数。

- **过小**：可容纳更多进程，但进程缺页频繁，调页开销大。
- **过大**：缺页改善逐渐有限，却挤占其他进程空间，降低系统并发度。

分配时需在**进程缺页开销与系统并发能力**之间权衡。

### 二、内存分配与置换策略

- **固定 / 可变分配**：决定进程的页框数量能否在运行期间调整。
- **局部 / 全局置换**：决定淘汰页的选择范围。

| 策略             | 做法                                         | 主要特点                         |
| ---------------- | -------------------------------------------- | -------------------------------- |
| 固定分配局部置换 | 页框数固定，只从自身驻留页中淘汰             | 相互影响较小，但初始数量难确定   |
| 可变分配全局置换 | 可增加页框，必要时从其他进程的可置换页中选择 | 灵活，但进程可能相互抢占页框     |
| 可变分配局部置换 | 置换限于自身，系统另行调整驻留集大小         | 可兼顾缺页率与并发度，管理较复杂 |

**可变分配局部置换**可按缺页率调整：缺页率高时增加页框，过低时适当回收。

教材通常不采用“固定分配全局置换”：从其他进程取得页框会改变双方的页框数量，与固定分配的要求冲突。

### 三、页框分配算法

- **平均分配**：可分配页框平均分给各进程，实现简单，但未考虑进程大小。
- **按比例分配**：按进程的逻辑地址空间大小分配。
- **优先权分配**：为重要、紧急进程分配更多页框；可与比例分配结合。

设可分配页框数为 $m$，进程 $i$ 的大小为 $s_i$，按比例分配时：

$$
a_i\approx m\times\frac{s_i}{\sum_j s_j}
$$

实际需取整数，并满足各进程的最小页框数要求。

### 四、调入页面的时机

| 策略     | 时机                                 | 优点                       | 代价                           |
| -------- | ------------------------------------ | -------------------------- | ------------------------------ |
| 预调页   | 访问前预测并提前调入，常用于初始装入 | 可批量调入，减少后续等待   | 预测不准时浪费内存和 I/O       |
| 请求调页 | 访问缺页时才调入                     | 目标明确，调入页确实被需要 | 缺页时需等待，分散调入开销较大 |

**预调页看“是否提前”，请求调页看“是否由缺页触发”**；二者可以结合使用。

### 五、从何处调入与如何调入

教材将外存区分为：**文件区**保存文件，**对换区（交换区）**保存换出页面。其模型中，对换区采用较连续的布局，便于调页 I/O。

**磁盘交换区：用于暂存从内存换出的页面，腾出 RAM，需要时再从交换区调回。** 页面内容保存到交换区后，其原来占用的物理页框可供其他页面使用。

**容量不等于速度：交换区在磁盘上，增大交换区只能容纳更多换出页面，不能直接提高换页 I/O 速度。** 换页 I/O 速度取决于存储设备性能、访问方式等；扩大交换区本身不会让页面读写变快。

- **对换区充足**：可事先将相关文件复制到对换区，之后从对换区调入。
- **对换区不足**：只读或未修改且有有效文件副本的页可从文件区调入；被修改并换出的页从保存其最新内容的对换区调入。
- **教材所述 UNIX 方式**：初次从文件区调入，已换出的页面再从对换区调入；若共享页已在内存，可直接建立共享映射。

调入主线：**找后备副本 → 分配或腾出页框 → 读入页面 → 更新页表与 TLB → 重试指令**。

## 3.2.4 页面置换算法

**页面置换算法**：需要调入页面却无可用页框时，决定淘汰哪个驻留页。目标是降低缺页率，并兼顾扫描、维护与写回开销。

### 一、最佳置换算法（OPT）

**淘汰未来最长时间不会使用的页；若以后永不使用，优先淘汰。**

- 给定访问序列和页框数，可取得理论上最少的缺页次数。
- 实际运行时无法预知完整未来，不能作为可在线实现的算法。
- 主要用于评价其他置换算法。

### 二、先进先出算法（FIFO）

**淘汰最早调入内存的页**，按装入顺序维护队列。

- 实现简单，命中时不改变装入顺序。
- 没有利用近期访问情况，可能淘汰频繁使用的老页面。
- **Belady 异常**：在页面访问序列相同、初始内存为空等条件一致时，给进程分配更多页框后，缺页次数反而增加。**常见于 FIFO，但并非每次增加页框都会出现。**

例：访问序列 `3, 2, 1, 0, 3, 2, 4, 3, 2, 1, 0, 4`，初始内存为空，FIFO 在 3 个页框时缺页 **9 次**，4 个页框时缺页 **10 次**。

**OPT、LRU 不会出现 Belady 异常。** 不要把这一结论扩展为“所有其他算法都不会”。

### 三、最近最久未使用算法（LRU）

**淘汰过去最长时间没有被访问的页**，利用时间局部性预测未来。

- 每次访问都更新使用顺序，**命中也要更新**。
- 可通过时间记录、栈等方式维护；精确实现的维护开销较大。
- 通常有较好的实际效果，但不保证每个访问序列都优于 FIFO。

记忆：**FIFO 看装入先后；LRU 看过去最近一次访问；OPT 看未来下一次访问。**

#### 三种算法的教材示例

初始内存为空，分配 3 个页框，页面访问序列：

```text
7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1
```

| 算法 | 缺页次数 | 置换次数 | 缺页率 |
| ---- | -------- | -------- | ------ |
| OPT  | 9        | 6        | 45%    |
| FIFO | 15       | 12       | 75%    |
| LRU  | 12       | 9        | 60%    |

**初始装入也算缺页，但有空闲页框时不算置换。** 本例前三次缺页仅填充空页框，因此置换次数 = 缺页次数 − 3；其他题目需按初始状态和分配情况判断。

### 四、简单 CLOCK 算法

以较低开销近似 LRU，又称**时钟算法 / 最近未用算法（教材中的 NRU）**。

为每页设置访问位 $A$，页框组成循环队列，指针指向下一检查位置：

1. 页面被装入或访问时，置 $A=1$。
2. 需要置换时，从指针位置检查。
3. 若 $A=0$，淘汰该页；若 $A=1$，置 0 并继续检查下一页，给予一次机会。
4. 新页装入后置 $A=1$，指针移向下一页框。

**命中只置访问位，不因命中而移动置换指针。** 做题时同时维护页框内容、访问位和指针位置。

若所有页的访问位均为 1，则先扫描一圈全部清零，再淘汰回到的第一项；在扫描期间无新访问的模型下，$n$ 个页框最多检查 $n+1$ 项即可找到淘汰页。

教材例：4 个页框，初始为空，访问序列 `7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 3, 2`，按上述规则缺页 **8 次**，其中置换 **4 次**。

### 五、改进型 CLOCK 算法

同时考虑**访问位 $A$**与**修改位 $M$**，在近期使用情况相近时，优先淘汰干净页以减少写回。

| $(A,M)$ | 页面状态           | 淘汰倾向               |
| ------- | ------------------ | ---------------------- |
| $(0,0)$ | 近期未访问、未修改 | 优先淘汰               |
| $(0,1)$ | 近期未访问、已修改 | 次选，需写回           |
| $(1,0)$ | 近期访问、未修改   | 倾向保留               |
| $(1,1)$ | 近期访问、已修改   | 倾向保留，换出还需写回 |

教材采用的扫描规则：

1. **第一轮找 $(0,0)$**，找到即淘汰；本轮不修改访问位。
2. 若未找到，**第二轮找 $(0,1)$**；按检查时的状态判断，未选中的经过页将 $A$ 清零。
3. 若仍未找到，重复第一轮、第二轮；前一轮已清零访问位，之后必能选出页面。

**第一轮不清访问位，第二轮边扫描边清零；扫描不清修改位。** 淘汰后指针通常移至下一项，具体以题目规定为准。

优点：兼顾局部性与写回成本；代价：可能需要多轮扫描。**不能只把四类静态排序后忽略指针和访问位的变化。**

## 3.2.5 抖动和工作集

### 一、抖动（颠簸）

**抖动**：页面刚换出又需调入、刚调入又被换出，系统频繁调页，难以完成有效计算。

- **根本原因**：进程获得的页框不足以容纳当前活跃页面集合。
- **表现**：缺页率高、磁盘 I/O 频繁、进程大量等待，CPU 利用率下降。
- **缓解**：增加所需页框、按工作集或缺页率调整分配；总内存不足时，暂停部分进程，降低多道程序度。

**CPU 利用率低不一定应增加进程数**；若已发生抖动，继续增加进程会加剧内存争用。

### 二、工作集

**工作集 $W(t,\Delta)$**：在时刻 $t$ 之前、窗口 $\Delta$ 内实际访问过的页面集合。

- 窗口可按时间或最近若干次页面访问定义，做题按题目规定。
- **工作集是集合，重复页只计一次**；工作集大小不等于窗口大小。
- 工作集随程序执行变化，反映当前的局部性。

**工作集反映进程当前的内存需求，可用来动态调整驻留集大小并降低缺页率。** OS 可依据工作集估计近期需要保留的页面：需求增加时适当增加页框，需求减少时回收多余页框，使驻留集尽量覆盖当前工作集，从而减少缺页和抖动。

例：最近 5 次访问为 `2, 3, 5, 3, 2`：

$$
W(t,5)=\{2,3,5\},\qquad |W|=3
$$

| 概念   | 表示什么                   |
| ------ | -------------------------- |
| 驻留集 | 当前实际在内存中的页面     |
| 工作集 | 最近一个窗口中访问过的页面 |

二者不必相同。**分配目标是让驻留集能容纳当前工作集**，仅页框数量足够、但页面不匹配，仍会缺页。

若各进程工作集大小之和超过可分配页框数，系统有发生抖动的风险，应调整并发进程或内存分配。增大窗口通常会增大或保持工作集，但过大窗口会混入已不活跃的页面。

## 3.2.6 页框回收

### 一、页面缓冲算法

在置换算法之外，利用内存中的链表**暂存被淘汰页面，延迟或合并实际磁盘 I/O**。

| 链表         | 保存内容                                   | 处理方式                           |
| ------------ | ------------------------------------------ | ---------------------------------- |
| 空闲页面链表 | 可重新分配的页框，可暂时保留旧的干净页内容 | 从链头取页框；回收的干净页框挂链尾 |
| 修改页面链表 | 已淘汰但尚未写回的脏页                     | 暂存内容，积累后批量写回           |

- **旧内容尚未被覆盖**：再次访问该页时，可恢复映射、复用原页框，避免从磁盘重读。
- **脏页尚未写回**：不能直接覆盖其页框用于存放其他内容。
- 批量写回减少分散 I/O；保留旧内容减少重复读入。

**页面被淘汰，不等于内容立即从物理内存消失；页框可复用，不等于旧映射仍然有效。** 复用旧内容前仍需恢复正确的映射和状态。

### 二、页框回收的基本原则

- 内存不足时回收可回收页框；内核关键页面、被固定的页面等不能随意回收。
- 有有效后备副本的干净页可丢弃；脏页须先保存修改。
- **应在空闲页框降至阈值时提前回收**，不能等完全耗尽才行动，因为写回 I/O 本身也可能需要内存。
- 页框释放后，可通过伙伴系统将空闲伙伴逐级合并，形成更大的连续块。

注意：分页没有单页分配意义上的外部碎片，但**申请多个连续页框时，仍可能遇到物理空间碎片**。伙伴合并也要求同属一对伙伴，不能只看大小相同、地址相邻。

## 3.2.7 内存映射文件

**内存映射文件**：在磁盘文件与进程的一段虚拟地址空间之间建立映射，使程序可像访问内存一样访问文件内容。

基本过程：

1. 建立文件区域与虚拟地址区域的映射。
2. 访问尚未驻留的页面时，通过缺页机制按需调入。
3. 程序以普通内存读写访问映射区域，由系统管理实际文件 I/O。

**`mmap`（文件映射）的要点：先建立“文件区域 ↔ 虚拟地址区域”的映射，实际数据通常按页、按需装入，不是一次把整个文件读进内存。** 建立映射不等于数据已全部驻留主存；访问所需页面时，若数据尚未在内存中，再通过缺页处理调入。

**映射对象辨析：`mmap` 建立的是“文件 ↔ 进程虚拟地址空间”的映射，不是直接建立“虚拟页 ↔ 磁盘块”或“文件 ↔ 物理内存”的映射。** 文件数据实际装入 RAM 通常由缺页机制按需完成，页表负责记录“虚拟页 ↔ 物理页框”的映射；文件内容在磁盘上的块位置由文件系统管理。若对应文件页已在内存中，缺页处理可直接建立页表映射，无需再次从磁盘读入。

### 一、共享与通信

多个进程以共享方式映射同一文件区域，可将各自虚拟页映射到同一组物理页框。

- 各进程映射的**虚拟地址可以不同**。
- 共享同一份数据，减少显式复制，便于进程间通信。
- **共享物理页不等于无需同步**；并发读写的互斥、先后顺序等仍需协调。

### 二、修改与写回

- **共享映射**：修改共享页面后，由系统按写回策略写入文件；需要特定同步保证时应使用相应机制。
- **私有映射**：修改可通过写时复制形成私有副本，不直接改动原文件。
- **写回不只发生在退出或解除映射时**，也可能提前由系统执行；解除映射不应简单等同于数据已持久化。

优点：简化文件访问方式，便于共享；首次访问仍可能缺页，不能认为内存映射完全没有磁盘 I/O。

## 3.2.8 虚拟存储器性能影响因素

**缺页率及每次缺页处理的成本，是影响性能的核心因素。**

| 因素       | 影响与权衡                                                                 |
| ---------- | -------------------------------------------------------------------------- |
| 页面大小   | 较小页面使页数、页表项增多，页表变大，平均页内碎片减小，但可能增加缺页频率、页表管理和调页 I/O 开销；较大页面可一次覆盖更多相邻内容、缩短页表，但增大内部碎片，不能认为越大或越小越好 |
| 分配页框数 | 增加页框通常可减少缺页，但收益会趋缓；FIFO 可能出现 Belady 异常            |
| 置换算法   | 保留近期或即将使用的页面，减少无效淘汰                                     |
| 写回策略   | 优先淘汰干净页、批量写回脏页，降低 I/O 开销                                |
| 页面缓冲   | 暂存淘汰页，减少重复读入                                                   |
| 程序局部性 | 访问越集中，越容易让活跃内容留在内存中                                     |

例：二维数组若按行存储，通常按行遍历更有利于空间局部性；大跨度按列访问可能增加缺页。

设缺页率为 $p$，不缺页时一次访问耗时为 $T_0$，发生缺页时从开始到最终完成该次访问的总耗时为 $T_f$：

$$
T_{\text{平均}}=(1-p)T_0+pT_f
$$

若题目给的是缺页**额外开销** $D$，则：

$$
T_{\text{平均}}=T_0+pD
$$

**先看缺页处理时间是否包含重试访存，避免重复计时。** 脏页换出时还可能增加写回开销；磁盘调页远慢于普通访存，即使缺页率很低，也可能明显影响性能。

## 3.2.9 地址翻译的示例

### 一、TLB、页表与 Cache 的分工

| 结构  | 查找目标                   | 未命中 / 不在内存时      |
| ----- | -------------------------- | ------------------------ |
| TLB   | 虚拟页号对应的页框号及权限 | 查页表，不一定缺页       |
| 页表  | 页面的映射与驻留状态       | 合法页不在内存则触发缺页 |
| Cache | 地址对应的指令或数据       | 从主存取数据，不等于缺页 |

本例 Cache 使用物理地址，访问链条为：

**虚拟地址 → TLB / 页表 → 物理地址 → Cache / 主存 → 数据。**

### 二、题设与地址划分

教材条件：按字节编址，虚拟地址 14 位，物理地址 12 位，页面大小 64 B；TLB 共 16 项、四路组相联；数据 Cache 直接映射、16 组、行大小 4 B。

#### 1. 分页与 TLB

- 页内偏移：$\log_2 64=6$ 位。
- 虚拟页号 VPN：$14-6=8$ 位。
- 物理页框号 PPN：$12-6=6$ 位。
- TLB 组数：$16/4=4$ 组，组索引为 VPN 低 2 位，标记为 VPN 高 6 位。

| 虚拟地址位段 | 位数 | 含义       |
| ------------ | ---- | ---------- |
| 13～8        | 6    | TLB 标记   |
| 7～6         | 2    | TLB 组索引 |
| 5～0         | 6    | 页内偏移   |

查 TLB 时，先定位组，再比较组内各有效项的标记；**四路不是四组，本例恰好二者都为 4**。

#### 2. Cache

- 块内偏移：$\log_2 4=2$ 位。
- 组索引：$\log_2 16=4$ 位。
- 标记：$12-4-2=6$ 位。

| 物理地址位段 | 位数 | 含义         |
| ------------ | ---- | ------------ |
| 11～6        | 6    | Cache 标记   |
| 5～2         | 4    | Cache 组索引 |
| 1～0         | 2    | 块内偏移     |

**页内偏移与块内偏移不同**：前者定位页内字节，后者定位 Cache 行内字节。本例 Cache 标记恰好与物理页框号重合，并非普遍规律。

### 三、三个虚拟地址的转换

以下数值带 `0x` 的均为十六进制。根据教材所给 TLB、页表及 Cache 初始内容：

| 虚拟地址 | VPN    | 页内偏移 | TLB 组索引 | TLB 标记 | 转换结果                                      |
| -------- | ------ | -------- | ---------- | -------- | --------------------------------------------- |
| `0x03D4` | `0x0F` | `0x14`   | 3          | `0x03`   | TLB 命中，PPN = `0x0D`                        |
| `0x00F1` | `0x03` | `0x31`   | 3          | `0x00`   | TLB 未命中，查页表得 PPN = `0x02`，页面在内存 |
| `0x0229` | `0x08` | `0x29`   | 0          | `0x02`   | TLB 未命中，页表存在位为 0，发生缺页          |

前两个地址的物理地址为：

$$
\mathtt{0x03D4} \rightarrow \mathtt{0x0D} \times \mathtt{0x40} + \mathtt{0x14} = \mathtt{0x354}
$$

$$
\mathtt{0x00F1} \rightarrow \mathtt{0x02} \times \mathtt{0x40} + \mathtt{0x31} = \mathtt{0x0B1}
$$

`0x0229` 必须先完成缺页处理，得到新分配的页框号，才能继续确定物理地址，不能使用无效页表项猜测。

### 四、用物理地址查 Cache

| 物理地址 | Cache 标记 | 组索引 | 块内偏移 | 结果                                         |
| -------- | ---------- | ------ | -------- | -------------------------------------------- |
| `0x354`  | `0x0D`     | `0x5`  | 0        | 有效位为 1 且标记匹配，命中，读得 `0x36`     |
| `0x0B1`  | `0x02`     | `0xC`  | 1        | 对应行有效位为 0，未命中，需从主存读取并填充 |

**命中条件 = 定位正确组 + 有效位为 1 + 标记匹配。** 标记相同但有效位为 0，仍不命中。

做题顺序：**先按页大小拆虚拟地址，再查 TLB / 页表；有了物理地址，才按 Cache 参数重新拆分。**
