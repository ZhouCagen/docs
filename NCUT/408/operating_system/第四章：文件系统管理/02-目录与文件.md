# 4.2 目录与文件

本节主线：**文件名 → 目录项 → FCB / inode → 数据块**。围绕这条链理解目录检索、物理分配、打开文件、共享与保护。

## 4.2.1 目录的基本概念

**文件目录**：用于组织文件、记录文件名及相关描述信息或其引用的数据结构，实现文件的**按名存取**。目录本身也可作为文件保存在外存。

目录管理的四个要求：

1. **按名存取**：根据名称定位文件，无需用户提供磁盘位置。
2. **提高检索速度**：合理组织目录，减少查找开销。
3. **支持共享**：允许多个用户访问同一文件。
4. **允许重名**：不同目录中可使用相同文件名，同一目录内仍需唯一。

## 4.2.2 文件控制块和索引节点

### 一、文件控制块（FCB）

**FCB** 是保存文件管理信息的数据结构。教材传统模型中，一个文件对应一个 FCB，目录由 FCB 组成。

| 信息类别 | 主要内容 |
| -------- | -------- |
| 基本信息 | 文件名、大小、物理位置、逻辑结构、物理结构等 |
| 存取控制信息 | 文件所有者及各类用户的访问权限 |
| 使用信息 | 创建时间、修改时间及其他使用状态 |

**FCB 保存的是文件的描述与控制信息，不是文件的数据内容。**

### 二、索引节点（inode）

查目录时主要比较文件名，没必要同时读入全部属性。因此可将文件名与其他描述信息分离：

**目录项 = 文件名 + inode 号（或指向 inode 的引用）**  
**inode = 文件属性 + 数据块地址等管理信息**

目录项变小 → 每个磁盘块容纳更多目录项 → 扫描目录需要读取的块数减少。找到文件名后，再读取对应 inode。

| 形式 | 保存内容与作用 |
| ---- | -------------- |
| 磁盘 inode | 持久保存所有者、类型、权限、数据块地址、文件长度、硬链接计数、时间等 |
| 内存 inode | 磁盘 inode 装入内存后的表示，另有引用计数、锁定/修改状态、设备号、管理链表指针等运行时信息 |

- **文件名通常不在 inode 中**，因此多个不同名称的目录项可以指向同一 inode。
- inode 号在所属文件系统内标识节点；跨文件系统区分文件还需结合设备或文件系统标识。
- **硬链接计数**统计目录项引用，**内存引用计数**统计运行时引用，不是每执行一次 `read` 就增加一个永久计数。
- 教材的 13 个地址项属于一种经典 UNIX 模型，不是所有文件系统都固定如此。

### 三、目录检索的计算

设目录有 $N$ 项，每项 $d$ B，块大小 $B$ B，且目录项不跨块：

$$
\text{每块目录项数}=\left\lfloor\frac Bd\right\rfloor,\qquad
\text{目录块数}=\left\lceil\frac{N}{\lfloor B/d\rfloor}\right\rceil
$$

教材例：640 项、块大小 1 KiB。

| 目录组织 | 每项大小 | 每块项数 | 总块数 | 顺序查找平均读块数（教材近似） |
| -------- | -------- | -------- | ------ | -------------------------------- |
| 完整 FCB | 64 B | 16 | 40 | 20 |
| 文件名 + inode 号 | 16 B | 64 | 10 | 5 |

若各项等概率、每块装满、从首块顺序查找且无缓存，成功查找的**精确平均读块数**为 $(K+1)/2$，上例分别是 20.5 与 5.5；教材常近似为 $K/2$。**读取目标 inode、数据块的开销另算，不能混入目录扫描后又重复统计。**

## 4.2.3 目录结构

### 一、四种目录结构

| 结构 | 组织方式 | 优点 | 局限 |
| ---- | -------- | ---- | ---- |
| 单级目录 | 所有文件放在一张目录表中 | 简单，实现按名存取 | 全局不允许重名、查找慢、难分类与共享 |
| 两级目录 | 主文件目录 MFD → 各用户目录 UFD → 文件 | 不同用户可重名，缩小搜索范围 | 用户内部仍只有一层，不便分类，用户间共享不便 |
| 树形目录 | 根目录下逐级建立子目录 | 层次清晰，便于分类、管理与保护 | 路径解析需逐级检索；严格的树不支持同一节点有多个父目录 |
| 无环图目录 | 允许多个目录指向同一文件或子目录，且不形成环 | 支持共享，无需复制数据 | 需维护引用关系，删除与回收更复杂 |

两级目录中：**MFD 记录用户名及其 UFD 位置；UFD 记录该用户的文件信息。**

无环图共享节点可维护共享计数：新增链接加 1，删除链接减 1，计数为 0 才具备回收条件；若还有打开等运行时引用，实际回收可能继续延后。

### 二、路径与当前工作目录

- **绝对路径**：从根目录开始，如 `/home/student/os.md`。
- **相对路径**：以进程的当前工作目录为起点，如 `notes/os.md`。
- `.` 表示当前目录，`..` 表示父目录。
- **当前工作目录的作用**：缩短路径书写，并使相对路径解析不必每次从根目录开始。

例：当前目录为 `/home/student`，则 `notes/os.md` 对应 `/home/student/notes/os.md`。

**用户主目录与进程当前工作目录不是同一概念**：主目录通常是登录后的起点，当前目录可在运行中改变。允许链接后，同一文件也可能对应多个路径名。

## 4.2.4 目录的操作

| 操作 | 核心动作 |
| ---- | -------- |
| 搜索 | 按文件名或路径查找目录项 |
| 创建文件 | 检查名称与权限，建立元数据并增加目录项 |
| 删除文件 | 移除目录项，更新链接计数，在满足条件后回收资源 |
| 创建目录 | 建立子目录，纳入父目录 |
| 删除目录 | 空目录可直接删除；非空目录需先清空，或由相应工具递归处理 |
| 移动 | 调整父目录中的目录项及名称关系，使路径改变 |
| 显示 | 列出文件、子目录名称及所需属性 |
| 改变目录 | 切换进程的当前工作目录 |

同一文件系统内移动文件通常只需修改目录关系；跨文件系统的移动可能需要复制数据再删除源文件。采用 inode 时，显示详细属性还可能需要读取 inode，不能认为所有属性都存放在目录项中。

## 4.2.5 目录实现

| 方法 | 原理 | 优点 | 代价 |
| ---- | ---- | ---- | ---- |
| 线性列表 | 顺序保存目录项，按文件名逐项比较 | 实现简单 | 查找通常为 $O(n)$；创建前也需检查重名 |
| 哈希表 | 对文件名散列，定位目录项或其指针 | 平均查找、插入、删除较快 | 需处理冲突，维护表的规模 |

线性列表删除后的空位可标记未使用、加入空闲链表，或通过移动末项复用。**缓存活跃目录及查找结果，可减少磁盘 I/O；哈希命中后仍需确认文件名，不能忽略冲突。**

**Hash 结构文件补充**：采用支持动态扩展的哈希组织时，可实现物理块的动态分配和回收。注意区分这里的文件组织与上表中用于目录检索的哈希表。

### 文件系统性能的易混点

- **磁盘调度算法是提高文件系统性能的措施**：合理安排磁盘请求顺序，可减少寻道等开销。
- **异步 I/O**：使 CPU 与 I/O 操作重叠，提高 CPU 利用率，但本身并没有减少磁盘 I/O 次数。在本类题目区分“提高系统整体效率”和“提高文件系统本身性能”的口径下，不将异步 I/O 作为后者的措施。

## 4.2.6 文件的物理结构

**文件分配方式**决定文件的数据块如何组织，主要有连续、链接、索引三种。空闲磁盘块如何跟踪与分配，见 4.3 的空闲空间管理。

文件逻辑块与磁盘物理块要区分；文件系统块大小也不必总与内存页大小相同。

### 一、连续分配

每个文件占用一段连续磁盘块，目录项或 FCB 记录**起始块号 $b$ + 块数 $n$**。

逻辑块号从 0 开始时：

$$
\text{物理块号}=b+i,\qquad 0\le i<n
$$

- **支持顺序访问和直接访问**，地址计算简单，顺序读写时磁盘寻道开销较小。
- **存在外部碎片**，需找到足够长的连续区域。
- 文件增长不便，可能需要预留空间或整体搬迁；紧凑存储时插入、删除记录也可能需要移动数据。

### 二、链接分配

文件的块可分散存放，依靠指针维持逻辑次序。**无须预知最终长度，便于动态增长，不要求连续空闲空间。**

#### 1. 隐式链接

目录项保存首块号，通常还保存尾块号；每个数据块内保存下一块的指针，末块使用结束标记。

```text
目录项 → 块 9 → 块 16 → 块 1 → 块 10 → 块 25 → 结束
```

- 适合顺序访问；定位后面的块必须沿链遍历，不支持高效直接访问。
- 指针占用块内空间；指针损坏可能使后续数据不可达。
- 以多个连续块组成的**簇**为分配和链接单位，可减少指针数量与遍历开销，但末簇可能产生更多内部碎片。

#### 2. 显式链接：FAT

把下一块指针集中放在**文件分配表 FAT** 中：表项下标是当前块号，表项内容是下一块号或特殊状态。教材中一个文件系统设置一张逻辑上的 FAT，覆盖该卷的块或簇。

```text
目录项：起始块 = 2
FAT[2] = 8，FAT[8] = 5，FAT[5] = EOF
文件块序列：2 → 8 → 5
```

- FAT 同时可标记空闲块与链尾，支持空闲空间管理；特殊标记的具体数值按题设。
- 教材通常假设 FAT 已装入内存，沿链查找不必读取前面的数据块，减少磁盘 I/O。
- **定位第 $i$ 块仍需沿 FAT 链查表**，不能像数组或索引表那样直接计算对应块号；其“支持直接访问”不可理解为常数次查表。
- FAT 规模随卷的块或簇数量增大，带来内存开销。

$$
\text{FAT 大小}\approx\text{表项数}\times\text{每项字节数}
$$

**FAT 是整个卷的块链信息；下面的索引块通常属于某一个文件。**

### 三、索引分配

为每个文件建立索引块，按逻辑块次序保存其数据块号，目录项或 inode 记录索引块位置。

#### 1. 单级索引

**索引表第 $i$ 项 → 文件第 $i$ 个逻辑块对应的物理块。**

- 支持高效直接访问，数据块可离散分配，没有连续分配式的外部碎片。
- 索引块占额外空间，小文件可能浪费大部分索引块。
- 单个索引块容量有限；链接多个索引块可扩容，但查找后面的索引块仍可能需要遍历。

设块大小为 $B$ B、每个块号占 $a$ B，则每个索引块可容纳：

$$
q=\left\lfloor\frac Ba\right\rfloor
$$

单级索引支持的最大数据量为 $qB$。例如 $B=4\text{ KiB}$、$a=4\text{ B}$，则 $q=1024$，最大为 **4 MiB**。

#### 2. 多级索引

上级索引块记录下级索引块地址，最下级索引块记录数据块地址。

```text
二级索引：主索引块 → 下级索引块 → 数据块
```

满 $k$ 级索引可覆盖 $q^k$ 个数据块，最大数据量为 $q^kB$。上述参数下，二级索引可覆盖 **4 GiB**，三级索引可覆盖 **4 TiB**。

优点是支持大文件；代价是索引空间和访问层数增加。**计算文件数据容量时不把索引块算作数据；计算磁盘占用时必须加上索引块。**

#### 3. 混合索引

inode 同时设置直接地址、一级间接、二级间接、三级间接地址，兼顾小文件速度与大文件容量。

教材经典模型：**10 个直接地址项 + 各 1 个一级、二级、三级间接地址项，共 13 项。**

| 地址类型 | 指向关系 | 本部分覆盖数据块数 | 块大小 4 KiB、地址项 4 B 时 |
| -------- | -------- | ------------------ | -------------------------- |
| 直接地址 | inode → 数据块 | 10 | 40 KiB |
| 一级间接 | inode → 索引块 → 数据块 | $q$ | 4 MiB |
| 二级间接 | inode → 两层索引 → 数据块 | $q^2$ | 4 GiB |
| 三级间接 | inode → 三层索引 → 数据块 | $q^3$ | 4 TiB |

总寻址数据容量：

$$
S_{\max}=(10+q+q^2+q^3)B
=40\text{ KiB}+4\text{ MiB}+4\text{ GiB}+4\text{ TiB}
$$

这是地址结构给出的容量上限，若题目另有文件长度字段或卷容量限制，还要同时满足。

### 四、索引题的计算步骤

1. 字节偏移 $x$ 转逻辑块号 $i=\lfloor x/B\rfloor$，块内偏移为 $x\bmod B$。
2. 根据直接区、一级区、二级区等范围，判断需要走哪条路径。
3. 减去前面各区覆盖的块数，得到区内块号，再用商和余数定位各级索引项。
4. 数清需读取的索引块及目标数据块，最后按题设加入目录、inode 开销并扣除缓存命中。

例如二级间接区的区内块号为 $r$，则主索引项号为 $\lfloor r/q\rfloor$，下一级项号为 $r\bmod q$。

若 **inode 已在内存、相关索引块与数据块均未缓存**，读取一个数据块：

| 所在区域 | 索引块读取次数 | 加上目标数据块后的 I/O 次数 |
| -------- | -------------- | -------------------------- |
| 直接区 | 0 | 1 |
| 一级间接区 | 1 | 2 |
| 二级间接区 | 2 | 3 |
| 三级间接区 | 3 | 4 |

这些次数仅针对一次目标块访问，**不能忽略题目给出的缓存与初始状态**。

### 五、三种分配方式对比

| 方式 | 定位目标块 | 动态增长 | 主要开销或问题 |
| ---- | ---------- | -------- | -------------- |
| 连续分配 | 起始块号加偏移 | 不便 | 外部碎片、搬迁或预留空间 |
| 隐式链接 | 逐块读指针 | 方便 | 随机访问慢、块内指针、断链风险 |
| 显式链接 FAT | 在 FAT 中沿链查找 | 方便 | 全卷表的空间开销、链式查表 |
| 索引分配 | 按索引项定位 | 在索引容量范围内方便 | 索引块空间、多级索引 I/O |

链接与索引分配不要求连续空间，但**最后一个块或簇仍可能有内部碎片**。

## 4.2.7 文件的操作

### 一、创建、删除、读写与定位

| 操作 | 核心过程 |
| ---- | -------- |
| 创建 | 检查名称、重名与目录权限 → 分配并初始化 FCB / inode → 建立目录项 → 更新管理信息 |
| 删除 | 按路径定位目录项并检查权限 → 移除目录项、减少链接计数 → 满足回收条件后释放数据块、索引块和 inode |
| 读 | 根据打开文件状态与当前位置读取数据，更新位置 |
| 写 | 向当前位置写入数据，必要时分配新块，更新位置、长度及相关元数据 |
| 定位（seek） | 改变后续读写位置，本身不要求读取文件数据 |

- **创建空文件不一定立即分配数据块**，可以到写入时再分配。
- **删除名称与回收文件是两件事**：仍有硬链接或打开等引用时，文件数据不能立即回收。
- 回收时必须保留足够的块地址信息，以便释放数据块和索引块，不能先丢失地址再尝试回收。

### 二、打开与关闭

**打开的目的**：把后续操作所需的信息保存在内存中，避免每次读写都按路径检索目录。

打开过程：**解析路径 → 找到目录项与 inode → 检查访问权限 → 建立打开文件状态 → 返回文件描述符。**

做题时要区分**目录检索**与**建立打开状态**两个阶段：

```text
先目录检索：在外存目录中找到文件的目录项 / FCB（已缓存时可直接利用缓存）
    ↓
再建立打开状态：把所需 FCB / 目录项信息调入内存的活动文件目录 / 打开文件表
```

从 `open()` 系统调用的完整过程看，目录检索可以是其中的前置步骤；题目单独问“打开”的核心动作时，重点是**将文件控制信息调入内存并建立打开状态**。

**打开不等于把整个文件读入内存。** 后续 `read`、`write`、`lseek`、`close` 通常使用文件描述符；删除、重命名等按路径操作仍可能使用文件名。

教材采用两级打开文件表模型：

| 结构 | 范围 | 主要保存的信息 |
| ---- | ---- | ---------------- |
| 进程打开文件表 | 每个进程私有 | 当前读写位置、访问模式及指向系统表项的引用等 |
| 系统打开文件表 | 系统共享 | 文件位置、大小等共享信息及打开计数等 |

```text
文件描述符 fd
    ↓ 作为本进程表的索引
进程打开文件表项 → 系统打开文件表项 → inode / 数据块信息
```

- 文件描述符只在所属进程的上下文中有意义；不同进程的相同数值不一定指向同一文件。
- 在教材的两级表模型中，**若文件已经打开，可以共享已有的系统打开文件表项**，增加打开计数；本进程的打开文件表仍需增加对应项，记录本次访问的状态。
- 关闭时撤销对应的进程表项，减少相关引用；最后一个引用消失后，可释放相应打开状态。
- **关闭不等于删除文件，也不等于所有数据已经持久化到磁盘。**

**`write()` 与 `close()` 的分工**：`write()` 负责写文件数据，并更新必要的元数据；`close()` 主要处理文件控制信息和关闭状态，如更新引用计数、释放打开表项，必要时处理修改过的控制信息。不能把“写文件数据”归为 `close()` 的主要职责。

教材表的划分用于理解共享关系。实际实现还可拆分“文件描述符表、打开文件描述、inode 缓存”等层次：**独立打开通常有独立偏移；共享同一打开文件描述的描述符可能共享偏移**，不能绝对认为不同进程的偏移总是独立。

## 4.2.8 文件共享

共享的目标是让多个名称或用户访问同一文件，无须维护多份数据副本。**共享同一 inode 可使文件长度、块地址等元数据保持一致；仅复制一份块地址列表不能可靠实现共享。**

### 一、硬链接：共享 inode

多个目录项指向同一 inode，即同一文件的多个名字。

```text
目录项 A ─┐
          ├→ 同一 inode（链接计数 2）→ 文件数据
目录项 B ─┘
```

- 新增硬链接：新增目录项，inode 的硬链接计数加 1；不复制数据，不改变所有者。
- 删除一个名字：移除该目录项，计数减 1，其他名字仍可访问。
- 数据最终回收通常要求**硬链接计数为 0，且没有需要保留文件的运行时引用**。
- 硬链接通常不能跨文件系统；一般不允许普通用户对目录建立硬链接，以避免目录环等问题。

**硬链接计数统计名字的数量，不是用户数量，也不是打开次数。** 同一用户可以为文件建立多个硬链接。

### 二、软链接（符号链接）：保存路径

软链接是独立文件，有自己的 inode，内容记录目标的路径名。访问时由系统解析该路径定位目标。

```text
软链接目录项 → 软链接自己的 inode → 目标路径 → 目标 inode → 数据
```

| 比较项 | 硬链接 | 软链接 |
| ------ | ------ | ------ |
| 保存的联系 | 目录项指向同一 inode | 独立文件保存目标路径 |
| 是否有独立 inode | 与目标共用 | 有 |
| 是否增加目标硬链接计数 | 是 | 否 |
| 目标原名称被删除后 | 其他硬链接仍有效 | 若保存的路径失效，则成为悬空链接 |
| 跨文件系统 | 通常不允许 | 可以，只要路径能解析到目标 |
| 指向目录 | 通常受限 | 可以 |
| 访问开销 | 直接定位共享 inode | 需要额外解析目标路径 |

软链接目标可使用绝对或相对路径；**相对目标路径以软链接所在目录为基准**。删除软链接本身不会删除目标文件；软链接也不复制目标的权限，访问目标仍需相应权限。

**符号链接文件自身的链接计数不受被链接文件的影响**：两者有独立的 inode 和计数。目标文件的硬链接计数变化或目标路径失效，不会直接改变符号链接自身的链接计数；建立符号链接也不会增加目标文件的硬链接计数。

## 4.2.9 文件保护

**文件保护**解决“谁可以对文件做什么”，避免未经授权的读取、修改或破坏。

对一个文件的访问，常由**用户访问权限和文件属性共同限制**，例如用户是否有写权限、文件是否设置为只读。**不同进程对同一文件的访问权限可能不同**，因为进程所代表的用户身份、所属组以及打开时的访问模式可能不同。

### 一、访问类型

| 类型 | 含义 |
| ---- | ---- |
| 读 | 获取文件数据 |
| 写 | 修改或写入文件数据 |
| 执行 | 将程序文件装入并运行 |
| 追加 | 只在末尾增加数据 |
| 删除 | 移除文件名称，并按条件释放资源 |
| 列清单 | 列出目录中的文件名称及所需属性 |

复制、打印等高层操作通常需要读取数据；允许读取后，仅靠普通文件读权限很难再禁止用户复制已读到的内容。

### 二、访问控制列表（ACL）

**存取控制矩阵用于多用户之间的存取权限保护**：行表示用户或保护域，列表示文件等对象，矩阵元素记录允许的操作。按某个文件取出对应的一列，可形成该文件的访问控制列表。

为文件或目录保存“**用户 / 用户组 → 允许的操作**”的列表。

- 优点：权限细致、策略灵活。
- 代价：列表可能较长，存储、查找和维护都有开销。
- 教材的精简形式把用户分为**所有者、组、其他用户**，分别规定权限。

匹配基本用户类别时按**所有者 → 所属组 → 其他**选择适用类别，不能随意把三类权限叠加。

| 用户类别 | 读 | 写 | 删除 | 执行 |
| -------- | -- | -- | ---- | ---- |
| 所有者 | 1 | 1 | 1 | 1 |
| 组 | 1 | 0 | 0 | 0 |
| 其他 | 0 | 0 | 0 | 0 |

上表是教材的 $3\times4$ 位示意模型。**不要与 UNIX 常见的三组 `rwx` 共 9 位直接等同**；在 UNIX 的目录语义中，删除一个名称主要受父目录的权限及其他限制控制，并非看目标文件是否可写。

### 三、口令、加密与访问控制

| 方式 | 思路 | 特点与局限 |
| ---- | ---- | ---------- |
| 口令保护 | 提供正确口令才能访问 | 简单，但口令保管、共享与泄露带来问题 |
| 加密保护 | 文件内容加密，使用密钥解密 | 保护内容机密性，有密钥管理和计算开销 |
| 访问控制 | 根据身份和策略判断具体操作是否允许 | 能区分读、写、执行等操作 |

**口令和加密是补充手段，不能代替对具体操作的权限控制。** 共享与保护也不矛盾：共享决定能否共同访问，保护规定各方能够执行哪些操作。

### 四、安全管理与备份

- **系统级安全管理包括注册和登录**：注册建立用户身份，登录验证身份，为后续按用户实施访问控制提供基础。
- **应对文件受损常用备份的方法**：保留可恢复的副本，在文件损坏、丢失或误删后恢复数据。严格说，备份主要减轻受损造成的损失，并不直接阻止原文件损坏。
- 做题区分：**注册、登录 → 系统级身份管理；存取控制矩阵 / ACL → 访问权限保护；备份 → 数据恢复。**
