# 4.3 文件系统

本节主线：**磁盘上保存文件与管理信息 → 内存中维护运行状态 → 管理空闲空间 → VFS 统一访问接口 → 挂载接入目录树。**

文件系统是操作系统组织、存储和管理文件的一套机制与数据结构，提供按名存取、空间分配与回收、共享和保护等功能。复习重点是**空闲空间管理的四种方法、位示图计算、VFS 四类对象及挂载的含义**。

**从用户观点看，操作系统引入文件系统的目的是实现对文件的按名存取**：用户通过文件名或路径访问文件，无须知道文件在磁盘上的具体物理位置。

## 4.3.1 文件系统布局

### 一、文件系统在磁盘中的结构

磁盘可划分为多个分区，各分区可以建立独立的文件系统。教材给出的一种典型布局如下，具体文件系统的布局可能不同：

```text
整个磁盘：MBR（含分区表）｜分区 1｜分区 2｜……
一个分区：引导块｜超级块｜空闲空间管理信息｜inode 区｜根目录｜其他文件和目录
```

| 组成 | 位置或主要内容 | 作用 |
| ---- | -------------- | ---- |
| 主引导记录 MBR | 磁盘的 0 号扇区，包含引导代码与分区表等 | 传统 BIOS 引导中，识别活动分区并转入其引导程序 |
| 分区表 | 各分区的位置、大小及活动标志等 | 描述磁盘如何划分 |
| 引导块 | 分区开头，保存该分区的引导程序 | 加载并启动操作系统；教材模型中，未安装可启动系统也保留此区域 |
| 超级块 | 文件系统的总块数、块大小、空闲块及空闲 inode 等管理信息 | 描述整个文件系统，挂载时读入内存 |
| 空闲空间管理信息 | 位示图、空闲链表等 | 跟踪未分配的磁盘块 |
| inode 区 | 文件属性、数据块地址等 | 描述各个文件，目录也有对应的 inode |
| 根目录及其他文件、目录 | 目录内容和文件数据 | 根目录是该文件系统目录树的起点 |

传统 BIOS + MBR 的引导顺序：**BIOS → MBR 引导代码 → 活动分区的引导块 → 操作系统**。

**区分层次：MBR 面向整个磁盘；超级块面向一个文件系统；inode 面向一个文件。** 引导块不等于超级块，超级块也不保存所有文件的具体内容。

**文件的索引结构由索引节点（inode）中的地址项组织**：在教材的混合索引模型中，inode 保存直接地址项及各级间接地址项。直接地址项指向数据块，间接地址项指向另外存放的索引块。因此，“索引结构放在索引节点里”不能理解为所有层级的索引表都完整存放在 inode 内。

### 二、文件系统在内存中的结构

磁盘结构负责持久保存，内存结构用于加速访问并维护运行状态，随挂载、访问、打开和关闭等操作更新。

| 内存结构 | 主要作用 |
| -------- | -------- |
| 挂载表（mount table） | 记录已挂载文件系统的设备标识、挂载点、类型、挂载选项等 |
| 目录项缓存 | 缓存近期访问的路径组成部分及查找结果，减少重复读盘，加快路径解析 |
| 系统级打开文件表 | 维护打开文件的描述信息及运行状态，如读写位置、访问模式、引用计数等 |
| 进程级打开文件表 | 用文件描述符定位该进程引用的系统级打开文件表项 |

```text
进程中的文件描述符 fd
    → 进程级打开文件表项
    → 系统级打开文件表项
    → 文件的元数据及数据块
```

同一个文件可被多次打开；**文件本身的属性与某次打开的状态要区分**，读写位置属于打开实例。相关对象见 4.3.3。

## 4.3.2 文件存储空间管理

**文件分配方式**解决“一个文件的数据块如何组织”；**空闲空间管理**解决“哪些块可用，以及如何分配、回收”。两者相关，但不是同一个问题。

### 一、空闲表法

以一段**连续空闲盘区**为单位建立表项，通常按起始块号递增排列。

**表项 = 起始空闲块号 + 连续空闲块数**（还可含序号）。

| 起始块号 | 空闲块数 | 表示的空闲范围 |
| -------- | -------- | -------------- |
| 2 | 4 | 2～5 |
| 9 | 3 | 9～11 |
| 15 | 5 | 15～19 |

- **分配**：类似内存动态分区分配，使用首次适应、最佳适应等算法寻找足够大的盘区；分配后修改起始块号和长度，恰好用完则删除表项。
- **回收**：按地址找到插入位置，检查与前、后空闲区是否物理相邻；分为均不相邻、仅前邻、仅后邻、前后均邻四种情况，相邻时合并。
- **特点**：适合连续分配，便于一次分配多个连续块；空闲区域零碎时表项较多，也可能找不到足够大的连续区。

例：从空闲区 `(2, 4)` 的开头分配 2 块后，表项变为 `(4, 2)`。

### 二、空闲链表法

| 类型 | 链接单位及节点内容 | 分配与回收 | 特点 |
| ---- | ------------------ | ---------- | ---- |
| 空闲盘块链 | 单个空闲块；保存下一空闲块指针 | 分配时从链首取块；回收时将块接回链中 | 单块操作简单；多块分配需反复沿链访问，链长、管理开销较大 |
| 空闲盘区链 | 一段连续空闲盘区；保存块数和下一盘区指针 | 分配时查找并可能拆分盘区；回收时检查相邻盘区并合并 | 链较短，适合成批分配；需处理拆分、合并，操作较复杂 |

**空闲盘块链链接的是“尚未分配的块”；文件的链接分配链接的是“属于某文件的数据块”。**

### 三、位示图法（计算重点）

每个磁盘块对应一个二进制位。按本书约定：**0 表示空闲，1 表示已分配**；题目另有约定时以题设为准。

- **分配**：查找一个或一组为 0 的位 → 换算成磁盘块号 → 将对应位置 1。
- **回收**：由块号定位对应位 → 将该位置 0。
- **优点**：结构紧凑，便于扫描和寻找连续空闲块；可将位示图缓存到内存中以减少磁盘访问。
- **代价**：大小随所管理的磁盘块数增加，大容量磁盘仍需考虑位示图的存储与扫描开销。

#### 1. 位示图需要多大空间

设管理 $N$ 个磁盘块，每个块对应 1 bit：

$$
\text{位示图字节数}=\left\lceil\frac{N}{8}\right\rceil
$$

若存放位示图的每个块为 $B$ 字节，则一个块可记录 $8B$ 个磁盘块的状态：

$$
\text{位示图占用块数}=\left\lceil\frac{N}{8B}\right\rceil
$$

例：管理容量为 1 GiB、块大小为 4 KiB 的空间：

$$
N=\frac{2^{30}}{2^{12}}=2^{18},\qquad
\text{位示图大小}=2^{18}/8=2^{15}\text{ B}=32\text{ KiB}
$$

因此位示图占 $32/4=8$ 个块。**bit 与 Byte 相差 8 倍，块数计算结果需向上取整。**

#### 2. 位的位置与磁盘块号换算

设每行有 $n$ 位，第 $i$ 行、第 $j$ 列对应磁盘块号 $b$。本书的行号、列号及下式对应的块号均从 **1** 开始：

$$
b=n(i-1)+j
$$

$$
i=\left\lfloor\frac{b-1}{n}\right\rfloor+1,
\qquad
j=((b-1)\bmod n)+1
$$

例：每行 16 位，第 3 行第 5 列对应块号 $16\times2+5=37$；反算得行号 $\lfloor36/16\rfloor+1=3$，列号 $36\bmod16+1=5$。

**不要只背“减 1 加 1”，先看清三种编号的起点。** 若行、列、块号都从 0 开始：

$$
b=ni+j,\qquad i=\left\lfloor b/n\right\rfloor,\qquad j=b\bmod n
$$

若编号起点混用，先求该位从 0 开始的线性序号 $k$：

$$
k=n(i-i_0)+(j-j_0),\qquad b=k+b_0
$$

其中 $i_0,j_0,b_0$ 分别为行、列、块号的起始值。题目用“字号、位号”描述位示图时，同样按每字的位数换算。

### 四、成组链接法（理解分配与回收）

经典 UNIX 使用的方法，结合**分组、记录块号、组间链接**，避免逐块遍历长链。内存只需维护当前一组的空闲块号，不必保存全部空闲块号。

#### 1. 如何组织

- 将空闲块分组，内存中设**空闲盘块号栈**，记录当前组的块号及数量。
- 当前组中的一个块用于保存**下一组的空闲块号和数量**，其块号位于当前栈底。
- 这些保存下一组信息的块逐级链接；它们本身也属于可分配的空闲块，完成信息转移后即可分配。
- 末组使用结束标记。教材示例使用 `0`，它是标记，不是要分配的块号。

教材示例：

```text
内存栈：保存 201～300 的块号，依次分配 201、202、……、299
    栈底块 300：保存下一组 301～400 的块号和数量
        栈底块 400：保存再下一组的信息
            ……
                块 7900：保存末组 7901～7999 的块号及结束标记 0
```

图中的首组有 100 个可分配块，末组只有 99 个；**结束标记不计入可分配块数**。

#### 2. 盘块分配

1. 栈中还有普通块号时，弹出栈顶块号并分配，空闲块计数减 1。
2. 当前组只剩保存下一组信息的栈底块时，**先读取该块中的下一组信息，更新内存栈**。
3. 信息转移完成后，再把该块本身分配出去。
4. 到达末组并耗尽可分配块后，报告无空闲块。

例：分配完 201～299 后，需要分配 300 时，**先把 300 中记录的 301～400 组信息读入内存，再分配 300**。不能先覆盖 300，否则会丢失后续空闲块信息。

#### 3. 盘块回收

| 当前内存栈状态 | 回收块 $b$ 的处理 |
| -------------- | ---------------- |
| 栈未满 | 将 $b$ 的块号压栈，计数加 1 |
| 栈已满 | 将当前栈的块号列表及数量写入回收块 $b$；随后将内存栈重置为仅含 $b$ 的一项，计数置 1 |

栈满时，回收块 $b$ 成为保存下一组信息的新块。**先把原有的一组信息写入 $b$，再让内存栈只保留 $b$ 的块号**；“计数置 1”只表示当前栈有一项，不表示整个文件系统仅剩一个空闲块。

记忆：**分配遇组尾，先读下一组再分配；回收遇栈满，先写旧组再留新块。**

### 五、四种方法对比

| 方法 | 管理空闲空间的方式 | 复习抓手 |
| ---- | ------------------ | -------- |
| 空闲表法 | 表项记录连续空闲区的起点、长度 | 查表分配、相邻合并 |
| 空闲链表法 | 按单块或连续盘区链接 | 单块链简单但长，盘区链需拆分合并 |
| 位示图法 | 每块对应一个 bit | 空间开销、块号与位序换算、连续空闲位 |
| 成组链接法 | 内存保存当前组，磁盘块保存下一组 | 组切换时的读入、写回顺序 |

空闲空间管理信息需要持久保存，并维护内存状态与磁盘状态的一致性；不能只修改内存而永久丢弃更新。

### 六、FAT 也可用于空闲磁盘块管理

**文件分配表（FAT）可以作为系统管理空闲磁盘块的数据结构**。FAT 表项除记录文件中下一块的位置、链尾等状态外，还可用特定值标记对应块（或簇）为空闲。

- **分配**：查找标记为空闲的表项，将对应块分配给文件，并更新 FAT 中的链接关系及状态。
- **回收**：释放文件占用的块，将相应 FAT 表项重新标记为空闲。
- **做题区分**：FAT 既支持文件的显式链接分配，也能跟踪空闲空间；不能因为它是文件分配表，就排除其管理空闲磁盘块的作用。

## 4.3.3 虚拟文件系统（VFS）

### 一、为什么需要 VFS

不同文件系统（如 ext4、NTFS、FAT）的磁盘组织、元数据和操作实现不同。**VFS 位于系统调用接口与具体文件系统之间，提供统一的文件操作抽象，将请求分发给相应文件系统。**

```text
应用程序：open / read / write / close 等
                    ↓
              系统调用接口
                    ↓
       VFS：统一对象与操作接口
           ↙        ↓        ↘
         ext4      NTFS      FAT
           ↓        ↓        ↓
               底层存储设备
```

- 对应用：使用统一接口，无须针对每种文件系统分别编程。
- 对具体文件系统：实现 VFS 规定的接口，即可接入系统。
- 对 VFS：用通用对象封装公共属性，并通过**操作函数指针**调用具体实现。

**VFS 是内核中的抽象层，不是一种磁盘文件系统格式，也不把磁盘格式统一改写成同一种格式。**

### 二、四类对象（重点区分）

以下沿用教材的 V 节点抽象模型。

| 对象 | 表示什么 | 典型内容与作用 |
| ---- | -------- | -------------- |
| 超级块对象 | 一个已挂载的文件系统 | 文件系统类型、块大小、总块数等全局信息，以及相关操作函数 |
| V 节点对象（vnode） | 一个具体文件或目录 | 统一表示文件属性，关联底层文件系统元数据，通过操作函数指针分发请求 |
| 目录项对象 | 路径中的一个组成部分 | 名称、父子目录项关系、关联 V 节点的指针等，用于路径解析和缓存 |
| 文件对象 | 一次打开形成的运行实例 | 当前读写位置、访问模式、引用计数，以及关联目录项、V 节点的指针 |

**四个层次：一个文件系统 → 一个文件 → 文件的名字与路径关系 → 一次打开的状态。**

#### 1. V 节点与 inode

- **磁盘 inode** 是具体文件系统持久保存文件属性、数据位置等信息的结构。
- **V 节点**是 VFS 在内存中的统一抽象，通过关联底层元数据屏蔽文件系统差异。
- 两者有关联，但**V 节点不等于磁盘 inode**；VFS 也不能要求所有底层文件系统都具有完全相同的磁盘 inode 格式。

#### 2. 目录项对象与磁盘目录项

VFS 目录项对象是路径解析过程中形成的**内存缓存对象**，不要求与某个固定磁盘结构一一对应。例如 `/home/user/file` 中的 `home`、`user`、`file` 都是路径组成部分。

**名称关系属于目录项，文件属性属于 V 节点所抽象的文件元数据。** 多个名称可关联同一文件。

#### 3. 文件对象与文件描述符

`open()` 创建打开实例，返回进程中的文件描述符 `fd`；通过 `fd` 可以找到对应文件对象。关闭相应引用后，文件对象在引用计数归零时才可释放。

- 同一文件被独立打开多次，可对应多个文件对象，各自维护读写位置。
- 多个描述符也可能引用同一文件对象，此时共享该打开实例的读写位置。
- **文件描述符是进程内的索引，不是 inode 号，也不是磁盘块号。**

### 三、以 `write(fd, buf, n)` 为例

1. 进程发出写系统调用，进入内核。
2. 根据 `fd` 在进程的打开文件表中找到文件对象。
3. 通过文件对象关联的 V 节点及操作函数，定位具体文件系统的写实现。
4. 具体文件系统处理数据与元数据，必要时分配磁盘块，最终由底层设备完成写入。

```text
fd → 文件对象 → V 节点 / 操作函数 → 具体文件系统 → 缓存及设备层
```

这里描述的是教材的抽象流程。**普通写操作可能先写入缓存，系统调用返回不等于数据已持久写入磁盘。**

## 4.3.4 文件系统挂载

**挂载（mount）**：把一个文件系统接入已有的目录结构，使进程能够通过路径访问其中的文件。用于接入的目录称为**挂载点（mount point）**。

### 一、UNIX 与 Windows 的组织方式

| 系统 | 典型组织方式 |
| ---- | ------------ |
| UNIX | 以根文件系统 `/` 为基础，其他文件系统挂载到目录树中的某个目录，形成统一的路径空间 |
| Windows | 通常通过 `C:`、`D:` 等驱动器号访问不同卷，也支持将卷挂载到目录 |

根文件系统在系统启动过程中挂载；其他文件系统可以自动挂载，也可以手动挂载。这里的设备可为逻辑设备，例如同一磁盘的不同分区。

### 二、挂载后如何访问

教材示例：将 `/dev/fd0` 上的 ext2 文件系统挂载到已有目录 `/flp`：

```bash
mount -t ext2 /dev/fd0 /flp
```

其中 `-t ext2` 指定文件系统类型，`/dev/fd0` 是设备，`/flp` 是挂载点。若该文件系统根目录中有 `a.txt`，挂载后即可通过 `/flp/a.txt` 访问。

卸载示例：

```bash
umount /flp
```

- **挂载不等于复制文件**，而是把文件系统的根接到指定路径上。
- 挂载点原有内容并未删除，但在该挂载生效期间通常被遮蔽，卸载后可再次访问。
- 按教材模型，同一设备可挂载到多个挂载点，一个挂载点同一时刻对应一个有效挂载；做题时按题设处理。
- 挂载使文件系统可通过路径访问；`open()` 则打开其中的具体文件，两者层次不同。

## 4.3.5 复习检查

1. **MBR、超级块、inode 分别描述谁？** 整个磁盘的引导与分区、一个文件系统、一个文件。
2. **连续空闲区如何回收？** 检查与前后空闲区是否相邻，必要时合并。
3. **位示图如何计算？** 每块一位；先确认 bit/Byte，再确认行、列、块号从 0 还是 1 开始。
4. **成组链接法何时访问保存组信息的块？** 当前组耗尽时读下一组；回收时栈已满则将旧组写入回收块。
5. **VFS 如何支持不同文件系统？** 统一对象和接口，借助操作函数指针调用具体实现。
6. **读写位置属于哪个对象？** 文件对象，即打开实例；不属于文件名或磁盘 inode。
7. **挂载完成了什么？** 将文件系统接入路径空间，使其中的文件能通过挂载点访问。
